# g1 평가 셋 — 크기 · 칸 · 도메인 · 해시 (소단계 45-바)

비공개 설계 2-4. 셋 본문은 git 밖 `~/.judgemodel/sets/g1/<셋>.jsonl` 에만 있다. 여기에는 수와 해시만 적는다.

## 0. 결론

- **넷 다 얼렸다.** 해시는 `protocol-g1.json` 의 `sets` 칸에도 넣었다.
- 45-라(10-11) 에 `protocol-g1.json` 의 `seeds` 만 [1,2,3] → [1,2,3,4,5] 로 고쳤다. 같은 씨앗 재실행 흔들림(acc3 +2.6%p)을 결정 모드로 없애고 씨앗을 늘려 d 짝 반폭을 3%p 아래로 넉넉히 두려는 것이다. `sets` 해시는 그대로이고, 규약 해시가 바뀌어 그 전 B0 결과는 견주지 않는다.
- blind-g1 은 공개판 안 같은 (근거, 주장) 두 쌍을 `--dedupe-same` 으로 하나씩 줄였다 (5절).
- 셋은 자르지 않았다. 라벨 붙은 쌍(`agree` · `third`)을 전부 넣었다. 그래서 설계 목표보다 크고, c 가 많고 b 가 적다 (2절).

## 1. 만든 법

`build/label_batches.py assemble --set <셋> --dirs <eval-public/셋> [<eval-archive/셋>] --dest ~/.judgemodel/sets/g1`

| 규칙 | 값 |
| --- | --- |
| 넣는 쌍 | `status` 가 `agree` · `third` 인 쌍 전부. `drop` 은 뺀다 |
| 함정 | 대응표의 함정 q · id, 함정 풀과 같은 (근거, 주장) 은 뺀다 — 넷 다 0 건이었다 |
| 멈춤 | `need-third` · `missing` 이 남음 · `cd` 칸 · 폴더 사이(또는 안) 같은 (근거, 주장) · 같은 id → exit 2 |
| 줄 필드 | id · evidence · claim · want(a/b/c/d) · `label_guide: "support-v5"` · domain · group · groups · lang · form · hint · source(있으면) · relabel · old_want(있으면) · votes · status · set |
| 차례 | id 로 정렬 — 같은 입력이면 같은 바이트 (두 번 돌려 해시가 같음을 확인) |
| 해시 | `freeze.py write` 의 sha256 = `data_prep.sha256_file` (= `eval_nli.py` 의 `set_sha256`) |

## 5. blind-g1 겹침 줄이기

- 공개 blind-g1 안에 같은 (근거, 주장) 이 두 쌍 있다. 둘 다 제안서 원천이고, 쌍마다 칸 · 상태(`agree`)가 같다. 공개판과 아카이브판 사이 겹침은 0 이다.
- 후보 뽑기에서 한 원천 안 같은 글을 못 거른 탓으로 보인다.
- 메인 승인으로 `assemble --set blind-g1 … --dedupe-same` 을 돌렸다. 겹친 쌍마다 id 가 작은 쪽만 남겨 공개판 617 → 615, 셋 1,118 쌍이다.

## 8. 정답셋 gold-g1 — dev-cmp 라벨 품질 (소단계 45)

결론 : **dev-cmp 라벨은 관문 통과.** 무작위 층 80쌍에서 gold 와 0.925 맞다(관문 0.85). 전체 0.799 는 갈린 쌍을 일부러 많이 뽑은 탓에 낮게 나온 값이라 관문에 안 쓴다.

gold-g1 은 dev-cmp 에서 200쌍을 다시 뽑아 신중 판정자에게 붙인 정답셋이다(`gold-pick` → 신중 판정 묶음 → `gold-score`).

| 항목 | 값 |
| --- | --- |
| 묶음 | 24판 모두 남김 (함정 하나는 애매해서 관문에서만 뺌) |
| 판정자 일치 κ | 0.761 · c/d 0.647 |
| 정함 | 합의 167 · 셋째가 가름 32 · 버림 1 |
| gold 칸 | a 48 · b 9 · c 66 · d 76 |
| 셋째(j3) sure 「낮음」 | 37쌍 중 24쌍 |

`gold-score --out eval-public/dev-cmp eval-archive/dev-cmp --gold gold-g1` (n 199)

| 잰 자리 | n | dev = gold |
| --- | --- | --- |
| **무작위 층 (random) — 관문** | 80 | **0.925** |
| 갈린 층 (split, 셋째가 가른 쌍) | 119 | 0.714 |
| 전체 (참고) | 199 | 0.799 |
| 첫 두 판이 같았던 쌍만 | — | 0.925 |
| 칸별 (gold 기준) a · b · c · d | — | 0.896 · 0.889 · 0.742 · 0.776 |

- 어긋남 40쌍은 거의 c↔d 다 : gold c → dev d 16 · gold d → dev c 12 · 그 밖 12. 방향이 양쪽으로 비슷해서 지침 한쪽이 기운 탓으로 보기 어렵다.
- 도메인별 일치는 0.78~0.84 로 고르다.

정한 것

| 정한 것 | 까닭 |
| --- | --- |
| 관문은 무작위 층으로 잰다 (`gate_on: random`) | `gold-pick` 이 120쌍을 갈린 쌍에서 일부러 뽑아 전체 평균이 아래로 치우친다. 무작위 층이 없으면 전체로 잰다. 갈린 층은 참고 수치로만 본다 |
| c↔d 지침을 고쳐 다시 붙이는 판은 안 한다 | 어긋남이 c→d · d→c 양쪽으로 비슷하다. 한 칸 규칙을 고쳐도 반대쪽이 늘 뿐이다. 그 쌍들은 사람 검토 목록으로 보낸다 |

사람 검토 목록 — git 밖 `sets/g1/human-review-todo.jsonl` (+ `README.txt`), 최대 200줄을 dev-cmp → dev-cal → blind-g1 차례로 채웠다.

| 셋 | why | 쌍 |
| --- | --- | --- |
| dev-cmp | gold-low (신중 판정자 누군가 「낮음」) | 114 (그중 gold ≠ dev 35 · gold 버림 1) |
| dev-cmp | gold-diff (gold ≠ dev, 「낮음」 없음) | 5 |
| dev-cmp | drop · third | 1 · 30 |
| dev-cal | drop · third | 2 · 38 |
| blind-g1 | drop · third | 3 · 7 (상한 200 에 걸려 third 77쌍이 못 들어감) |
| 합 | | 200 |

- 신중 판정자는 200쌍 중 114쌍에 「낮음」을 하나 이상 달았다. 그래서 gold-low 칸이 목록의 절반을 넘는다. 줄마다 `gold` 칸(신중 판정자 라벨)을 같이 싣는다.
