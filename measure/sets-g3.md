## 2. 표본 200 판정 (2026-10-13)

**결론 : 통과.** 전체 b 40.0% (80 / 200, 95% 범위 33.5~46.9%) — 멈춤 문턱 15% 를 넉넉히 넘는다. 다만 `name` 은 b 25% 로 낮고 `qual` 은 12.5% 라, 다음 거르기 판에서 **둘 다 빼고 num · date · ordinal 만 남기기**를 권한다(남은 b 75%). 그래도 b 는 한 조각으로 넉넉하고, **d 만 모자라 조각을 하나 더 처리해야 할 공산이 크다.**

- 소스 : `~/.judgemodel/build/g3/kowiki/sample200.jsonl` (1-4 의 표본, 씨앗 20261013) → 판정 `sample200-judged.jsonl` (줄마다 `judge: {label, reason, confident}`).

## 3. 거르기 규칙과 d 통과율 (2026-10-13)

**결론 : 거른 뒤 3,728쌍(b 3,448 · d 280). d 판정 통과율은 71.8%(201 / 280)다. 위키가 질 d 약 330 에 130 쯤 모자라서 두 번째 조각이 필요하다.** b 는 한 조각으로 넉넉하다(판정 후보 약 920 이면 된다).

```
python -I mine_wiki.py filter --in …/chunk3.jsonl --out …/chunk3-f.jsonl        # 권장값이 기본
python -I mine_wiki.py split --in …/chunk3-f.jsonl --out-eval …/chunk3-f-eval.jsonl --out-train …/chunk3-f-train.jsonl
python -I mine_wiki.py stats --in …/chunk3-f.jsonl > …/chunk3-f.stats.json

- bz2 는 다시 돌리지 않았다. `chunk3.jsonl` 에 규칙만 덧씌웠다(`filter`, 몇 초).
- 규칙은 셋이고 이 차례로 건다. ① 「N년 (M월) 현재 · 기준」의 **때만** 바뀐 b 는 d 로 돌린다(`rehint: time-anchor`). ② b 는 `num · date · ordinal` 만 남긴다. ③ flag 붙은 b 는 남은 b 의 20% 까지(씨앗 20261013).
- d 줄은 kind · flag 로 거르지 않는다. 모자라서 다 판정에 넘긴다.

### 12-1. 뽑기 (`public_pick.py pick`)

```
python -I public_pick.py pick --src …/klue/answered-rw.jsonl --check …/klue/answered-rw.check.jsonl \
    --forbid …/klue/answered-rw.jsonl --set eval --n-b 95 --n-a 60 --out …/klue/pick-eval.jsonl

- BoolQ(8-1)와 같은 규칙이다. 다른 점 셋만 적는다.
  - 평서문 검사가 짝(`pair`) 단위다. 떨어진 짝 64개는 a · b 두 줄을 다 뺐다(128줄). 다시 쓴 것이 없는 11짝(22줄)도 이 64짝 안에 들어 있었다.
  - `--forbid` 는 맞은편 split 의 문단만 쓴다. 평가 몫은 train 문단, 학습 몫은 heldout 문단을 뺀다. 같은 파일 하나를 넘기면 split 거르기와 문단 겹침 빼기가 같이 된다.
  - `kind` 는 `klue-heldout` · `klue-train` 이다.
- heldout × train 문단 겹침이 79묶음 있었다. 이 묶음은 평가 · 학습 둘 다에서 빠졌다.

| --- | --- | --- |
