# 라벨 프롬프트 g1 — 라벨 판 · 신중 판정자 판

g1 셋과 Ⅱ · ㄱ 학습 쌍에 Opus 로 라벨을 붙일 때 쓰는 프롬프트 뼈대다. 기준은 `라벨기준support-v5.md` 다.
원문은 `../Design/2026-10-11-d자료층재구축설계.md` 3-3 ④ (라벨 판) · 2-4 「정답셋」 (신중 판정자 판)이다.

- **라벨 판** : 학습 쌍 · dev · blind 라벨, 자 ④. 한 묶음 100쌍.
- **신중 판정자 판** : 정답셋 `gold-g1` 200쌍만. 라벨 판과 **다른 프롬프트**라야 같이 틀리지 않는다.
- 묶음 파일 · 함정 · 답 합치기는 `build/label_batches.py`(소단계 45 에서 만듦) 몫이다. 여기는 글과 규칙만 둔다.

## 1. 라벨 판 뼈대

다섯 부분을 이 차례로 붙인다. `{…}` 는 채울 자리다.

```text
[① 역할]
너는 두 글의 관계를 칸 넷(a 지지 · b 반대 · c 무관 · d 비슷한 계열) 중 하나로 가르는 라벨러다.
쌍마다 「근거(evidence)」와 「주장(claim)」이 있다. 근거가 주장에 대해 무엇을 말해 주는지를 본다.

[② 기준 전문]
아래 기준을 그대로 따른다. 기준에 없는 자리는 Q1 → Q2 → Q3 차례로만 가린다.
---
{support-v5.md 1절 ~ 3절 전문을 고치지 않고 붙인다}
---

[③ 예/아니오 셋]
쌍마다 아래 셋을 차례로 답한다. 답은 「예」 또는 「아니오」와 까닭 한 마디(20자 안팎)다.
- Q1 같은 대상인가?  아니오면 Q2 · Q3 은 「-」 로 두고 c.
- Q2 함께 참일 수 없는 말이 있나?  예면 Q3 은 「-」 로 두고 b.
- Q3 근거가 맞다고 해 주는 말이 주장에 하나라도 있나?  예면 a, 아니오면 d.
d 를 고르기 전에 숨은 부분 지지(다른 말 · 다른 단위 · 이름 · 날짜)를 한 번 더 본다.

[④ 칸 하나]
칸은 a · b · c · d 중 하나만 고른다. {학습 묶음이면 : Q1 을 정말 못 고를 때만 cd 를 쓸 수 있다. dev · blind 묶음이면 이 줄을 빼고 「cd 는 쓰지 않는다」를 넣는다.}

[⑤ 금지]
- 이 글과 아래 쌍 말고 **다른 파일을 열지 말라.** 다른 쌍의 답을 보지 말라.
- 쌍이 어디서 왔는지(원천 · 자료 이름 · 묶음 순서)를 **짐작하지 말라.** 글에 적힌 말만 보고 가린다.
- 칸 비율을 맞추려 하지 말라. 한 묶음에 한 칸이 몰려도 된다.

[출력]
쌍 하나에 한 줄. JSON 한 줄 말고 아무것도 쓰지 않는다. 까닭은 q1 · q2 · q3 값 뒤에 「 — 」로 붙인다.
{"q": "q0412", "q1": "예 — 같은 앨범", "q2": "아니오", "q3": "아니오 — 출시일만 말함", "label": "d"}

[쌍]
{줄마다 {"q": "...", "evidence": "...", "claim": "..."} — 100쌍}
```

### 1-1. 출력 꼴

- 줄 꼴 : `{"q": "q0412", "q1": "예", "q2": "아니오", "q3": "아니오", "label": "d"}`.
- `q1` · `q2` · `q3` 값은 「예」 · 「아니오」 · 「-」 로 **시작**한다. 뒤의 「 — 까닭」은 있어도 되고 합치는 쪽은 첫 낱말만 읽는다.
- **앞뒤가 맞는지 기계로 검사한다.** 안 맞는 줄은 그 쌍을 「답 없음」으로 친다.

| q1 | q2 | q3 | label 이어야 |
| --- | --- | --- | --- |
| 아니오 | - | - | c (학습 묶음은 cd 도 됨) |
| 예 | 예 | - | b |
| 예 | 아니오 | 예 | a |
| 예 | 아니오 | 아니오 | d |

- 한 묶음에서 답 없음이 5% 를 넘으면 그 판을 버리고 다시 돌린다.

### 1-2. 함정 쌍

- 묶음마다 **10%** 를 정답을 아는 함정 쌍으로 채운다. 함정은 칸 넷에 고르게(칸마다 2~3쌍), 다른 쌍 사이에 섞고 같은 불투명 `q` id 를 준다.
- 함정 정답은 기준 3절 보기처럼 **누가 봐도 한 칸**인 쌍만 쓴다. 지난 셋에서 사람이 확정한 쌍이나 지어낸 쌍.
- 판정자에게 함정이 있다는 것을 알리지 않는다.
- **함정 정답률이 80% 아래인 판은 통째로 버린다** (그 판의 다른 답도 안 쓴다). 같은 묶음을 새 판으로 다시 돌린다. 두 번 연속 버리면 메인에 알린다.
- 함정 답은 셈에서 뺀다(라벨 · κ · 일치율 모두).

### 1-3. k=3 — 예시 차례 바꾸기

학습 쌍(Ⅱ · ㄱ)은 같은 묶음을 **세 판** 돌린다(k=3). 세 판은 따로 띄운 판정자다(서로 답을 못 본다).

- **바꾸는 것** : ② 기준 3절 표의 **자리 차례**와 각 자리 안 **보기 차례**, 그리고 [쌍] 목록의 쌍 차례.
  - 판 1 : 기준 그대로 · 쌍 차례 그대로.
  - 판 2 : 자리 차례를 거꾸로 · 쌍 차례를 씨앗 2 로 섞음.
  - 판 3 : 자리 차례를 씨앗 3 으로 섞음 · 자리 안 보기도 거꾸로 · 쌍 차례를 씨앗 3 으로 섞음.
- **안 바꾸는 것** : 기준 1 · 2 절 글, 질문 Q1~Q3 차례, 출력 꼴, 함정 쌍(쌍 차례 안에서 자리만 바뀜).
- 합치는 법(설계 3-3) : 3/3 같으면 그 칸 · 2/3 같고 갈린 표가 c↔d 뿐이면 `cd`(학습 전용) · 그 밖은 버림.
- dev · blind 라벨은 k=3 대신 **둘 따로 · 다르면 셋째**(설계 2-4). 차례 바꾸기는 판 1 · 판 2 꼴을 쓴다.

## 2. 신중 판정자 판 (정답셋 `gold-g1` 용)

라벨 판과 같은 기준을 쓰지만 **묻는 글 · 주는 자료 · 출력**이 다르다. 같은 프롬프트면 같이 틀리기 때문이다.

| 자리 | 라벨 판 | 신중 판정자 판 |
| --- | --- | --- |
| 역할 글 | 라벨러 | 「다른 사람의 라벨을 다시 보는 검토자」. 서두르지 말고 쌍마다 따로 생각하라 |
| 묶음 크기 | 100쌍 | **20쌍** |
| 자료 | 근거 · 주장 | 근거 · 주장 **+ 앞뒤 문맥**(원천에서 근거 앞 1~2 문장 · 뒤 1~2 문장, 없으면 「없음」) |
| 출력 | 예/아니오 + 짧은 까닭 | 예/아니오 + **까닭 한 줄**(문장으로) |
| 함정 | 10% | 10% (같은 규칙, 80% 아래 판 버림) |
| 라벨 판의 답 | — | **주지 않는다** |

```text
[① 역할]
너는 두 글의 관계 라벨을 다시 보는 검토자다. 칸은 a 지지 · b 반대 · c 무관 · d 비슷한 계열 넷이다.
쌍마다 따로, 천천히 본다. 앞 쌍의 답에 끌리지 않는다.

[② 기준 전문]
---
{support-v5.md 1절 ~ 3절 전문}
---

[③ 문맥 쓰는 법]
쌍마다 「앞 문맥」 · 「뒤 문맥」을 준다. 문맥은 근거가 무엇을 가리키는지(대명사 · 생략된 주어 · 때)를
알아내는 데만 쓴다. **판정은 근거와 주장으로만 한다** — 문맥에만 있는 말로 a 나 b 를 주지 않는다.

[④ 예/아니오 셋 + 까닭 한 줄]
Q1 → Q2 → Q3 을 차례로 답한다. 값마다 「예/아니오/-」 뒤에 까닭을 한 문장(40자 안팎)으로 붙인다.
d 를 고르기 전에 숨은 부분 지지를 한 번 더 보고, 본 결과를 q3 까닭에 적는다.
칸은 a · b · c · d 중 하나. cd 는 쓰지 않는다. 정말 못 고르겠으면 칸을 고르고 "sure": "낮음" 을 적는다.

[⑤ 금지]
다른 파일을 열지 말라. 원천 · 자료 이름 · 다른 판정자의 답을 짐작하지 말라.

[출력]
{"q": "q0412", "q1": "예 — 둘 다 같은 앨범의 출시를 말한다", "q2": "아니오 — 날짜와 회사는 서로 부딪치지 않는다", "q3": "아니오 — 주장의 회사 이름을 근거가 말하지 않고, 다른 말로 쓴 것도 없다", "label": "d", "sure": "보통"}

[쌍]
{줄마다 {"q": "...", "before": "...", "evidence": "...", "after": "...", "claim": "..."} — 20쌍}
```

- `sure` 는 「높음 · 보통 · 낮음」. 「낮음」 쌍은 사람이 나중에 볼 목록(`human-review-todo.jsonl`)에 먼저 넣는다.
- 앞뒤 검사(1-1 표)는 같다. 두 판정자가 다르면 셋째(같은 신중 판정자 판)가 가른다.

## 3. 채울 자리 정리

| 채울 자리 | 무엇 | 누가 |
| --- | --- | --- |
| ② 기준 전문 | `라벨기준support-v5.md` 1~3 절, 고치지 않음 | 묶음 만드는 스크립트 |
| ④ cd 줄 | 학습 묶음 / dev · blind 묶음에 따라 | 같음 |
| [쌍] | 불투명 `q` id 로 바꾼 쌍 · 함정 섞음 | 같음 |
| 앞뒤 문맥 | 원천의 앞뒤 문장(공개 원천은 원문 · 우리 자료는 같은 기억 · 문서의 앞뒤 줄) | 정답셋 만들 때(45) |
| `q` → 원래 쌍 대응표 | 판정자에게 안 줌. git 밖에만 | 같음 |
