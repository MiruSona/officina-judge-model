# R0 — 한·영 기반 모델과 영어 자료 조사 (2026-10-09)

길 1 보강 판 첫 바퀴의 0차례다. 한국어와 영어만 함께 배우는 기반 모델(몸통)을 고르고, 영어 NLI 자료를 받아 공통 꼴로 만든다.

## 결론

| 정한 것 | 값 |
| --- | --- |
| 몸통 | **`FacebookAI/xlm-roberta-large`** · HF revision `c23d21b0620b635a76227c604d44e43a9f0ee389` · **MIT** · 560M |
| 영어 자료 | **MNLI 1.0 학습 셋**(NYU 원본 zip) · **SNLI 1.0 학습 셋**(Stanford 원본 zip) — 둘 다 NC 없음 |
| 바퀴당 양 | 한국어 = KLUE 학습 전부(약 2.5만) + KorNLI 5만 · 영어 = **MNLI 5만 + SNLI 2.5만** → 한 : 영 = 7.5만 : 7.5만 (1 : 1) |
| 가중치 공개 | 몸통 MIT · 자료는 BY-SA 4.0(KLUE · KorNLI · SNLI) · BY-SA 3.0 / BY 3.0 / OANC(MNLI) → 기본 모델은 **CC BY-SA 4.0** 으로 내놓는다 |

`mdeberta-v3-base` 는 영어 XNLI 는 XLM-R base 보다 낫지만 large 보다 낮고, `tokenizer.json`·`model.safetensors` 가 저장소에 없으며 ONNX 내보내기 함정이 알려져 있어 뺐다.

- **XNLI 에는 한국어가 없다** (15개 언어 중 ko 없음). 그래서 한국어 성능은 KLUE 논문 표 32(KLUE-NLI 시험 정확도)로 견줬다. 같은 표에서 KoELECTRA-base 85.63 · KLUE-RoBERTa-base 84.83 이라 XLM-R large 는 한국어 전용 base 급보다 높고 KLUE-RoBERTa-large 보다 3.2점 낮다.
- 그 3.2점은 KorNLI·KLUE 를 함께 배워 일부 메운다고 본다. 실측은 기반 학습 뒤 KLUE dev 로 klue 판(0.908)과 견준다.
- 한·영 NLI 로 미리 가르친 공개 모델(`joeddav/xlm-roberta-large-xnli`, `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7` 등)은 XNLI·ANLI 같은 비상업 자료가 섞여 뺐다.
- 고르는 차례(라이선스 → 한·영 NLI → ONNX → 크기 → `tokenizer.json`)로 보면 XLM-R large 가 다섯 칸 모두 걸림이 없다. 크기 560M 은 600M 권장 아래다. 늘어난 몫 대부분이 낱말 칸(25만 × 1024)이라 셈 양은 klue large 와 비슷하다.

### DeBERTa-v3 ONNX 함정 (뺀 까닭)

- 내보낼 때 `modeling_deberta_v2.py` 의 자체 softmax symbolic 에서 `'torch._C.Value' object has no attribute 'dtype'` 오류가 난 보고가 있다. transformers #18272 로 일부 고쳤지만 2024-02 에도 파이프라인 문제가 남았다는 보고가 있다.
- 상대 위치 임베딩을 그때그때 셈하는 꼴이라 일부 연산이 조용히 틀린다는 보고도 있다.
- 우리 길은 `torch.onnx.export(dynamo=False)` 한 길이라, 새 함정을 떠안을 까닭이 없다.

- SNLI 의 `gold_label` 이 `-` 인 줄(다섯 사람 의견이 갈림)은 뺀다. MNLI 학습 셋에도 같은 규칙을 건다.

## 양 정하기

- 앞 판 한 바퀴 = KLUE 학습 약 2.5만 + KorNLI 5만(MNLI 7 : SNLI 3).
- 영어도 같은 꼴로 바퀴마다 겹치지 않는 표본을 뽑는다 : **MNLI 5만 + SNLI 2.5만**.
  - MNLI 는 장르가 열 가지고 문장이 길어 클라이언트의 실사용 문장에 더 가깝다 → 몫을 크게.
  - SNLI 는 사진 설명 한 줄짜리라 쉽다 → 몫을 반으로.
- 한 : 영 = 7.5만 : 7.5만 = 1 : 1. 한국어가 주 손님이므로 영어가 이보다 많아지지 않게 한다.
- 한 바퀴 15만 쌍 · batch 32 면 약 4,700 스텝. klue 판(2,300 스텝 · 12.5분)의 약 2배라 한 바퀴 25~30분으로 어림한다.

## 3. 다음 소단계(기반 학습)에 넘길 것

```
# 학습 동안 같은 GPU 를 쓰는 다른 서버는 사람이 내린다.
run/podman-train.sh -e TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=0 -e HF_HUB_OFFLINE=1 --name base-2 \
  train/train_nli.py --device cuda --dtype bf16 --init hf/xlm-roberta-large \
  --train data/prep/klue-train.jsonl \
  --train-epoch data/prep/kornli-e{epoch}.jsonl --train-epoch data/prep/mnli-e{epoch}.jsonl \
  --train-epoch data/prep/snli-e{epoch}.jsonl \
  --dev data/prep/klue-dev.jsonl --out runs/base-2 \
  --epochs 2 --batch 32 --max-len 128 --lr 8e-6 --warmup 0.10 --seed 1
```

- 한 바퀴 약 15만 쌍 · 4,700 스텝 → **바퀴당 25~30분, 두 바퀴 + 평가 약 1시간** 으로 어림한다(klue 판 12.5분 × 2).
- 메모리 : 몸통이 337M → 560M 이라 가중치 + AdamW 상태가 약 5.4GB → 9GB 로 는다. GTT 는 klue 판 +10.8GB 에서 **+15~17GB** 로 어림한다(안 잼). 검사점 `ckpt-last` 도 약 1.7배 커진다.
- lr : XLM-R large 는 NLI 에서 무너짐(한 라벨만 냄) 보고가 많아 klue 판 1e-5 보다 조금 낮추고 warmup 을 늘렸다. 근거는 경험칙이라 약하다 — 무너지면 스크립트가 씨앗 +1 로 두 번, 그 뒤 5e-6 으로 다시 한다.
- dev 는 KLUE dev(3,000) 그대로 — klue 판 0.908 과 바로 견줄 수 있다. 영어 성능은 학습 셋만 쓰기로 해 지금 따로 잴 셋이 없다. 필요하면 MNLI dev matched(라이선스 같음, 학습엔 안 씀)를 평가 전용으로 푸는 것을 다음 판에서 정한다.
- 그 뒤 : `eval_nli.py --max-len 320` · `calibrate.py --temperature-only` → `export_onnx.py --name nli-base-v2 --body-name FacebookAI/xlm-roberta-large --body-weights hf/xlm-roberta-large/model.safetensors`.
