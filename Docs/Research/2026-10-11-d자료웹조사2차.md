## 1. 결론 먼저

| 갈래 | 닿은 결론 |
| --- | --- |
| A — 논문 | **NEI-CAP(2026)** 이 우리 d 문제를 그대로 쟀다. 「아무 증거나 붙인 NEI」로만 배운 DeBERTa 는 「관련 있지만 모자란 증거」 재현이 **0.216**, 여러 꼴을 고르게 섞으면 **0.915** [A21 원문]. 새 후보는 IBM ArgKP · AmbiFC · WiCE · MiniCheck C2D/D2C · Jira. 트랜스포머 1단 4칸으로도 「discuss」(≈d) F1 84.57 이 선다 [A30]. |
| B — 오픈소스 | 「같은 대상」을 **자료 구조가 보장하는** 셋이 낫다 — VitaminC NEI(train 52,981 [셈]) · KLUE-MRC 답 없는 질문(한국어 7,350 [셈]) · ContractNLI · Jira `Relates` · 설계 제안서(PEP 등). **KLUE-STS 1~2점대는 1,302쌍 중 73% 가 숙소 후기이고 예시가 c 쪽**이라 평가를 낮춘다. FEVER·VitaminC·SICK·AI허브 라이선스를 원문으로 확정했다. 재사용할 틀은 `mine_hard_negatives` · distilabel + Argilla. |
| C — 커뮤니티·방안 | 실무에서 된 것 1위는 **「입력은 실물, 라벨만 LLM」**. 합성이 필요하면 실물 씨앗 다시 쓰기로만 하고, **「진짜 같은 것만 남기는」 판별기 거르기는 하지 않는다**(F1 0.55 → 0.26) [C6]. 캔 d 후보에는 사실은 a 인 쌍이 섞이니 교사로 거른다(정답 점수 95% 문턱) [C10][CV5]. 학습 전에 돌릴 「자 다섯」과 만들기 길 ㄱ~ㄹ 을 냈다. |

**d 가 안 배워지는 까닭은 모델보다 자료 쪽이다.** 메인이 학습 자료를 직접 세어 보니 train-r2 2,965줄 중 d 는 **285(10%)** 뿐이고 못 고른 `cd` 가 306 으로 더 많다(5절). NEI-CAP 은 d 를 한 꼴로만, 또는 적게 가르치면 a 로 샌다는 것을 보여 준다. 그래서 다음 d 자료는 ① 같은 대상을 **구조로 보장하는 실물 원천**에서 캐고 ② **여러 꼴**(같은 문서 · 근접 검색 · 받침 문장 빼기 · 링크)로 섞고 ③ **교사로 거짓 음성(사실은 a)을 거르고** ④ 사람은 **갈린 쌍만** 본다. 한국어 개발 글꼴 d 공개 셋은 이번에도 없다. 영어 구조 원천(Jira · 제안서 · VitaminC)으로 뼈대를 세우고, 한국어는 KLUE-MRC 바꾸기와 우리 실물로 채우는 그림이다. 1차 권고(길 2 먼저)와 이번 방안을 엮은 조합은 8절에 있다.

## 5. 왜 d 가 안 배워지나

세 까닭이 겹친다.

### 5-1. d 를 한 꼴로만 가르치면 안 선다 (A — NEI-CAP)

- NEI-CAP 은 NEI 를 만드는 꼴 8가지(자리표 · 무작위 · 위치 · **BM25 근접** · **인용했지만 근거 아님** · **같은 문서** · 같은 주장 증거 갈아끼우기 · 한 고리 빼기)로 나눠 각각 학습·평가했다 [A21 원문].
- DeBERTa-v3-base 어려운 NEI 재현 : 무작위로만 학습 **0.216** · BM25 근접 0.691 · 인용 0.679 · 쉬운 꼴 섞음 0.178 · 어려운 꼴 섞음 0.770 · **모두 고르게 섞음 0.915**. 자리표로 배우면 같은 꼴 F1 1.000 인데 어려운 꼴 0.000 [원문].
- 우리 증상과 같은 그림이다 — blind v4 에서 d 55쌍 중 20 이 a 로, 11 이 b 로 갔다(1차 전제) [추론].

### 5-2. 학습 자료에 d 가 적다 (메인 직접 확인)

메인이 git 밖 `~/.judgemodel/sets/2026-10-10/build/` 의 README 와 파일을 직접 셌다.

| 묶음 | 줄 | 칸 구성 | kind |
| --- | --- | --- | --- |
| train-r2 (학습 전체) | 2,965 | support 1,161 · contradict 761 · unrelated 452 · **related(d) 285** · **cd 306** | synth-supersede 671 · synth-related 65 이 이미 들어 있음 |
| synth-r2 (R3 합성) | 320 | a 160 + b 160, 같은 기억에서 짝으로 | flip-buried |
| synth-r4 (R3 합성) | 109 | a 80 + d 29, 짝 (합성 d 30% 상한) | ad-boundary |

- d 는 학습의 **약 10%** 이고 a 의 약 1/4 이다. 경계가 흐린 `cd`(306)가 d 보다 많다. `cd` 는 「합친 칸 손실」이라 d 를 직접 가르치지 않는다 [추론].
- **C 의 「합성 말투 = d 지름길」 가설은 대체로 아니다.** synth-r2 는 같은 말투에 a·b 가 반반이라 말투가 칸 신호가 안 된다. synth-r4 의 합성 d 는 29줄뿐이다.
- C 의 나머지 두 까닭은 그대로 살아 있다 : ② 한 축만 바꾼 최소 편집이라 고친 축만 배운다(1차 [34]) · ③ 320·109줄은 자 흔들림(13.5)에 묻힐 크기다(R3 6절).

### 5-3. 라벨러가 바로 d 에서 흔들린다 (A · C)

- 6개 LLM 으로 NLI 라벨을 붙이니 모든 모델에서 **neutral 이 가장 어렵고 불안정**, 전제·가설 순서만 바꿔도 흔들렸다 [A28 요약]. 1차의 Sabiá-3 사례(1차 [18])와 같은 쪽이다.
- LLM 라벨로 학습하면 판 사이 일치(α)가 84 → 44~53 으로 떨어졌다 [C5 원문]. 과학 NLI 에서 사람끼리도 neutral 일치가 68.3% 로 가장 낮다 [C34 요약].
- FNC-1 에서도 discuss ↔ unrelated 혼동이 양방향(330 · 262)이다 [C27 요약]. d ↔ c 는 칸별 F1 로 재야 한다.

→ **양이 적고(10%) · 꼴이 한 가지이고 · 라벨이 흔들린다.** 레시피보다 자료가 먼저다 [추론].

## 6. 자료를 만드는 방안

뼈대는 C 4절 (가)~(마)다. A·B 의 방법을 끼워 넣었다.

### 6-1. 실물 캐기 — 「같은 대상 열쇠」 안의 서로 다른 문장

- 열쇠를 메타데이터로 잡고 그 안의 서로 다른 문장을 짝짓는다 [C 추론]. 열쇠는 1차 2-2 의 「같은 대상」(같은 사물 · 사건 · 기능 · 규칙 · 수치 자리)으로 고른다. 넓으면 c, 좁으면 a 가 섞인다.

| 원천 | 같은 대상 열쇠 | d 후보 | b 후보 |
| --- | --- | --- | --- |
| Jira · 이슈 · PR [B5][1차 GitBugs] | Relates 링크 · 같은 컴포넌트 · 같은 이슈 | Relates 짝 · 같은 이슈 다른 댓글 · 비중복 버그 | 「이건 아니다」 댓글 |
| 설계 제안서 · ADR [B7][B8] | 같은 제안서 · 같은 결정 번호 | 같은 문서 다른 절 | 대체(superseded) 짝 |
| git 커밋 · CHANGELOG | 같은 파일 · 함수 · 기능 이름 | 같은 파일 다른 커밋 | revert · 값 바꿈 커밋 |
| 한국어 위키 | 같은 문서 · 같은 절 | 같은 판 안 다른 문장 | 사실이 바뀐 수정 전후 |

- **NEI-CAP 대로 꼴을 섞는다** [A21] : 같은 문서 · BM25 근접 · 인용했지만 근거 아님 · 링크 · 받침 문장 빼기(6-2)를 한 묶음에 고르게. **c 를 무작위 짝으로만 만들지 않는다.**
- **거짓 음성 거르기** — 같은 열쇠 안에는 서로 받치는 짝이 섞인다. 검색 학습에서 굳은 고침 [CV5][C10] :
  1. 지금 JudgeModel 로 a·b 확률을 잰다.
  2. 정답 쌍 점수의 **95% 넘는 쌍은 버리거나** a/b 후보로 돌린다.
  3. **캐는 모델과 학습할 모델을 다르게** — Opus 나 로컬 모델로 한 번 더.
  4. 순위 꼭대기 말고 중간 구간(예 : 10~60위)에서 뽑는다. dev.to 사례는 자기 모델로 top-15 를 캤다가 기본 모델보다 떨어졌다 [C10].
- **틀** : sentence-transformers `mine_hard_negatives`(Apache-2.0) — `range_min`(가장 비슷한 위 n개 건너뜀) · `range_max` · `max_score` · 여백 · cross-encoder 재채점 [B29]. 같은 저장소·같은 문서 문장을 말뭉치로 주면 d 후보 풀이 된다. 한국어는 FlagEmbedding `hn_mine` + bge-m3 가 편하다 [B32].
- 함정 : 개인정보(1차 1-3) · 「fix typo」 같은 빈 커밋은 길이·낱말로 거른다 · 나무위키는 비상업.

### 6-2. 받치는 문장 빼기 (A — MiniCheck · SufficientFacts)

- MiniCheck : 문서에서 **받치는 문장 하나를 빼고** 그래도 안 받쳐지는지 교사가 확인 → 「같은 문서 · 받침 없음」 [A6]. 이 합성을 빼면(ANLI 만) LLM-AggreFact BAcc 가 **−14.8**(59.9) [원문].
- 우리 실물 메모에 바로 된다 : 메모 → 주장을 받치는 줄 빼기 → 남은 메모 ↔ 주장 = d 후보 [추론]. 교사 확인 비용이 들고, 남은 글에 반대 문장이 있으면 b 라 2단 분리가 필요하다.
- SufficientFacts : 사람이 매긴 2,600쌍. 부사 수식어가 빠진 것을 가장 못 찾았다(21%, 날짜는 63%) [A12 요약] → 평가·진단용.

### 6-3. 합성 — 해야 한다면

**되는 조건**

| 조건 | 근거 · 숫자 |
| --- | --- |
| **실물 씨앗 다시 쓰기** (근거만 다시 쓰고 주장은 실물) | 비꼼 macro-F1 맨 합성 0.48 → 다시 쓰기 0.55 · 실물 0.60 [C6 원문] · WANLI 도 실물 씨앗 + 사람 고침 [C16] |
| **속성 격자로 다양성 강제** | 단순 칸 조건 프롬프트는 다양성이 낮다 [C3 요약]. 격자 예 : 대상 종류 × d 종류(다른 속성 · 다른 시점 · 다음 단계 · 원인↔결과) × 길이 × 글꼴 |
| **네 칸을 같은 말투로 같이** | 출처 말투가 칸 신호가 되지 않게 [C11]. 지금 synth-r2 는 이미 a·b 짝이다(5-2) |
| **k회 다수결** | Mixtral 라벨 91.6 → 94.0 (k=3) [C7 원문] |
| **일관성 앙상블 → 뒤집히는 쌍만 사람** | 차이의 60~75% 회복 [C5 원문] |
| **여러 판정 거르기 + 원 자료 돌려 섞기** | 어려운 벤치 일관성 63.5% → 81.0%, 원 정확도 유지 [A23 요약] |

**하지 말 것** : 「진짜처럼 보이는 것만 남기는」 판별기 거르기 — F1 0.55 → **0.26** [C6] · 맨 프롬프트 합성 [C6][CV2] · 합성으로 사람 자료를 **대신**하기 — zeroshot base 0.643 → 0.619 [C8] · 합성 음성만 따로 쓰기 — 캐낸 음성보다 늘 못함(nDCG@10 0.292) [C12 요약][A24].

### 6-4. 사람 라벨을 싸게

- **입력은 실물, 라벨만 LLM, 사람은 고치기** — 요리 8시간 · S&P Global 15시간으로 LLM 기준선을 넘음 [CV1] · 금융 감성 학생 RoBERTa ≈ GPT-4 [C7].
- **질문을 예/아니오로 쪼갠다** : 같은 대상인가 → 받치는 말이 있나 → 어긋나는 말이 있나. 범주 하나씩 묻자 10배 빨랐다 [CV1].
- **불확실 + 무작위 반반** : 불확실 표집이 약 10% 나았지만(그림 눈대중) [CV3], 라벨이 아주 적은 시작에선 무작위가 이기기도 한다 [C22][C23]. 「불확실」 = a·d 확률 차가 작음 · Opus k회 중 갈림 · 로컬과 Opus 가 어긋남.
- **순서 바꿔 두 번 묻기**로 흔들리는 쌍을 사람에게 [A28 추론].
- **1인 일관성** : 같은 사람도 약 25% 다르게 답한다 [C24]. 지난 감사의 5% 를 몰래 다시 붙이고, 10% 넘게 바뀌면 지침을 다시 본다 [C25].
- **틀** : distilabel(LLM 라벨러 둘 합의) + Argilla(갈린 쌍만 띄우는 감사 화면), 둘 다 Apache-2.0 [B30]. 질문 → 평서문 바꾸기는 AlignScore 코드(MIT)를 빌린다 [B10].
- B 의 권하는 묶음 : 구조로 짝 뽑기 → `mine_hard_negatives` 보충 → distilabel 라벨러 둘 → Argilla 감사.

### 6-5. 번역

- 영어 d 자료는 **번역하지 않고 그대로** 중간 학습에 쓰고 한국어 실물로 마무리하는 쪽이 싸고 위험이 적다 [C 추론] (영→한 손실 약 3점, 1차 3절).
- 번역할 거면 숫자 · 이름 · 부정어가 그대로인지 규칙으로 검사한다. 숫자가 흐려지면 a → d, 부정을 놓치면 b → d 로 샐 수 있다 [추론].

### 6-6. 학습 전에 재는 「자 다섯」 (C)

| 자 | 하는 일 | 통과 기준(안) [추론] |
| --- | --- | --- |
| ① 주장만 보는 모델 | 근거를 지우고 주장만으로 d 를 맞히게 한다. LLM 이 만든 NLI 는 가설만 보고 86~96% 맞힌다 [C13] | 실물 d 와 비슷. 크게 높으면 말투 지름길 |
| ② 출처 판별기 | 같은 칸 안에서 합성 vs 실물을 가린다 [C11] | **진단용만. 거르기에 쓰지 않는다** [C6] |

## 7. 학습법 보강 (A 4절 요약)

- **1단 4칸으로 d 칸이 선다.** FNC-1 1단 4칸 discuss F1 : BERT 80.07 · XLNet 82.10 · RoBERTa **84.57** (unrelated 99.16 · disagree 58.06 · agree 70.71) [A30]. 단 FNC-1 unrelated 는 무작위 짝이라 쉽다 — 우리 c(같은 분야 다른 대상)는 훨씬 어렵다. 같은 자료로 2단과 견준 숫자는 없다.
- **LP-FT 는 NLP 에서도 작게 이득, 대신 보정이 나빠진다.** RoBERTa-base FT → LP-FT : CB 81.43 → 84.64 · RTE 74.73 → 76.75 · SemEval 은 조금 떨어짐 [A32]. 머리 크기가 커져 RTE 보정 오차가 63.95, 온도 보정 뒤 13.94 → **LP-FT 를 쓰면 온도 보정을 같이** 한다.
- **소프트 라벨** : ChaosNLI 정확도 hard 51.75 → soft 55.30 [A33 요약]. 이득의 큰 몫이 스무딩 효과라는 반론도 있다 [A34]. → d ↔ a · d ↔ c 경계 쌍은 LLM 둘·사람 의견을 분포로 넣고, 최소한 label smoothing 0.1.
- **보정** : 온도 보정만으로는 과신이 남는다. 보류 문턱을 쓸 거면 소프트 라벨 dev 로 보정한다 [A35 요약].
- **칸 늘리기** : 우리는 옛 자료를 다 다시 섞으므로(replay 100%) 잊음 걱정은 작다 [A36 · 추론].
- **LLM 교사 → cross-encoder NLI 4칸 증류 사례는 없다.** 재순위 증류의 교훈 「어려운 음성이 핵심」은 NEI-CAP 과 같은 쪽이다 [A37].

## 8. 방향 후보

1차 5절의 **길 1 · 2 · 3** 과 C 5절의 **자료 만들기 길 ㄱ~ㄹ** 을 엮었다. ㄱ = 실물 캐기 + 교사 거르기 · ㄴ = 실물 씨앗 다시 쓰기(WANLI 꼴) · ㄷ = 쓰면서 쌓기 + 불확실 쌍 감사 · ㄹ = 실물(공개) 짝에 LLM 라벨만. 네 길은 서로 막지 않는다. 공수는 모두 어림 [추론]. **결정은 적지 않는다 — 사용자가 고른다.**

## 9. 못 찾은 것 · 확인 못 한 것

- **정식 topic-aware NLI 셋**과 d 칸을 가진 공개 cross-encoder (A · B). NEI-CAP 자료는 「곧 공개」.
- **한국어** : d 성격 공개 셋(KLUE 밖) · 같은 사건 다른 기사 셋(중국어 CNSE 만) · 팩트체크 NEI 셋 · 위키 수정 이력 NLI 셋 · 스탠스 4칸 셋 · 국내 실무 경험담(GeekNews 소개 글 1건뿐) · 국내 영상. K-HALU 는 라이선스·라벨 꼴을 못 봄.
- **학습법** : LLM 교사 → cross-encoder NLI 4칸 증류 · 트랜스포머 2단 vs 1단 같은 자료 비교 · LP-FT 로 칸을 새로 붙인 숫자 · NLI 에서 실물:합성 비율을 잰 연구 · neutral(related-but-neutral) 칸만 따로 합성해 잰 경험담 · 번역이 a/b 를 d 로 흐리는 비율.
- **라이선스 원문을 못 본 것** : AmbiFC(봇 차단) · IBM ArgKP 원 배포 조건 · NEI-CAP · VAST · Climate-FEVER · PIT-2015 · Twitter URL · 나무위키(404) · 한국어 위키백과 · 모두의 말뭉치 약정(승인제만 확인) · FNC-1 · SO · LinkSO · ADR 셋(1차부터).
- **세지 못한 것** : Jira 덤프의 `Relates` 수·비율·실제 짝(5.8GB 라 안 받음) · ContractNLI `NotMentioned` 비율 · SQuAD 2.0 답 없음 수(43k 는 기억) · KLUE-STS 1~2점대를 2단 지침으로 붙였을 때 수확률(예시 6개만).
