- 왜 : 「1.0.0 · 1.1.0 · 1.2 셋이 왜 그런 결과가 났나」를 한 자리에서 견줘, 다음 판(v1.2 다시 시도) 설계의 근거로 쓴다.
- 쓴 사람 : Opus 서브에이전트 · 읽기와 셈만 했다(코드 · 셋 · 모델 · 미니PC 는 안 고쳤다. blind-g4 는 열지 않았다).
- 칸 : a 지지 · b 반대 · c 무관 · d 비슷한 계열(같은 대상, 받치지도 뒤집지도 않음). 뜻은 `../Guide/라벨기준support-v6.md`.
- 표시 : **[원문]** = 문서 · 측정 출력에 적힌 숫자 · **[셈]** = 이번에 학습 층 · dev 셋 파일을 직접 세어 본 값 · **[추론]** = 이 문서가 엮은 말.
- 숫자의 늘었다 / 줄었다 방향은 측정 문서 원문에서 옮겼고, K · K3 몇 줄은 git 밖 `compare.md` 원본과 다시 맞췄다.

## 0. 결론

1. **세 판은 같은 자로 잰 적이 없다.** v1.0.0 은 mem 쌍 자(blind v2)에서 통과했고, v1.1.0 은 공개 원천 중심 자(blind-g1)에서 절대 자 셋을 못 넘고도 「3칸 개선판」으로 나갔다. v1.2 후보는 「v1.1.0 대비 일곱 축 모두 안 나빠짐(95% 아래끝)」 자를 받았다. 판끼리 숫자를 그대로 이어 보면 틀린다.
2. **v1.0.0 의 약점은 「관련은 있지만 다른 말」(d 성격 쌍)이다.** 3칸이라 이런 쌍을 a · b 로 불러, 실사용에서 무관 쌍을 반대로 확신하는 일이 많았다(모순 큐 c→b 32/32). v1.1.0 은 d 칸 + 우리 아카이브 자료로 이 「확신 틀림」을 크게 줄였고, 대신 d 자체는 못 가르고(.46) 보류가 늘었다(.42).
3. **v1.2 의 다섯 후보는 모두 같은 기제로 깨졌다 — 「한 원천을 한두 칸으로만 넣으면, 모델이 그 원천의 겉모양을 그 칸의 단서로 쓴다.」** B 는 VitaminC 를 a · b 로만 넣어 VitaminC c 를 b 로, K 는 BoolQ · 위키를 a · b · d 로만 넣어 그 원천의 c 를 d · b 로, K2 는 공개 원천 c 를 겹침 낮은 꼴로만 넣어 공개 원천 d 를 c 로, K3 는 VitaminC 를 d 로만 넣어 VitaminC c 의 95% · b 의 32% 를 d 로 보냈다 [셈 + 원문].
4. **공개 원천에서 얻은 것은 우리 글(mem · archive)로 거의 안 넘어간다.** 공개 원천 층은 늘 그 원천의 칸만 올렸고, mem · archive 의 b · d 는 그대로이거나 조금 내렸다.
5. **다음 판의 첫 수는 「원천마다 네 칸이 고루 든 층」으로 바꾸는 것이다.** 층 하나를 더할 때 원천 × 칸 표에 빈칸이 생기지 않게 하고, dev 에도 같은 원천 × 칸이 다 들어가게 한다. 가중치 · 합성 · 보정은 이미 여러 번 안 먹혔다.

### 2-1. v1.0.0 — 「mem 3칸」에는 강하고 「관련 있지만 다른 말」에 약하다

- 몸통을 한·영 xlm-r 로 바꾸고(dev 반대 재현 .768 → .838), mem 의 「덮은 결정」 약점을 합성 supersede 로 메웠다(blind 합성 블록 반대 재현 .915) [원문 · 길1보강반복 · R5 5절].
- 자가 쉬웠다 [추론, 결정이력복원 2-2 원문 근거]. blind v2 의 반대 161 은 모두 만든 쌍(flip · 합성)이고, 무관 82 는 범위가 뻔히 다른 쌍(sscope · xscope)뿐이라 d 성격 쌍이 거의 없다.

- 흐름 [추론] : B 의 b 이득은 영어 몫이었고 ko b 를 못 올려 K 로 갔다 → K 는 ko b 를 올렸지만 한국어 c 를 잃어 K2 로 갔다 → K2 는 c 를 찾았지만 d 를 잃어 K3 로 갔다 → K3 는 d 를 찾았지만 영어 b · c 를 잃었다. **판마다 앞 판이 깬 칸 하나를 메우는 층을 그 칸만으로 더했고, 매번 새 칸을 깼다.**

### R1. 원천 하나 = 칸 하나 지름길

학습 층의 원천 × 칸 [셈 : 얼린 학습 파일 줄 수] 과, 같은 원천이 평가에서 다른 칸일 때 일어난 일 [원문].

| 판 | 학습에 들어간 그 원천의 칸 | 평가에서 쓸려 간 것 |
| --- | --- | --- |
| B4h | VitaminC : a 199 · b 199 · c 0 · d 0 | VitaminC c → b (c .800 → .659) |
| K | kowiki : c 1 / BoolQ : c 0 / KLUE-answered : c · d 0 | BoolQ · 위키 · KLUE near-x c → d · b (BoolQ c .833 → .633 · klue-mrc c .819 → .667) |
| K2 | 공개 원천 c 1,300 은 겹침 .01~.07 / 공개 원천 d 397 은 겹침 .79 | 겹침 낮은 공개 원천 d → c (klue-mrc .396 → .123 · VitaminC .491 → .221) |
| K3 | VitaminC : d 250 만 (K 처방에 VitaminC 학습 쌍 0) | VitaminC c 의 95% · b 의 32% → d |
| (대조) B1 · Ⅱ | VitaminC a 365 · b 197 · c 81 · d 318 등 원천마다 네 칸 | d 는 그 원천에서 크게 오름(.32 → .76). 다른 칸 붕괴 대신 b 가 조금 내림(−.024) |

- **닻이 있는 꼴은 안 쓸렸다.** K2 에서 archive d(학습 266 · 겹침 .12) · mem d · 위키 wiki-edit d 는 그대로였다(K2-d붕괴진단 2-2) [셈]. 같은 겉모양의 다른 칸 쌍이 학습에 있으면 지름길이 안 선다.
- 웹조사 2차 · mem `20261011-1a170e6a` 의 「NEI 를 한 꼴로만 배우면 어려운 NEI 재현이 무너진다(.216 → 여러 꼴 .915)」와 같은 그림이다 [원문].
- **바로 이것이 v1.2 다섯 판의 실패를 한 줄로 설명한다** [추론]. 층을 만들 때 「목표 칸만 뽑고 다른 칸은 버리는」 짝 규칙(예 : B 층은 a · b 짝만, K3 d 층은 판정이 c · a · b 인 후보 418줄을 버림)이 원천 × 칸 빈칸을 스스로 만들었다.

### R2. 한 축의 양쪽

| 경계 | 축 | 증거 |
| --- | --- | --- |
| c ↔ d | 겹침(주장 낱말이 근거에 있는 몫) | K2 : 겹침 0~.1 구간에서 ko d→c .30 → .51 · en .50 → .74, 같은 구간 c 정답은 .83 → .95. 「c 얻은 것과 d 잃은 것이 한 축의 양쪽」(K2-d붕괴진단 2-4) [셈] |

### R3. 공개 원천 이득은 우리 글로 안 넘어간다

| 판 | 공개 원천 몫 | 우리 글 몫 |

- 거꾸로 우리 글 층(ㄱ arch)은 우리 글과 제안서 d 를 올렸다(g1-ㄱ짝비교) [원문]. **d 이득은 학습 자료의 원천을 따라간다**는 10-11 의 읽기가 다섯 번 다 맞았다.
