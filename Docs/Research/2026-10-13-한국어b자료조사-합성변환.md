**한 줄 판단** : 돈은 걸림돌이 아니다(1,000 b 에 판정비 수십 달러 어림). 걸림돌은 ① **한국어 씨앗이 평가 셋과 겹치지 않게 뽑는 것**과 ② **합성 b 가 「대놓고 어긋남」만 가르치는 함정**(ㄴ 의 실패)이다. 그래서 세 길 모두 **한 자리만 바꾼 b + 같은 씨앗의 a 짝**으로 만들고, 진단 3-2 의 「다시 쓸 조건」(b 만 · 한국어 실물 씨앗 · 최소 고침 · a 짝 · 출처 판별기 .65 아래 · 학습 b 의 25% 이하)을 관문으로 건다.

**KLUE 가 실패한 까닭** : 「답 없는 질문」은 지문이 그 자리 값을 **말하지 않는다**. 그래서 가짜 답을 넣어도 지문과 「둘 다 참일 수 없는」 말이 생기지 않고, v6 3절 「답 없는 질문을 바꾼 문장」 규칙대로 d 가 된다. 설계가 원천을 거꾸로 골랐다. b 를 만들려면 **지문이 참 답을 직접 적는 질문**에서 답만 바꿔야 한다(길 2).

## 1. 길별 설명

### 1-1. 한국어 실물 문장 씨앗 → 최소 고침 b (추천 1)

- **무엇** : 우리 문서 · 기억의 한국어 문장 중 **값이 하나뿐인 자리**(수 · 날짜 · 서수 · 켬/끔 · 누가 냈나 · 이상/이하)가 있는 문장을 씨앗으로 고른다. 그 자리 하나만 바꾼 문장을 주장으로 만들어 b 후보로, 같은 뜻을 다른 꼴로 쓴 문장(「90초」→「1분 30초」, 「4만 7천」→「4만이 넘는다」)을 a 짝으로 만든다.
- **왜 1순위** : 실사용 글꼴(짧은 기술 · 기획 문장)이 그대로이고, 진단이 말한 모자란 꼴 ㉠(수 · 한정어 · 서수) ㉡(낱말 하나 바꿈)을 바로 겨냥한다. 합성 ㄴ 이 깨진 까닭(근거를 대놓고 어긋나게 다시 씀 · 주장 하나에 근거 넷)을 피하는 꼴이다.
- **공개 레시피** : FactCC(Kryściński 외 2020)가 수 · 날짜 · 개체 · 대명사 바꿈과 부정 넣기를 규칙으로 해 「안 맞음」 자료를 만든다 [검색 · 코드 BSD-3 원문]. LLM 반사실 연구(Nguyen 외 2024)는 **LLM 이 NLI 라벨 뒤집기에 가장 약하다**고 적는다 — 뒤집힘률 GPT-4 57~66% · 사람 59~80%, 그리고 LLM 반사실을 학습에 더하면 원래 시험 점수가 오히려 떨어졌다(71.85 → 53~63) [원문]. → 생성 모델의 라벨을 믿지 말고 **v6 두 판 판정으로 걸러야 한다**는 근거다. 반대로 Google 의 합성 NLI(2024)는 LLM 라벨이 사람 다수결과 80% 맞고, 합성으로 MNLI 보다 TRUE 평균이 3~9점 올랐다 [원문] — 넓은 영역 합성은 통한다.
- **생성기 고르기** : 규칙으로 바꿀 자리를 고르고(정규식 : 숫자 · 날짜 · 「처음/마지막」 · 「켬/끔」 · 「이상/이하/넘는/못 미치는」 · 「전/뒤」), **문장 다듬기만** LLM 에 맡긴다. 한국어는 숫자 뒤 조사가 읽는 소리에 따라 바뀌어(3이 · 4가) 규칙만으로는 어색한 문장이 생긴다 [어림]. 다듬기는 로컬 Qwen3.6(Apache 2.0)로 충분할 것으로 보나 재지 않았다. Opus 를 쓰면 품질은 낫지만 약관 판단이 따른다(4절).
- **비용** : 씨앗 100개 생성 · 판정 두 판 + 셋째 10% 를 Opus 5.5 단가($4 · $20 / 백만 토큰 [원문])로 셈하면 100 후보당 약 0.7달러 → b 1,000 (남김률 .7, a 짝까지 판정) 에 **약 20달러** [어림]. 우리 판정은 구독 몫으로 돌아 실제 돈보다 **시간**이 비용이다 : 도구 4~6시간 + 판정 3~5시간.
- **품질 기대** : v6 3절 ③ 이 「값 하나 자리 바뀜 → b」를 정해 두어 남김률이 높을 것이다(.70~.85). 새는 곳은 **둘 다 참일 수 있는 자리**(쓴 툴 중 하나)를 바꾼 경우 → d, 때 · 조건이 다른 경우 → d. 자리 목록을 「값 하나」 표로 좁히면 줄일 수 있다.
- **함정** : 숫자만 다르면 b 라는 지름길을 배울 수 있다. **d 짝(같은 자리 · 다른 때)** 과 **a 짝(단위 · 꼴 바꿈)** 을 같은 씨앗에서 같이 넣어 막는다. 출처 판별기 .65 를 넘으면 접는다(진단 3-2 조건).
- **겹침** : 가장 위험하다. 한국어 고침 원천의 문서 묶음이 dev-cmp-g2 · dev-cal-g2 · blind-g2 로 이미 예약됐고 g1 평가 묶음도 있다(sets-g2 2 · 3절). 씨앗은 `blind-g2.forbid.json` 의 문서 경로 · 커밋 · 묶음과 g1 · g2 금지 목록 **밖의 문서**에서만 뽑는다. 남는 문장 수는 세지 않았다(5절).

### 1-2. KLUE-MRC 답 바꾸기 (추천 2)

- **무엇** : 지문이 답을 직접 적는 질문(유형 1 바꿔 쓴 질문 · 유형 2 여러 문장 추론)에서, 답을 **같은 종류의 다른 값**(같은 지문의 다른 날짜 · 다른 사람 · 다른 수)으로 바꿔 평서문 주장을 만든다. 근거 = 참 답이 든 문장 1~2. 참 답 평서문은 a 짝이다.
- **레시피** : QACG(Pan 외 ACL 2021) — 질문 · 답 쌍을 만든 뒤 답을 Sense2Vec 의 비슷한 말 상위 5 중 하나로 바꿔 REFUTED 주장을 만든다. 손으로 본 100개 중 바꾼 답이 사실은 맞았던 것이 2개(2%) [원문]. 무학습 FEVER F1 이 약 50 → 77 [검색].
- **지금 도구와 다른 점** : `attach-rewrite` 의 평서문 바꾸기는 그대로 쓰고, 입력만 「답 없는 질문 + 가짜 답」에서 「답 있는 질문 + 같은 지문 속 같은 종류 틀린 값」으로 바꾼다. 같은 지문에서 고르면 「지문에 없는 값」이 아니라 「지문이 다른 자리에 쓴 값」이라 판정자가 근거 문장과 맞대 볼 수 있다.
- **비용 · 품질** : 다시 쓰기 · 판정 합쳐 10~20달러 · 반나절 [어림]. 남김률 .70~.85 [어림] — 값 하나 자리(언제 · 누가 처음 · 몇 개)를 묻는 질문만 고르면 높고, 「무엇을 했나」류는 d 로 샌다.
- **한계** : 뉴스 · 위키 글꼴이라 실사용 글과 멀다. 그래서 2순위다. KLUE-MRC 는 g1 에서 22,406 후보를 이미 캤으니 원천 수는 넉넉하다.
- **겹침** : g1 · g2 에 쓴 KLUE 지문 묶음(blind-g2 의 a 42 · c 40 포함)을 문서째 뺀다. 지금 `make_sets` 금지 규칙에 「KLUE 답 있는 질문」 줄을 더하면 된다.

### 1-3. VitaminC 대조쌍 번역 (추천 3)

- **무엇** : 학습 층에 이미 고른 VitaminC train 대조쌍(같은 주장 · 판 고침 전후 근거 a · b 짝)을 **짝째 한 번에** 옮긴다. 「두 근거는 바뀐 자리 말고는 글자까지 같게 옮겨라」를 지시하고, 옮긴 뒤 두 근거의 차이가 한 덩이인지 기계로 확인해 아니면 버린다.
- **왜 짝째인가** : 따로 옮기면 겹치는 낱말이 줄어 대조가 흐려진다(Artetxe 외 2020 「translation artifacts」) [검색]. 수 옮김 실수도 흔하다 — 상용 번역기와 연구 모델 모두 자릿수 · 단위 · 구분 기호에서 틀린다(Wang 외 2021) [검색]. 사람 확인 연구에서는 옮긴 쌍의 라벨을 사람이 원문과 비슷하게(83% vs 85%) 되살렸다(XNLI) [검색].
- **약관** : VitaminC 자료 고지 = 「위키 문서 약관, 없으면 CC BY-SA 3.0」 [원문]. 옮긴 자료도 BY-SA 를 따르며, 3.0 은 같은 요소의 뒤 판(4.0)으로 내는 것을 허용해 모델 공개(CC BY-SA 4.0)와 맞는다 [어림 — 법률 판단 아님]. 번역 도구 : Google Cloud Translation LLM 백만 글자당 10달러(입출력 각각) [검색 · 공식 요금 페이지 요약], Papago 는 단가를 확인 못 했고 「Papago 출처 표기 필수」 조건이 있다 [검색]. DeepL 은 출력 소유 조항을 찾지 못했다. **Opus 로 옮기는 게 가장 단순하다** — 출력은 우리 것 [원문], 비용은 1,000 짝에 5~15달러 [어림].
- **품질 기대** : 영어 VitaminC b 남김률이 dev-cmp .72 · dev-cal .82 였다(sets-g2 6-1). 번역 손실을 빼 .60~.75 [어림].
- **한계** : 이미 영어 VitaminC 가 b 를 +10%p 올렸는데 한국어 b 는 안 올랐다. 번역본은 **한국어 겉모습 + 위키 글꼴**이라 「언어」 차이는 메우지만 「글꼴」 차이는 못 메운다. 1 · 2 길과 같이 넣어야 의미가 있다. 비교 한정어(more than → 넘는다) · 서수 자리처럼 한국어 원천이 모자란 꼴을 채우는 몫으로 본다.
- **겹침** : 영어 평가 쌍의 번역본이 학습에 들면 언어만 바뀐 누출이다. train split 만 옮기고 `pick_contrast` 의 묶음(위키 문서) 금지를 그대로 쓴다.

### 1-4. 한국어 위키 + Wikidata 값 바꾸기

- **무엇** : 한국어 위키 문장에 Wikidata 값(태어난 해 · 세운 해 · 낸 회사 · 개발사 등)이 글자로 들어 있으면, 그 값을 같은 속성의 다른 값으로 바꿔 주장을 만든다.
- **좋은 점** : Wikidata 속성에는 **「값 하나」 제약**(single-value constraint, Q19474404)이 붙어 있다. 태어난 곳 · 죽은 곳이 그 예다 [원문]. 이 표로 v6 ③ 의 「값 하나 자리 → b · 둘 다 참일 수 있는 자리 → d」를 기계로 가를 수 있다. 구분자(separator) 한정어가 붙은 속성(수도 + 시작 · 끝 때)은 「때가 다름 → d」 짝을 만드는 데 쓴다.
- **약관** : Wikidata 구조 자료 CC0, 위키 글 CC BY-SA 4.0 [원문 · 검색].
- **한계** : 문장 속 값 찾기(날짜 · 수 꼴 맞추기) 도구가 커서 1~2일. 글꼴은 위키라 3 과 같은 한계. 이미 VitaminC 위키 문서와 겹치는 문서는 뺀다.

### 1-5. 규칙만으로 바꾸기

- 수 · 날짜 · 서수 바꿈은 규칙만으로도 b 가 잘 나올 것이다(.80 넘음 [어림]). 부정 넣기(「-지 않는다」 · 「안/못」)는 대놓고 어긋난 b 라 ㄴ 의 실패를 되풀이할 위험이 있다. 비교말(이상 ↔ 이하 · 전 ↔ 뒤)은 범위 안팎을 따져야 해서 근거 값과 같이 봐야 한다.
- 한국어 NLI 부정 · 반사실 증강을 다룬 공개 도구는 찾지 못했다. 서강대 연구(2023 학위논문 · arXiv 2410.20710)가 「토큰 기반 · 문장 기반 증강으로 칸마다 반사실 쌍」을 만든다고 적지만 언어 · 코드 · 자료 공개가 초록에 없다 [원문 초록].
- **그래서 따로 쓰기보다 1-1 의 「자리 고르기」 단계로 넣는다.**

### 1-6. FEVER · WANLI · 반사실 SNLI 번역

- FEVER REFUTES 는 사람이 주장을 「바꿔 쓴」 꼴이라 최소 고침이 섞여 있지만, 근거가 검색기로 뽑혀 대조쌍 꼴이 아니다. 약관 BY-SA 3.0(mem `20261011-d394f0e6`).
- WANLI : CC BY 4.0 [원문]. GPT-3 이 만든 뒤 사람이 고친 자료다. 반대 쌍이 문장을 통째로 바꾼 꼴이 많아 ㉠ ㉡ 을 못 가르친다 [어림].
- 반사실 SNLI(Kaushik 외) : 저장소 Apache-2.0 [원문]이나 바탕 SNLI 약관도 따라온다. 이 자료로 학습해도 같은 크기의 보통 자료보다 일반화가 낫지 않았다(Huang 외 2020) [원문 초록].
- **셋 다 3 보다 b 꼴이 우리 목표와 멀어 뒤로 미룬다.** 한국어로 옮겨 공개한 판은 찾지 못했다(KorNLI 는 SNLI · MNLI · XNLI 만) [검색].

## 2. 품질 관리 (세 길 공통)

| 단계 | 하는 일 | 거르는 것 |
| --- | --- | --- |
| 생성 | 씨앗 하나에 b 하나 + a 짝 하나(+ 가능하면 d 짝 하나). 바꾼 자리 · 옛 값 · 새 값을 칸으로 남긴다 | — |
| 기계 검사 | 근거 · 주장 차이가 한 덩이인가 · 새 값이 근거에 이미 다른 자리로 있나 · 길이 · 물음 꼴 · `scrub.py` | 두 군데 넘게 바뀐 것 · 이름 샘 |
| 판정 | `label_batches.py` v6 두 판 + 셋째(지금 꼴 그대로) | hint 와 다른 칸 → **짝째 버림**(`pick_contrast keep-pairs` 규칙) |
| 관문 | 출처 판별기 .65 아래 · 학습 b 의 25% 이하 · 학습에 안 든 b 혼동표 먼저 | 진단 3-2 조건 |

- 생성 모델 라벨을 믿지 않는다. LLM 반사실의 뒤집힘률은 사람보다 낮다(1-1 의 수).
- 생성기와 판정기가 같은 Opus 이면 서로 같은 실수를 할 수 있다. 생성은 로컬 모델, 판정은 Opus 로 나누면 이 위험과 약관 위험이 둘 다 준다 [어림].

## 3. 비용 셈의 바탕 [어림]

- 판정 : 100쌍 묶음 하나 = 입력 약 18K 토큰(기준 글 + 쌍) · 출력 약 6K → Opus 5.5 단가로 판정자 하나당 약 0.2달러. 두 판 + 셋째 10% ≈ 100 후보당 0.4달러.
- 생성 : 씨앗 100개 = 입력 약 10K · 출력 약 10K → 약 0.25달러.
- b 1,000 = 후보 1,250~1,650(남김률 .6~.8) × a 짝까지 판정 → 15~25달러. 번역 길은 번역비 5~15달러를 더한다.
- 실제로는 Claude Code 구독 몫으로 돌아 돈보다 판 수 · 시간이 비용이다. 앞 판(blind-g2 641쌍 = 16판 + 셋째 1판) 규모와 비슷하다.

## 6. 못 찾은 것 · 재지 않은 것

- 한국어로 옮겨 공개한 VitaminC · FEVER · ANLI · WANLI 는 찾지 못했다(검색 두 번).
- 한국어 NLI 의 부정 · 수량 · 비교 표현 규칙 증강 공개 도구는 찾지 못했다.
- 번역이 b 의 작은 차이(한정어 · 서수)를 얼마나 지키는지 **잰 수치**는 찾지 못했다. 수 옮김 실수가 흔하다는 연구만 있다.
- DeepL · Papago · Google 번역 출력의 소유 · 학습 이용 조항 원문은 확인하지 못했다.
- 길 1 의 **씨앗이 금지 목록 밖에 몇 문장 남는지** 세지 않았다. 다음 판의 첫 일이다.
- 로컬 Qwen3.6 의 한국어 최소 고침 품질은 재지 않았다. 표본 50개로 먼저 본다.
