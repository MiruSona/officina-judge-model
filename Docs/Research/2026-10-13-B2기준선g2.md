# B2 기준선 g2 로 다시 재기

설계 `../Design/2026-10-12-v1.2-B판설계.md` 1절 4번 · 5-2 의 「기준선 B2」 차례다. 셋은 `../../measure/sets-g2.md`, 규약은 `../../measure/protocol-g2.json`(아직 미커밋). 1차 s3 평가는 옛 판 sha 2fb79965 로 쟀고, 10-13 손질 뒤 판은 cd561791 이다 — 1차 결과는 새 규약의 compare·baseline 에 그대로 못 넣고, 스크립트가 s3 를 다시 잰다.

## 0. 결론 (10-13 오후, 5절이 최종)

- **B4h(B 층 절반) 짝 비교는 「먹힘」 — 설계 5-3 판정 「통과」다.** 목표 b 는 **+.070 [+.044, +.098]** 이라 아래끝이 +.04 를 넘는다. 지킴 여섯과 경보 둘은 다 통과했다. d 는 +.005 [−.021, +.029] 다.
- 앞 판 B4(층 전부)는 b +.100 이었지만 d 아래끝이 −.041 이라 「지킴 깨짐」이었다(4절). 층을 절반으로 줄이니 b 오름은 .03 줄고 d 는 지켜졌다.
- 기준선 B2 는 판별 가능하다. 다섯 dev-cmp-g2 b .738 [.687, .787], 씨앗 평균 짝 반폭 어림 **.015**(1v1 .033) ≤ .04.
- b 오름은 거의 vitaminc·en 몫이다(B4h b .768 → .870). ko b 는 .643 → .624 (−.019)로 경보 문턱(−.03) 안이다.
- 새벽 1차(1~3절)는 ckpt 가 s3 만 남아 s3 만 쟀다. 게임 서버가 떠 있어 재학습이 멎었고, 사용자가 게임 서버를 끈 뒤 스크립트로 끝까지 돌렸다.

## 2. 게임 서버를 끈 뒤 돌릴 스크립트

미니PC `~/judgetool/logs/g2-B2B4.sh` (만들기만 했다. 머리 검사가 게임 서버를 보고 exit 2 하는 것까지 확인했다).

1. B2 재학습 s1·s2·s4·s5 — `logs/g1-B2.sh` 학습 명령 그대로, 학습만, 순차
2. B2 다섯을 g2 로 평가 — dev-cal-g2 · dev-cmp-g2 · 잣대 3쌍 · 곁 자 셋 → `runs/<판>/g2/`(옛 g1 eval 폴더는 안 건드린다), calibration 은 dev-cal-g2 로
3. `baseline.py` → `runs/g2-B2-base/baseline.json` — b 씨앗 평균 짝 반폭 어림 > .04 면 「판별 불가」로 멈춤
4. B4 학습 s1..s5 — B2 처방 + `--train mem/g2/train-g2-b.jsonl`, `--replay-n 2965` 그대로
5. B4 다섯을 g2 로 평가
6. `compare.py --protocol protocol-g2 --set dev-cmp-g2 --base B2 --new B4 --by domain,lang` → `runs/g2-B4-eval/`

- 머리 검사는 네 가지다 : 게임 서버 꺼짐 · llama 꺼짐 · 다른 jt- 컨테이너 없음 · 가용 40GB 이상. 셋 해시도 확인한다.
- 단계마다 스왑(시작 +256MB)·가용(10GB)을 본다. 끝난 단계는 `logs/g2-B2B4.stage` 에 쌓여 다시 띄우면 이어 돈다. 반쯤 남은 판은 스스로 지우지 않고 멈춘다.
- **돌리기 전에** 미니PC `src/measure/compare.py` 를 메인 PC 판(g2 규약을 읽는 판)으로 맞춘다. 10-13 기준 두 판이 다르다. 6번만 다시 돌리려면 `STAGE_ONLY=compare` 를 준다.
- 어림 시간 : 학습 9판 × 약 13분 + 평가 10판 × 약 3분 ≈ 2.5시간.
