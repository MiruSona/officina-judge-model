## 2. 쓸 수 있나 — 라이선스 · 약관 · robots · 속도 제한 · 덤프

### 2-1. 라이선스 [원문]

- 「리브레 위키:저작권 보호 정책」 : 「리브레 위키의 문서는 크리에이티브 커먼즈 저작자표시-동일조건변경허락 3.0 Unported 라이선스를 적용해 배포됩니다.」 바닥글 · API `rightsinfo` 도 CC BY-SA 3.0.
- 이용약관 18조 : 저작권은 편집자에게 있고, 모든 글은 CC BY-SA 로 배포한다. 「저작권자를 표시하는 조건으로 … 영리/비영리적으로 이용할 수 있고」 같은 조건일 때만 고쳐 다시 배포할 수 있다.
- **리그베다 위키 자료를 가져오지 않았다.** 「리브레 위키」 문서 : 「원래 리그베다 위키의 자료들을 포크하고자 했으나, 저작권 문제 때문에 그러지 않고 처음부터 새로 시작하였다.」 NC 자료가 섞일 뿌리가 없다.
- **함정 하나 — 나무위키에서 옮겨 온 이력.** 봇 `ZhunyBot` 이 2015년 6~7월에 SCP 관련 문서의 **이력을 나무위키에서 옮겨 왔다**(편집 요약 「유저 ○○가 [[나무위키]]에서 수정했던 로그」) [실물 · 표본 4,149 판 중 45 판]. SCP 글은 원래 CC BY-SA 3.0 이라 리브레 저작권 정책도 「호환」으로 적지만, **원 편집자가 나무위키 사용자**다. 회색이면 피하는 이 프로젝트 기준대로 **이 봇의 2015년 편집은 뺀다.** 표본 b 13 중 2(#147 · #218)가 여기 걸린다.
- **함정 둘 — 다른 위키에서 가져온 이력.** 사용자 이름이 `Wikichan>○○` 꼴인 판이 79개(표본 판의 1.9% · 2011 ~ 2016)다 [실물]. 미디어위키 「가져오기」로 다른 위키(위키챈으로 보인다)의 이력을 옮긴 것인데, **그 위키의 라이선스는 못 찾았다.** 확인 전엔 `>` 가 든 사용자 이름의 판을 뺀다. 표본 쌍 231 중 5(b 1 · #122)가 여기 걸린다.
- 3.0 → 4.0 : CC BY-SA 3.0 의 동일조건 조항은 「같은 요소를 가진 뒤 판」으로 내보내기를 허용한다 [기억]. 리브레 정책 문서도 「위키백과 2023년 5월 31일 이전판(3.0)」만 호환으로 적는데, 이는 리브레 쪽(3.0)으로 **들여올** 때 얘기라 우리 쪽(4.0)으로 내보내는 것과는 방향이 반대다.

### 2-2. 약관 · robots · 속도 제한

- **robots.txt [원문]** : 모든 봇에 `DisAllow : /` 를 걸고 `/wiki/` · `/` · `/sitemap/` 만 열었다. **`/api.php` · `/index.php`(이력 · 비교 화면)는 닫혀 있다.**
  - 한국어 위키백과 robots 도 `/w/`(api.php 포함)를 닫지만, 위키미디어는 따로 API 이용 규칙(속도 · User-Agent)을 두어 API 를 쓰게 한다. **리브레 위키에는 그런 API 안내 문서가 없다**(「리브레 위키:API」 404).
  - 대신 「리브레 위키:봇」 문서가 「일반 사용자는 검색 결과를 한 번에 500건까지 불러올 수 있다」 · 「IP 기반의 속도 제한」을 적어, 사람 · 도구가 API 를 쓰는 것은 전제한다 [원문].
  - **판단** : robots 는 색인용 긁개(크롤러)를 막는 규칙이라 이번 표본 크기(요청 245, 1초 간격)는 받았다. **전량(요청 수만)을 API 로 받는 것은 robots 의 뜻과 어긋나므로, 하기 전에 운영진(사이트에 적힌 운영 연락 주소)에게 덤프 · 허락을 묻는다.** 이건 사람이 할 일이다.
- **이용약관 [원문]** : 자동 수집을 막는 조항은 없다. 13조 6항 「기술적인 방법으로 위키의 정상적인 운영이나 다른 사람의 위키 이용을 방해한 경우」 회원 자격을 제한할 수 있다 — 느린 요청이면 걸리지 않는다.
- **속도 제한 [원문 API]** : 비로그인 `ratelimits` 에 읽기 제한은 없다(편집 · 올리기 · 지우기 등만). 이번에 1초 간격 245 요청 · 50판 묶음 요청에서 **오류 0 · 막힘 0** [실물].
- **덤프 [원문]** : 공개 덤프는 못 찾았다(「리브레 위키:덤프」 · 「데이터베이스 덤프」 404 · 웹 검색 0건). `특수:내보내기`(문서 하나의 전체 이력 XML)는 열려 있다 — `/wiki/` 아래라 robots 상으로도 열려 있으나, 6만 문서를 하나씩 내보내는 건 결국 전량 긁기라 위와 같이 먼저 묻는다.

### 2-3. 한국어 위키백과는 어땠나

- 이름만 있는 User-Agent(연락처 없음)로 1초 간격으로 보내자 **20 요청 만에 429(너무 많은 요청)** 가 났다 [실물]. 위키미디어 규칙상 연락처 없는 클라이언트는 **분당 10 요청**이다 [원문 mediawiki.org Rate limits].
- 우회하지 않고 **7초 간격으로 늦추고, 요청 하나로 판 50개를 받는 묶음 방식**으로 바꿔 42 요청에 끝냈다. 대량은 앞선 조사대로 **덤프**로 간다.

## 3. 받는 법 (이번 표본)

- **고르기 — 편집마다 같은 확률.** 1 ~ 최대 판 번호(리브레 2,023,803 · 위키백과 42,651,288)에서 판 번호를 무작위로 50개 뽑는다. 문서를 먼저 고르면 이력이 긴 문서가 덜 뽑혀 「전체 편집 × 비율」 셈이 틀어진다.
- **요청 1** : `action=query&prop=revisions&revids=<50개>&rvprop=ids|user|timestamp|comment|size` → 없는 판 · 본문 아닌 이름공간 · 문서 만들기를 가른다.
- **요청 2** : 본문 편집의 「새 판 + 앞 판」 본문을 50판씩 받는다(`rvprop=ids|content&rvslots=main`).
- **비교(로컬)** : 줄 단위로 비교 → 위키 문법(틀 · 각주 · 링크 · 굵게)을 벗김 → `. ! ?` 로 문장을 나눔 → **바뀐 문장이 딱 하나이고 덧붙인 · 지운 문장이 없는 편집**만 「한 문장 고침」. 두 문장 다 15자 이상, 글자 닮음 ≥ .6(`mine_archive.py revision` 과 같은 값).
- **User-Agent** `…JudgeModel-research/0.1`(연락처 없음). 리브레 1초 · 위키백과 7초 간격.

## 9. 나무위키 자리를 메우나 · 섞는 비율

- **문체는 메운다.** 서술 · 설명체가 58% 로 위키백과(5%)와 딴판이고, 게임 · 서브컬처 문서가 절반이다. 「~인데 ~해서」 꼴 긴 설명문은 위키백과에서 거의 안 나온다.
- **양은 못 메운다.** b 수천이 상한이고, b 밀도가 위키백과의 4분의 1이다. 나무위키(편집 수억)를 대신할 크기가 아니다.
- **제안** :
  - **학습 b 쌍 : 위키백과 80 : 리브레 20.** 리브레 b 를 거의 다 쓰는 비율이다(위키백과 b 를 2만쯤 쓰면 리브레 5천). 리브레 a · 버림 쌍은 「낱말 다듬기는 b 가 아니다」를 가르치는 **a 칸 대조 쌍**으로 쓸 만하다(47%).
  - **평가 셋(dev · blind) 한국어 b : 리브레 20 ~ 30%.** 문체별 성능을 따로 셀 수 있게 원천 칸을 단다. 실사용(팀 기억 저장소 글)은 짧은 설명체라 리브레 몫이 위키백과보다 가깝다.
  - 위키백과를 아직 안 받았다면 **리브레 먼저 돌려 파이프라인을 다듬고**(작아서 빨리 돈다) 위키백과 덤프로 넘어가는 순서가 낫다.

## 12. 못 한 것

- **공식 판정 없음** — 231 + 62쌍 분류는 내 손 한 판이다. 특히 b?(2) · b+(3) · 「a 대 d」 경계는 갈릴 수 있다.
- **xlm-r 토큰 길이** — 글자 수로 대신했다.
- 전량 받기에 드는 **데이터 크기** — 판 크기를 안 남겼다.
- **운영진 답** — 덤프가 비공개로라도 있는지 모른다.
- `Wikichan>` 이력의 원 위키 라이선스 — 리브레 안 「위키챈」 문서 · 웹 검색으로 못 찾았다.
- 위키백과 표본이 62쌍뿐이라 b 19% 의 범위가 넓다. 앞선 조사 계획대로 덤프 조각 하나로 다시 잰다.
- 「서술체 · 도메인」 분류는 문장 하나 · 문서 제목만 보고 내가 붙였다. 정해진 잣대표가 없다.
