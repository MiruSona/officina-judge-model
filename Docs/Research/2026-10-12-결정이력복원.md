## 결론 먼저

1. **출발점은 「게임 서버가 떠 있어도 도는 가벼운 mem 판정기」였다.** 자는 mem 기억 쌍으로 만든 셋(K 48 · game90 · blind v2)이었고, **10-09 에 이미 통과했다**(blind v2 정확도 0.892 · 반대 재현 0.882). 그 뒤 일은 모두 「통과한 뒤에 더 얹은 것」이다.
2. **d 를 연 까닭으로 문서에 적힌 것은 「b 를 d 로 푼다」가 아니라 「merge(합치기) 큐 2차 거름 + 양방향 접기」다.** 「b 를 d 로 푼다」는 논리는 설계 어디에도 가설로 적혀 있지 않다. 비슷한 숫자는 **d 를 이미 하기로 한 뒤** 측정 결과에서만 나온다(옛 3칸 모델이 d 쌍 103 중 42 를 b 로 봄 · blind v4 에서 d 쌍 55 중 11 을 b 로 봄). 사용자가 기억하는 연결은 「d 쌍을 b 로 잘못 보는 것(거짓 반대)을 d 칸이 받아 준다」로 읽을 수 있고, 이 뜻이라면 맞는 방향이었지만 **실사용(mem 모순 큐)에서 그 손해를 잰 기록은 없다.**
3. **같은 일이 이름만 바꿔 되풀이됐다.** 판정 셋을 3일 동안 **여섯 번** 새로 얼렸고, 합성 자료 넣기는 **여섯 번**, b 가중치는 **세 번**, 「d 를 더하니 b 가 깎임」은 **세 번** 났다. 셋이 바뀔 때마다 자도 바뀌어 앞 판 숫자와 이어 볼 수 없었다.
4. **10-11 「공개 범용 모델」 결정(mem `20261011-d30c9754`)이 자를 바꿨다.** 지금 릴리스 자 blind-g1 의 b 66쌍 중 **50쌍(76%)이 VitaminC(영어 위키 사실 고침)** 이고 mem 은 3쌍이다. mem 셋에서 3칸 모델의 b 재현은 처음부터 0.87~0.94 였다. 지금 v1.2 가 쫓는 「b 80%」는 mem 일이 아니라 VitaminC 일이다.
5. **권고 : 길 A — 실사용 자부터 세운다(반나절~1일).** mem 이 실제로 묻는 세 자리(retain 지지 관문 · 모순 큐 C19 · merge)에서 v1.0.0 과 v1.1.0 이 내는 손해를 잰다. 그 숫자를 보고 「범용 v1.2 를 계속할지(길 B)」 「d 를 모델 밖으로 뺄지(길 C)」를 고른다.

### 2-1. 「b 를 d 로 푼다」는 어디에 있나

| 자리 | 적힌 것 | 성격 |
| --- | --- | --- |
| 할 일 `20261010-a364fc83` (d 의 처음) | 「합치기(C20) · 덮임(C17) 후보를 낱말 문턱으로만 고르고 맞다 비율 30~40%. 규칙으로 못 가르는 짝을 모델이 맡게」 | **merge 이유. b 언급 없음** |
| 넷 설계 4-2 · 8절 | 「넷 칸에서 반대가 d 로 새는지 본다」 · 위험 「넷 칸에서 반대 재현이 떨어짐」 | **b 는 지켜야 할 것(위험)** |
| R2 기준선 (10-11 새벽, 측정 뒤) | 「옛 모델이 틀리는 곳은 거의 정답 d 다. d 103 중 c 47 · **b 42** · a 14. 관련 있지만 다른 말을 반대로 읽는다」 | **사후 관찰.** 단 이 견줌은 셋 오염으로 무효 판정(R3 1절) |
| 1차 d 조사 전제 (10-11 오전) | blind v4 v1.0.0 : 틀린 55 중 31 이 d 쌍(**지지로 20 · 반대로 11**) → 「모델의 진짜 약점은 d 쌍이다」 | **사후 관찰.** d 쌍이 a 로 새는 것이 b 로 새는 것의 두 배 |

- [추론] 그래서 「d 가 b 를 푼다」의 뜻은 **「d 성격 쌍을 반대로 잘못 보는 것(거짓 반대 = b 정밀)」을 d 칸이 받아 준다**로 읽어야 맞다. 이 뜻이라면 넷 칸 r2-02 에서 d→b 는 8/103 으로 줄었다(R2 혼동표). 하지만 **mem 의 모순 큐(C19)에서 거짓 반대가 얼마나 나는지는 한 번도 안 쟀다**(3칸 서버로 C19 가 scope 하나에서 상한 20 을 다 채운 기록만 있다, `AIMemoryTool/Docs/Design/2026-10-10-기억점검정리설계.md` 「큐」 절).
- 지금 v1.2 가 쫓는 b 는 반대 방향이다 — **b 재현**(진짜 반대를 놓침)이고, 놓친 b 는 d 보다 **a 로 더 샌다**(dev-cmp 38 중 a 22 · d 14, `2026-10-11-v1.2-b진단.md` 1-1). d 칸은 이 문제를 못 푼다.

## 6. 판단 — 목표에서 다시 출발한다면

| | 길 A — 실사용 자부터 | 길 B — 범용 v1.2 계속 | 길 C — 3칸 고정 · d 는 모델 밖 |
| --- | --- | --- | --- |
| 무엇 | mem 이 실제로 묻는 세 자리에서 표본을 뽑아 v1.0.0 · v1.1.0 을 견준다 : ① retain 지지 관문(확신 거짓 지지) ② 모순 큐 C19(거짓 반대 = d 성격 쌍을 b 로) ③ merge 놓침. 각 50쌍 안팎 · Opus 둘 + 사람 표본 | b 진단 권고 ①~③(dev b 300 · v5 한정어 규칙 · VitaminC 대조쌍 + 한국어 고침 b) + d 진단 ②(Ⅱ 를 b 지킴과 함께) | 제품을 3칸으로 굳힌다(v1.1.0 `--compat3` 그대로). merge 는 임베딩 문턱 설계를 꺼내 쓰고, 거짓 반대 · 수 · 한정어는 규칙 층과 SemIf 넘기기로 잡는다 |
| 얻는 것 | **「b · d 오판이 mem 에서 얼마나 손해인가」 숫자.** 이것이 B 와 C 중 무엇이 값어치 있는지 가른다. v1.1.0 교체가 mem 을 해쳤는지도 확인 | 공개 카드의 b · d 숫자. 범용 모델로서의 완성도 | 학습 판 없이 mem 쪽 문제를 바로 줄임. 되풀이 고리에서 나옴 |
| 비용 | 반나절 ~ 1일 · 사람 1시간 안팎 · 학습 0 | 2~4일 · 학습 수십 판 · 셋 하나 더(v1.2 blind) | 1~2일(임베딩 문턱 · 규칙 꼴 · SemIf 넘김 시험) |
| 버리는 것 | 며칠 동안 v1.2 진척 | mem 실사용과의 연결(자가 VitaminC 중심). 「d 더하면 b 깎임」 네 번째 위험 | 4칸 공개 기능(이미 만든 코드는 남음) · 범용 d |

**권고 : 길 A 를 먼저 하고, 그 숫자로 B · C 를 고른다.** 까닭 셋.

1. 지금까지의 미달 판정은 다 「바뀐 자」 위에서 나왔다. 원래 목표(mem 판정)의 자로 v1.1.0 을 잰 적이 없다. 자를 먼저 고정하지 않으면 B 를 해도 또 「새 셋 · 새 미달」이 된다(3절 되풀이 1번).
2. A 는 싸다(학습 0). 그리고 「d 가 b(거짓 반대)를 푼다」는 사용자의 원래 직관을 **처음으로 실사용에서 확인**하는 일이다.
3. [추론] 예상 : retain 관문 거짓 지지가 0 근처면(K 48 기록) mem 쪽은 이미 쓸 만하고, 손해는 C19 거짓 반대와 merge 놓침에 몰릴 것이다. 그러면 C(규칙 · 임베딩 · SemIf)로 싸게 막고, 범용 v1.2(B)는 「공개 제품」 일로 따로 떼어 서두르지 않는 것이 맞다.
