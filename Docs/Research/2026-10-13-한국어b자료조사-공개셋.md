## 1. 결론 먼저

**한국어로 「사람이 만든 claim–evidence 반대 쌍」을 크게 담은 공개 셋은 없다.** 한국어 FEVER · VitaminC · ANLI · WANLI 의 사람 작성판, 한국어 개정(revision) 기반 셋, 한국어 요약 사실 일치 셋 모두 못 찾았다. 대신 **다른 목적으로 만든 셋 안에 b 로 바꿀 수 있는 짝이 들어 있는 것**이 몇 있다. 셋 다 그대로는 못 쓰고 「평서문으로 바꾸기 + v6 다시 판정」이 필요하다.

## 2. 후보별 설명

### 2-1. KoBEST BoolQ — 1순위

- 출처 : <https://huggingface.co/datasets/skt/kobest_v1> · 논문 <https://arxiv.org/abs/2204.04541> (COLING 2022). 라이선스 카드에 **cc-by-sa-4.0** [원문]. 논문은 「자유롭게 쓰고 고치고 다시 배포해도 된다」고 적었다 [원문].
- 크기 : train 3,665 · dev 700 · test 1,404 = 5,769, test 라벨도 공개 [원문]. 미리보기 101줄에서 참 51 · 거짓 50 이라 거짓은 절반쯤 [원문 요약].
- 만든 법 : 한국어 위키 문단을 고르고, 한국어 모국어 주석자가 문단만 보고 답할 수 있는 예/아니오 문장을 썼다 [원문]. **번역이 아니다.**
- b 로 쓰는 법 : 문단 = 근거, 「거짓」 문장 = 주장. 질문 칸이 이미 평서문인 줄이 많다 — 「타이완 요리는 다른 지역의 중국 요리처럼 기름을 많이 사용하는 것이다」(라벨 0, 문단은 「담백하다」) 는 그대로 b 다 [행]. 「연하곤란이 생기면 식도가 막히나요?」(라벨 0) 처럼 물음꼴이면 평서문으로 바꿔야 하고, 이 줄은 문단이 「식도가 막혀 연하곤란이 생긴다」라 **원인 · 결과 뒤집기**여서 b 인지 d 인지 갈린다 [행].
- 어림 : 거짓 약 2,900 중 v6 b 로 남는 비율 50~70% → 1,500~2,000 [어림]. 참(1) 줄은 a 로 덤이 된다.
- 함정 : ① 「아니오」가 추론으로만 나오는 줄은 d 로 갈 수 있다. ② 위키 문단이라 KLUE-MRC · 우리 평가 셋과 **문단이 겹칠 수 있다** — `blind-g2.forbid.json` 과 글 겹침 검사가 필요하다. ③ 문장 길이 위키 문단 1~5문장, 기술 · 기획 메모와는 말투가 멀다.
- 공수 어림 : 받기 10분 · 물음꼴만 평서문으로(LLM, 많아야 수백 줄) 1시간 · v6 두 판 판정 3~4시간 · 겹침 검사 30분 → **반나절~하루**.

### 2-2. Korean-Hallucination-Bench (ginigen) — 2순위

- 출처 : <https://huggingface.co/datasets/ginigen/Korean-Hallucination-Bench>. 카드에 **Apache 2.0** [원문].
- 크기 · 꼴 : 10,170 줄, 4지선다. 칸은 `question` · `options` · `answer_index` · `explanation` · `hallucination_type` [원문]. 환각 종류 10가지(수치 · 날짜 오류, 조항 왜곡, 없는 출처 등), 영역 다섯(법 · 특허 · 행정 · 의료 · 금융) [원문].
- 만든 법 : 대형 언어 모델이 문제와 보기를 만들고, 다른 모델이 법령에 비춰 정답을 고치고 애매한 문항은 버렸다 [원문]. 사람 작성이 아니다.
- b 로 쓰는 법 : 「특허권 존속기간은 설정등록일로부터 몇 년인가?」 + 정답 「20 년」 / 틀린 보기 「25 년」 [행] → 「…20년이다」 ↔ 「…25년이다」. 값 하나 자리라 v6 ③ 으로 b 다. 정답이 실제로 맞는지는 b 판정과 상관없다(둘이 함께 참일 수 없으면 b).
- 어림 : 한 문항에 한 짝만 쓰면 약 10,000 후보, 보기가 「3 년 이내, 출원취하로 봄」처럼 두 값이 섞인 것도 있어 b 남김 50~70% → 5,000~7,000 [어림].
- 함정 : ① 보기가 짧은 구절이라 질문과 합쳐 평서문을 **만들어야** 한다(LLM 변환 = ③ 갈래와 겹치는 일). ② 틀린 보기가 「더 넓은 말」이면 d(예: 「3개월 이내」 ↔ 「6개월 이내」는 6개월 이내가 참일 수도 → 다시 판정). ③ 모델이 쓴 매끈한 말투 — R3 때처럼 합성 말투 지름길이 생길 수 있다. ④ 카드가 해설이 흔들리는 줄을 스스로 경고한다 [원문]. ⑤ 근거와 주장이 둘 다 한 문장이라 「긴 근거 속 한 자리」 꼴은 못 가르친다.
- 공수 어림 : 변환 2~3시간(로컬 판 가능) · 다시 판정 3~4시간 → **하루**.

### 2-3. PAWS-X 한국어 — 3순위

- 출처 : <https://github.com/google-research-datasets/paws/tree/master/pawsx> · HF `google-research-datasets/paws-x` (config `ko`). LICENSE 원문 「The dataset may be freely used for any purpose」 [원문].
- 크기 : ko train 49,401(기계번역) · dev 1,965 · test 1,972(사람 번역) [원문]. train 라벨 0(패러프레이즈 아님) 27,572 · 1 21,829 [셈]. dev · test 의 0 은 같은 비율이면 약 2,170 [어림].
- b 로 쓰는 법 : PAWS 는 낱말 자리를 바꿔 뜻을 바꾼 짝이다. 「타바시 강은 류드라 강의 지류이다」 ↔ 「류드라 강은 타바시 강의 지류이다」(0) [행] 는 b. 「싱글A Kane County · AA Portland」 ↔ 「A레벨 Portland · AA Kane County」(0) [행] 도 b.
- 함정 : ① 라벨 0 이 다 b 는 아니다 — 「1938년 인류학자가 되었고 현장 작업을 이끌었다」 ↔ 「…현장 연구를 수행했다」(0) [행] 는 번역이 차이를 지워 a 로 읽힌다. ② train 은 기계번역이라 이름 표기가 영문 · 한글로 섞인다 [행]. ③ 위키 인물 · 지명 문장이라 말투가 멀다. b 남김 30~50% [어림].
- 쓰는 자리 : 학습 몫(많고 잡음 큼). 사람 번역 dev · test 는 감사용.
- 공수 어림 : 다시 판정 양이 커서(쓰는 만큼) **하루 이상**. 2,000~3,000줄만 뽑아 쓰면 하루.

### 2-4. KorAdvMRS (카카오엔터프라이즈, EMNLP 2021)

- 출처 : <https://github.com/kakaoenterprise/KorAdvMRSTestData>, **Apache-2.0** [원문].
- 크기 · 꼴 : 시험 2,220 건, 각 건 = 대화 맥락 + 맞는 답 1 + 틀린 답 1. 틀린 답 꼴 일곱 : 되풀이 · 부정 · 시제 · 주어목적어 · 낱말 모순 · 의문사 · 주제 [원문]. 꼴별 수는 표 그림이라 못 읽었다.
- b 로 쓰는 법 : 부정 · 시제 · 주어목적어 · 낱말 모순 넷이 b 와 맞닿는다. 일곱 꼴이 고르면 약 1,200 [어림]. 예시 「회사 갔다가 이제 집 왔어요」 ↔ 「회사 안 갔어?」 [원문] 처럼 **틀린 답이 물음꼴**인 줄이 많아 평서문 바꾸기가 필요하다.
- 함정 : 일상 대화 말투 · 맥락이 여러 줄이라 근거가 흩어진다. 원래 시험 셋이라 양이 작다 → 평가 · 감사 보조로.

### 2-5. KoBEST SentiNeg

- 같은 `skt/kobest_v1` 안 [원문]. test 397 문장은 train 문장에 부정 표현을 넣거나 빼고 반대말로 바꿔 극성을 뒤집은 것이고, 원문 397 은 `test_originated` 로 따로 있다 [원문 · 요약].
- b 로 쓰는 법 : 원문 ↔ 뒤집은 문장을 그대로 짝지으면 거의 b. 397 쌍뿐이고 상품 후기 말투(「맛있다 ↔ 맛있지 않다」꼴)라 도메인이 멀다. 짝 맞춤이 줄 번호로 되는지는 받아 봐야 안다.

### 2-6. multilingual-NLI-26lang-2mil7 의 ko 칸

- 출처 : <https://huggingface.co/datasets/MoritzLaurer/multilingual-NLI-26lang-2mil7>. ko 파일 다섯 : `ko_mnli` · `ko_fever` · `ko_anli` · `ko_wanli` · `ko_ling`, 각 25,000(ling 5,000) [원문]. 번역기는 ko 에 m2m100_1.2B [원문].
- 라이선스 : 카드에 라이선스 칸이 **없다** [원문]. 원천별로 갈린다 — WANLI CC BY 4.0 [원문] · ANLI **CC BY-NC 4.0 → 못 씀** [원문] · FEVER CC BY-SA 3.0 (지난 조사) · MNLI 는 KorNLI 와 원천 같음 · LingNLI 못 봄.
- 어림 : WANLI 모순 비율은 낮고(약 15% [기억]) FEVER-NLI 반박은 약 1/3 [기억] → 쓸 수 있는 두 칸에서 모순 5,000~10,000 [어림].
- 함정 : 기계번역 품질(카드도 「NLI 같은 일엔 문제가 될 수 있다」고 적음 [원문]) · 카드 라이선스 빈칸 · KorNLI 와 MNLI 겹침. 영어 원본을 우리가 직접 더 나은 번역기로 옮기는 편이 낫다(③ 갈래 몫).

### 2-7. Poly-FEVER ko

- 출처 : <https://huggingface.co/datasets/HanzhiZhang/Poly-FEVER> · arXiv 2503.16541. 11개 언어로 맞춘 77,973 주장, SUPPORTS 46,808 · REFUTES 31,165, Google 번역 + COMETKiwi 점수 칸 [원문].
- 왜 낮나 : **근거 문장 칸이 없다** [원문]. b 쌍을 만들려면 영어 FEVER 근거를 ID 로 찾아 붙이고 번역해야 한다. 카드 라이선스 칸도 없고 SciFact 몫은 NC 다 [기억]. 쓰더라도 FEVER 몫 REFUTES 만.

### 2-8. 이미 쓴 KorNLI · KLUE-NLI 다시 캐기

- 둘 다 CC BY-SA 4.0 (KorNLI HF 카드 [원문]). 기반 학습에 이미 들어갔다(R0 문서).
- 새 원천은 아니지만, 모순 칸 중 **근거와 주장의 낱말이 많이 겹치고 한 자리(수 · 때 · 이름)만 다른 줄**을 골라내면 v6 ③ 꼴 b 를 수천 줄 얻을 수 있다 [어림]. SNLI 계열 모순은 「같은 장면이라 치고」 만든 것이라 v6 에선 c · d 로 갈리는 줄이 섞인다 [추론] — 다시 판정이 필요하다.

## 5. 못 찾은 것

- **한국어 FEVER · VitaminC · ANLI · WANLI 의 사람 작성판 또는 기계번역판** — HF id 검색(korean-fever · ko-anli · ko-wanli · vitaminc 등) 0건. VitaminC 다국어판은 인도 언어뿐.
- **한국어 개정(revision) 기반 대조쌍 셋** — 없음. ② 갈래 몫.
- **한국어 요약 사실 일치(SummaC · FRANK 꼴) 셋** — 없음. Naver-News-KO 같은 요약 셋은 사실 라벨이 없다 [요약].
- **XNLI · XFEVER · X-FACT 의 ko** — XNLI 에 ko 없음(KorNLI 논문 [요약]), XFEVER 는 es · fr · id · ja · zh 뿐 [요약], X-FACT 는 ko 없음 [기억].
- **KOLIN (한국어 추론 자료, 언어 현상 78 꼴)** — 책 소개만 있고 자료 공개처를 못 찾음 [요약]. 2024 연구과제 「KoLinNLI」도 공개 소식 없음 [요약].
- **Yoon 외 2019 낚시성 헤드라인 셋** — 라이선스를 못 봤고, 본문 문단을 바꿔 넣어 만든 것이라 b 보다 c · d 쪽이다 [요약 · 추론].
- KorAdvMRS 꼴별 수, PAWS-X ko dev · test 라벨 비율, SentiNeg 짝 맞춤 방법 — 받아 봐야 안다.
