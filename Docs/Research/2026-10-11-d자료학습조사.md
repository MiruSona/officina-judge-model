## 전제 (사용자 2026-10-11)

- **JudgeModel 은 공개 범용 판정 모델 제품이다.** AIMemoryTool 전용이 아니다. 다른 툴 · 앞으로 만들 툴 · 게임 저장소도 쓴다. 판본(semver)으로 내고 응답 꼴(칸 수)은 깨지 않는다.
- **NLI 양방향 접기는 완전히 접는다.** d 는 **v1.1 후보**로 둔다. d 정의는 쓰는 쪽과 무관한 말(같은 주제 · 담김도 어긋남도 아님)로 일반화한다.
- **blind v4 를 3칸 v1.0.0 에 한 번 쟀다(10-11 09:03).** 정확도 0.750 으로 미달. 틀린 55쌍 중 31쌍이 d 쌍이다(d 55쌍 중 지지로 20 · 반대로 11). d 를 뺀 165쌍은 0.855. → **모델의 진짜 약점은 d 쌍이다.**
- **범용 기준으로 다시 짓는 층은 둘이다.** ① 자료(학습 쌍 · dev · blind) ② 정의·평가(라벨 지침 · 평가셋 · 성적표). 바탕(xlm-roberta-large + base-2)과 코드는 그대로 둔다. 지금 자료는 입력 꼴(문장 정렬된 두 문장) · 라벨 지침(합치기 큐 기준) · 평가셋 도메인(개발 메모 하나)이 한 손님에 맞춰져 있다.

| 체계 | 칸 | 우리 d 에 해당 | 배울 점 |
| --- | --- | --- | --- |

### 2-2. d 의 범용 정의 (초안)

설계 1절의 정의는 「같은 절에 넣을 글」 · 「merge 큐 문턱」 같은 합치기 큐의 말로 적혀 있다. 쓰는 쪽과 무관한 말로 바꾼다.

| 칸 | 정의 (초안) | 한 줄 시험 |
| --- | --- | --- |
| a 지지 | 근거가 주장의 **어느 한 부분이라도** 맞다고 받친다 | 주장 속 말 중 근거가 「맞다」고 해 주는 것이 하나라도 있나 |
| b 반대 | 근거와 주장의 어느 부분이 **둘 다 참일 수 없다** | 함께 참일 수 없는 말이 하나라도 있나 |
| c 무관 | **다른 대상**을 말한다 | 둘이 같은 사물·사건·기능·규칙·수치 자리를 가리키지 않는다 |
| d 비슷한 계열 | **같은 대상**을 말하지만 근거가 주장의 어느 말도 받치지도 뒤집지도 않는다 | 같은 대상에 대한 글인데 서로 다른 사실을 말한다 |

- 「같은 대상」 = 같은 사물 · 같은 사건 · 같은 기능 · 같은 규칙 · 같은 수치 자리. **같은 큰 분야(같은 툴 · 같은 저장소 · 같은 게임)는 기준이 아니다** — 분야가 같아도 대상이 다르면 c.
- 우선순위는 지금과 같다 : **b > a > d > c.** 칸 차례(a·b·c 그대로, d 넷째)도 그대로라 옛 번호가 안 바뀐다.

### 2-3. 2단 라벨 지침 (초안)

1. **1단 — 같은 대상인가?** 아니면 **c**. 정말 못 고르면 `cd`(학습에서만 합친 칸 손실, 평가셋에는 안 넣음 — 설계 1-1 그대로).
2. **2단 — 같은 대상이면** 위에서부터 먼저 걸리는 칸.
   - 함께 참일 수 없는 말이 하나라도 있다 → **b**
   - 맞다고 받치는 말이 하나라도 있다 → **a**
   - 둘 다 없다 → **d**
3. **2단에서 한 번 더 볼 것** : 같은 사건을 다룬 짝의 약 74% 가 「부분 함의」라는 보고가 있다 [19, 요약]. d 를 붙이기 전에 **숨은 부분 지지**가 없는지 본다.

- **LLM 라벨러를 그대로 믿지 않는다.** 포르투갈어 NLI 재라벨에서 LLM(Sabiá-3)은 전체 일치도는 사람과 비슷했지만 **「맥락은 같은데 뚜렷한 논리 관계가 없는 문장」을 잘못 붙였다** [18, 요약] — 바로 d 다. 측정 조사의 「LLM 라벨러끼리 같이 틀린다 · 합의 추정 90.7% 가 실제 71.0%」와 같은 쪽이다.
- 그래서 d 라벨은 **LLM 둘 합의 + 사람 감사**로 간다. 감사는 갈린 쌍·불확실한 쌍 위주로 고른다(측정 규약 8 「사람 정답셋 100~200」).
- 지금 dev 에도 이 지침을 소급해 d 경계 쌍을 다시 본다 [A 권고 4]. 지침 30분 + 재검 1시간 어림.

| **자료** | 공개 4칸 자료(1-1 의 KLUE-STS · KLUE-NLI neutral 재라벨 · GitBugs 짝, 영어 neutral 겹침 큰 것은 소프트 d [26]) → 우리 실물 + replay | 교사 LLM 이 여러 분야 전제마다 a·b·c·d 가설을 쓰고(특히 **겹침 큰 d**) k회 다시 라벨해 일치만 남김. 목표 수만 쌍 | 지금 자료 그대로 + 겹침 크고 d 인 짝 수백 개 이하 |
| **손실·단계** | CE(label smoothing 0.1) + 선택 SCL [24]. ① 몸통 얼리고 4칸 머리만 1바퀴(LP-FT [22]) ② 공개 4칸 전체 ③ 실물로 낮은 lr | 교사 확률이면 KL, 없으면 일치율을 소프트 라벨로. **0단계 : 교사를 dev 에 돌려 d 재현부터 잰다 — 교사가 학생의 상한** [29] | 편향 모델(겹침 특징 4~5개 작은 분류기)이 확신하는 짝일수록 교사 분포를 평평하게 해 증류(Utama 식 [32]). 운영에선 MaxProb 문턱 아래를 보류로 |
| **비용 [추론]** | 공개 수만 쌍이면 한 판 1~2시간 · 씨앗 3 × 조건 2 면 반나절 | 생성·라벨링이 가장 큼(교사 속도에 달림) · 학습은 A 와 비슷 | 편향 모델 몇 분 · 학습 한 판 20~30분 · 지금 틀에 가장 싸게 끼움 |
| **기대 효과** | 크기 못 찾음. 방향 근거 : 중간 과제 전이 [25][38] · 영 → 한 손실 약 3점 [36] · LP-FT OOD 이득(이미지만) [22] | GNLI TRUE 평균 약 +7%(T5-small) [27] · WANLI HANS +11% [28] · BERT 학생 ≈ 교사(F1 차 0.006) [29] | **HANS 61.1 → 69.1, MNLI 84.3 그대로** [32 표 2] |
| **함정** | 공개 자료 글꼴이 멂. FNC-1 은 라이선스로 못 씀. neutral 을 그대로 c 로 쓰면 d 가 섞임 [17] | 교사가 약하면 차이 0.12 까지(Mistral-7B) [29] · 학생이 교사 잡음에 과적합 [30] · LLM 은 d 에서 틀림(2-3) | 다른 종류 편향엔 일반화 약함 · 「겹침 큰 진짜 지지」 정확도 하락 [33] · 보류는 d 를 맞히진 못함 [39] |

**근거 숫자**

- **한·영 전이** : KorNLI 시험에서 XLM-R large 는 한국어로 배우면 83.41, **영어로만 배우면 80.30** — 약 3점 차 [36 표 5]. 목표 언어 예시를 더하는 효과는 작다 — XNLI 에서 10개 +0.41 · 100개 +1.71 · 1,000개 +2.52 [37]. → 한국어 실물 d 수백 쌍은 「언어 맞추기」보다 **도메인·d 정의 맞추기** 몫이다. 영어 중간 자료를 번역할 필요도 적다 [38].
- **편향 억제** : 「같은 주제 → 지지 확신」은 어휘 겹침에 기대는 HANS 류 버릇이다 [31]. Utama 표 2(MNLI-m / HANS) — 기준 84.3 / 61.1 · PoE 82.8 / 69.2 · learned-mixin 84.0 / 64.9 · **conf-reg 84.3 / 69.1** · reweighting 84.7 / 65.3 [32]. conf-reg 만 원래 정확도를 지키며 겹침 확신을 깎았다.
- **대조쌍** : 우리 R3 의 합성 대조쌍(묻힌 flip · a/d 경계)은 효과가 없었다. 사람이 고친 대조쌍(CAD)도 「고친 축만 배운다 · SNLI 에서 같은 양 일반 자료보다 낫지 않다」로 엇갈린다 [34]. 반면 VitaminC 는 **위키 실제 수정 이력에서 나온 40만+ 다양한 짝**이라 적대 NLI +6 이 났다 [35]. 차이는 **양 · 다양성 · 실물 원천**이다.
- 세 레시피 모두 **씨앗 3개 이상 평균 + 짝 비교**로 견줘야 한다(측정 규약 3·4). 지금 dev 크기로는 3~5%p 아래 차이를 못 가린다.

| 1 | **모델 카드 뼈대** | 무엇을 판정하나 · **라벨 표(번호 · 이름 · 한 줄 정의 · 경계 예 2개, 특히 d ↔ c)** · 언제 쓰고 언제 쓰지 말 것(Out-of-Scope [43]) · 학습 자료와 **자료별 라이선스** · 도메인별 성적표 + 공개 셋 1개 · 알려진 실패(문장 꼴로) · 입력 길이 한계·지연 · 재현 절차 · 판본 기록. 본보기는 zeroshot-v2.0 카드 [40] | 반나절 | — |

| 3 | **피드백 고리** | `POST /report` : 입력 해시 · 호출자 꼬리표(어느 도구) · 모델 판본 · 모델 답 · 사람이 고친 답 · 종류(정해진 값). **원문은 비공개 저장 칸에만**, 공개 저장소엔 해시 · 라벨 · 도메인 · 짧은 요약만 [51]. 맞았다고 확인된 사례 → 회귀 셋, 틀린 사례 → 다음 학습 후보(EPO 꼴 [49]). 최소 꼴은 파일 한 개에 덧붙이기 [50] | 1~2일 | 7 · 8 |
| 4 | **평가 보고 꼴** | 도메인별 표 + 공개 셋 1개 + d 경계 행동 시험(고정 회귀 셋 [52]). 판단용 셋은 판본마다 조금씩 새로 떼고, 한 번 결정에 쓴 셋은 회귀 셋으로 옮긴다 | 반나절 | 7 · 10 |

| **공수 어림 [추론]** | 6~9일 + 학습 판 | 4~5일 [C 어림] | 1.5~2일 |
| **사람 몫** | 정답셋 100~200 라벨(3~6시간) · d 감사 200~300쌍(2~3시간) · 도메인 고르기 | 카드 검토 · 공개 전 검사 2회(사람 읽기 포함) | 감사 200쌍(약 1시간) |
| **끝에 얻는 것** | 범용 d 를 가진 v1.1 과 그걸 재는 자 | 공개 가능한 v1.0.0 제품 꼴 · 여러 손님의 실물 틀린 사례가 쌓이기 시작 | 「공개 자료만으로 d 가 얼마나 서나」 한 줄 답. 단 지금 dev 는 한 도메인이라 범용성은 못 말함 |
| **위험** | 가장 길다 · 실물 d 원천이 여전히 얇다 | d 약점은 그대로 남는다(카드에 밝힘) | 3~5%p 아래면 「판별 불가」로 끝날 공산(측정 조사) |

**권고 : 길 2 를 먼저.** 까닭 셋.
1. 길 1·3 이 다 필요로 하는 것을 길 2 가 만든다. 여러 도메인 실물 d 는 공개 자료로 못 채우고(글꼴이 멂 · FNC-1 은 라이선스로 막힘), 우리 기억 풀도 바닥이다(R3). **쓰는 쪽이 틀린 사례를 보내는 고리**가 유일하게 계속 늘어나는 원천이다.
2. 호환 규칙(`label_set` opt-in)이 먼저 있어야 v1.1 4칸을 응답 꼴을 깨지 않고 낼 수 있다(전제).
3. 측정 규약 3·4·9 와 권고 5 가 겹쳐, 길 2 를 하면 길 1·3 의 자도 같이 생긴다. 길 2 안에 2절 d 정의·2단 지침(반나절)을 끼워 두면 신고 종류 칸에 바로 쓴다.

## 6. 못 찾은 것 · 확인 못 한 것

- 정식 「topic-aware NLI」(네 칸이 우리 d 와 같은) 공개 셋과 그 라벨 일치도.
- KLUE-STS 점수별 분포(1~2점대가 몇 쌍인지).
- FNC-1 · SICK · FEVER · SciTail(충돌) · SO 관계셋 · LinkSO · ADR 셋의 확정 라이선스. AI허브 「학습한 모델 공개」 허용 원문.
- LP-FT 를 NLP **라벨 추가**에 쓴 숫자(원 논문은 이미지뿐). focal · dice · 가중 CE 를 NLI 에서 견준 숫자.
- 새 칸(d)이 영어 → 한국어로 옮겨 가는 정도(3칸 전이 숫자만 있음).
- LLM 교사 → cross-encoder **NLI 4칸** 증류 사례. LLM 으로 「같은 주제·중립」 짝만 따로 만들어 잰 논문.
- 2단 구조가 트랜스포머 cross-encoder 에서 1단 4칸보다 낫다는 최근 근거(FNC-1 옛 특징 모델 1건뿐).
- 같은 이름에서 라벨 수를 늘리며 판본만 올린 공개 사례 · 원문 대신 해시만 공개하는 피드백 사례 · 카드가 잘 된 한국어 NLI 덧학습 모델.
- 세 레시피·다섯 권고·세 길 모두 **우리 자료로 돌려 보지 않았다.** 비용은 모두 어림이다.
