# v1.2 d 진단 — 보정 문제인가, 모델 문제인가 (2026-10-11)

> v1.1.0(`g1-B2-s3`)의 d(비슷한 계열) 미달 셋(d 재현 · 보류 · d 확신 정밀)이 어디서 오는지 가른 조사다.
> 숫자는 **dev-cal(457쌍) · dev-cmp(1,449쌍) 출력으로만** 셈했다. blind-g1 · ood-g1 은 이미 공개된 관문 숫자만 읽었다.
> 실측 로그 · 스크립트(git 밖) : `~/.judgemodel/measure/g1/v12-diag/` (`diag.py` · `diag-1.txt` · `diag-2.txt` · 미니PC `runs/g1-B2-s3/eval-dev-{cal,cmp}/pred.jsonl` 복사본).

## 결론

1. **보정이 아니라 모델이 d 를 못 가른다.** 「온도 2.35 때문에 d 확률이 .67 에서 막힌다」는 겉모습이다. 온도를 빼도(T=1 이면 d 확률 최고 .94) **어떤 점수로 줄을 세워도 d 정밀 .80 을 넘는 자리가 없다.** 모델이 「가장 d 같다」고 본 위 5쌍도 정답 d 는 3쌍(60%)뿐이다.
2. **d 재현 .46 은 온도 · 문턱과 아예 무관하다.** 관문의 d 재현은 「최고 칸이 d 인가」(argmax)로 센다. 한 값 온도는 최고 칸을 바꾸지 못한다. 보정을 어떻게 고쳐도 d 재현은 그대로다.
3. **칸별 편향 · 칸별 온도로 최고 칸을 옮기면** d 재현은 올릴 수 있지만 a · c 를 그만큼 빼앗는다. d 재현 .83 을 만들면 a .48 · c .55 · d 정밀 .41 이 된다. **보정만으로 「모든 칸 80%」는 닿지 않는다.**
4. **보류 44%(dev-cmp)의 56% 는 「d 라고 답했지만 확신 못 한」 쌍이다.** d 를 최고 칸이면 확신으로 치면 보류는 .21 로 떨어지지만, 그 확신 d 의 정밀은 .47 이다. 반은 틀린 답을 확신으로 내보내는 셈이라 받아들일 수 없다.
5. **d 를 가르는 힘을 키운 유일한 실측은 B1(Ⅱ 공개 원천 4,813쌍)이다.** d 재현 .43 → .70, d 확신 문턱을 다섯 판 다 찾음(정밀 .78~.92 · 확신 38~86개). 같은 calibrate 규칙에서 문턱이 잡혔다. 즉 **모델이 d 를 가르면 지금 보정 규칙으로도 문턱이 잡힌다.**

**권고 : v1.2 의 d 는 자료로 푼다 — Ⅱ 를 다시 넣되 b 지킴을 같이 묶는 판(아래 4절 후보 ②).** 보정 고치기는 보류 몫을 다듬는 곁가지로만 쓴다.

## 1. 보정 구조 (코드 확인)

`train/calibrate.py` 를 읽고, dev-cal 출력으로 다시 돌려 `calibration.json` 과 같은 값(T 2.35 · .83 / .50 / .99 · dev 보류 .4792)이 나오는 것을 확인했다.

| 무엇 | 지금 규칙 |
| --- | --- |
| 온도 | **한 값(scalar)** 하나를 네 칸에 다 건다. 0.50~3.00 격자에서 dev-cal NLL 최소 |
| `nli_sure_support` | .50~.99 중 확신 거짓 지지 ≤ 지지 아닌 쌍 × 1% 인 가장 작은 값 |
| `nli_sure` (b · c) | 확신 b · c 정확도 ≥ .90 인 가장 작은 값. 못 찾으면 .99 → 보류 30% 를 넘으면 이것만 내린다 |
| `nli_sure_related` (d) | 확신 d 정밀 ≥ .80 인 가장 작은 값. **못 찾으면 .99 로 두고 내리지 않는다** |
| Go 기본 선 | 최고 확률 < .40 이거나 1 · 2위 차 < .01 이면 무조건 보류 |

- d 문턱이 안 잡히는 까닭 : 문턱 격자는 .50 부터인데, dev-cal 에서 **최고 칸이 d 인 106쌍의 정밀이 .37 이고 문턱을 올려도 오히려 내려간다**(.50 이상 .36 · .55 이상 .29 · .60 이상 .27). 「정밀 ≥ .80」 을 만족하는 문턱이 0~.99 어디에도 없다.
- 덤으로 `nli_sure` 도 못 찾았다(확신 b · c 정확도 .77 < .90). 그래서 .50 까지 내려갔다. 보류를 키우는 두 번째 갈래다.

### 순위 상한 — 보정과 무관한 「가를 수 있는 힘」

점수 = 「d 로짓 − 나머지 셋 중 최대 로짓」으로 줄을 세웠다. 보정(온도 · 편향 · 문턱)은 이 순서를 거의 못 바꾸므로, 여기서 안 되면 보정으로도 안 된다.

| | dev-cal | dev-cmp |
| --- | --- | --- |
| d 대 나머지 AUC | .680 | .745 |
| d 대 a / b / c AUC | .665 / .725 / .676 | .726 / .848 / .732 |
| 정밀 ≥ .80 에서 d 재현 최대 | **0** | **0** |
| 정밀 ≥ .70 에서 d 재현 최대 | 0 | 0 |
| d 재현 .80 일 때 정밀 최대 | .32 | .43 |
| 위 5 · 10 · 30 · 100쌍 정밀 | .60 · .40 · .30 · .37 | .60 · .40 · .43 · .50 |

- **보정만으로 닿는 상한** : d 확신 정밀 ≥ .80 은 재현 0 에서도 못 닿는다. d 재현을 .80 으로 끌면 정밀은 많아야 .43 이다.
- 즉 **d 를 a · c 와 가르는 힘(AUC .73)이 모자란 것이 뿌리**다. 보정은 이 힘을 늘리지 못한다.
- 모델이 가장 d 같다고 본 30쌍 중 11쌍이 정답 c 다. d / c 경계의 라벨 흔들림도 섞였을 수 있다(사람 감사는 아직 없음 — 4절 후보 ⑤).
