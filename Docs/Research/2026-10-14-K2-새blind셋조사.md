# K2 판 새 blind 셋(blind-g4) 조사 (2026-10-14)

- 작성일 2026-10-14 · K2 소단계 2. 같은 시각 다른 갈래가 「ko c 진단」을 쓴다 — c 자료 분석은 그쪽 몫이라 여기서는 c 의 **수와 자리**만 다룬다.
- 왜 : K 판 blind-g3 관문에서 미달 셋(en b · a · c 의 「v1.1.0 대비 같은 쌍 차 95% 아래끝 ≥ −.03」). blind-g3 는 한 번 쟀으니 쓴 셋이고(mem `20261014-52e65d46`), 다음 출시 판은 새 셋이 든다. 자(−.03)는 그대로다.
- 표시 : **[원문]** = 파일 · 결과를 직접 열어 본 값 · **[셈]** = 이번에 스크래치 스크립트로 직접 센 값(읽기만) · **[어림]** = 이 문서가 짐작한 수.
- 셈 스크립트 · 출력은 스크래치에만 있다(`g4size.py` · `g4pool.py` · `g4ko.py` · `g4wt.py`). 셋 · 코드 · 설정은 안 고쳤고 아무것도 내려받지 않았다.

## 0. 결론

1. **en b 가 미달한 진짜 까닭은 「묶음 수」보다 「묶음당 쌍 수」다.** VitaminC 는 한 쪽(page)에서 4쌍까지 뽑아(묶음당 2.53쌍) 설계 효과(분산 부풀림)가 1.62 다. 한국어 b(묶음당 1.10쌍)는 1.01 이다 [셈]. 같은 쌍 수라도 **묶음당 2쌍 상한**으로 뽑으면 구간이 좁아진다.
2. **필요한 묶음 수** (K 와 v1.1.0 의 엇갈림이 그대로라는 가정 · 1절 표) [셈 → 어림] :
   - en b : 평균 +.03 일 때 반반 통과 **약 106**, 80% 통과 **약 216** (지금 79). 묶음당 2쌍이면 **96 / 196**.
   - a(쌍 전체) : +.03 이면 반반 192 · 80% 392 (지금 232). K 의 실제 효과 +.017 이면 반반 통과에 **약 313**.
   - c(쌍 전체) : +.03 이면 지금 124 로 충분(반반 68). 하지만 c 는 평균이 실제로 내렸다(−.044). **K2 가 c 를 0 까지 되돌려도 −.03 자를 반반으로 넘으려면 약 272, 80% 면 약 555.**
   - d · ko b · b 전체 · acc3 는 지금 수로 충분하다(효과가 커서).
3. **원천은 넉넉하다.** g1 · g2 · g3 금지를 다 뺀 뒤 [셈] :
   - VitaminC heldout : b **6,876쌍 · 2,460 쪽** · a 11,919 · 4,697 쪽 · 같은 쪽 c 10,548 · 2,745 쪽.
   - 한국어 : 위키 평가 몫 판정 전 b 후보 **409 · 277 문서** · BoolQ 판정 끝 안 쓴 b **84**(판정 공수 0) + 판정 전 약 1,640 · KLUE 판정 끝 안 쓴 30(b 19 · a 11) + heldout 판정 전 약 1,150.
   - 모자란 칸은 **한국어 d** 하나다(위키 평가 d 54 를 g3 가 다 썼다). d 자는 쌍 전체로 재고 효과가 커서 관문에는 안 걸린다.
4. **권장은 안 2(약 1,800쌍)** — en b 220 쪽(쪽당 2쌍) · a 400 묶음 · c 280 묶음. K 같은 효과면 en b 는 +.010, a 는 +.012, c 는 거의 0 이상이면 아래끝을 넘는다. 새 판정 약 1,700쌍 × 판정자 2 [어림].
5. **규약 g4 에서 바뀔 것** : 셋 이름 · 해시 · 금지 목록, VitaminC 쪽당 상한 4 → 2, 「묶음 최소 수」 칸 새로(조립 검사가 막음), 짝 비교의 기준 판(base). 자(−.03 · > 0 · −.02)와 ref(v1.1.0)는 그대로.

## 1. 필요한 크기 (물음 1)

### 1-1. 셈 방법

- 관문의 구간은 `compare.cluster_bootstrap` 이다 [원문] — 묶음(`group`)을 복원 뽑기 1만 번, 쌍마다 (K 맞힘 − ref 맞힘)의 비율 차. 릴리스 판은 씨앗 하나라 쌍마다 차가 −1 · 0 · +1 이다.
- 붓스트랩 반폭은 묶음 수 G 에 대해 **1/√G 로 준다**(묶음 꼴이 같을 때). 그래서 `반폭(G') = 반폭(G) × √(G / G')` 로 늘려 셌다. 확인으로 있는 묶음을 G 의 2배 · 3배로 복원 뽑아 실제 붓스트랩을 돌려 보니 en b 는 .0490 · .0421 (어림 .0491 · .0401), a 는 .0358 · .0298 (어림 .0386 · .0315) 로 맞았다 [셈].
- 통과 조건 : 관측 차 − 반폭 ≥ −.03.
  - 「반반」 = 참 효과 그대로 관측될 때 넘는 크기 → 반폭 ≤ 효과 + .03.
  - 「80%」 = 관측이 흔들려도 열에 여덟은 넘는 크기 → (1.96 + 0.84) × se ≤ 효과 + .03.
- **가정** : K2 와 v1.1.0 이 쌍마다 엇갈리는 비율이 K 와 v1.1.0 만큼이다. 다른 모델 짝이면 수가 달라진다 [어림].

[어림] 판정자 둘을 그대로 쓰고 묶음 하나 100줄 · 서브에이전트 하나 묶음 2개 꼴(g3 와 같음)로 늘렸다. 토큰은 g3 기록에 없어 못 어림했다.

### 3-4. 도구 손질 (코드는 안 고쳤다 — 다음 판 몫)

- `make_sets.reserve_g3` 는 g3 에 박혀 있다(`G3_SETS` · `G3_B_TARGET` · `G3_GROUP_CAP` · 입력 파일 이름). 다시 돌리면 `build/g3/reserve/` 를 통째로 덮는다(sets-g3 9-4 주의). **g4 는 `build/g4/` 에 따로 쓰는 `reserve-g4`(또는 판 이름 인자)** 가 든다.
- 금지 클래스는 `G3Forbid` 를 이어 `G4Forbid` 로 — g3 세 셋 · train-g3-ko · `blind-g3.forbid.json` · reserve-g3 예약 · 학습 층 후보를 더한다(이번 셈 스크립트가 한 것과 같다).
- `add_g3_ac.py`(git 밖) · `assemble_g3.py` 도 g4 판이 든다. `check_g3` 27칸에 「g3 셋 겹침」 칸을 더한다.
- VitaminC 판정 대상은 b 후보만이 아니라 a(같은 쪽) · c 도 같이 묶는다(g3 10절 꼴 그대로).

## 4. 규약 protocol-g4 에서 달라질 것 (물음 4)

| 칸 | g3 | g4 (제안) |
| --- | --- | --- |
| `name` · `hash_rule` | protocol-g3 | protocol-g4. g3 는 그대로 둔다 |
| `release_gate.set` · `sets.blind-*` | blind-g3 b30e64b7… | **blind-g4** (얼린 해시) |
| `release_gate.ref_model` | v1.1.0 (runs/g1-B2-s3, 14d0d520) | **그대로 v1.1.0** — 8092 가 아직 v1.1.0 이고 K 는 안 냈다 |
| `release_gate` 자 (vs_ref · b_recall_min · 보류 · 거짓 지지 · p95) | 지금 값 | **그대로** (사용자 결정 「잰 뒤 기준 재검토 안 함」) |
| `compare_on` · `calibrate_on` | dev-cmp-g3 · dev-cal-g3 | K2 가 dev 셋에 한국어 c 를 더하지 않으면 그대로. 더하면 dev-cmp-g4 · dev-cal-g4 (c 진단 갈래 · 설계가 정함) |
| `pair_gate.base` · `new` | B2 → K | **K → K2** 또는 B2 → K2 — 설계가 정한다. K 를 기준으로 하면 「ko b 를 지키며 c 를 되돌렸나」를 바로 잰다 |
| `pair_gate.target` | ko b +.05 | K2 의 목표 자(ko c 등)로 — 설계 몫 |
| `train_sets` | train-g3-ko | train-g3-ko + 새 c 층 해시 |
| **새 칸 `min_groups`** | 없음 | 예 : `{"b@en": 200, "a": 380, "c": 260, "b@ko": 220}` (안 2 기준). **조립 검사(`assemble_g4 check`)가 모자라면 exit 1** 로 막는다. gates 는 안 읽는다 |
| **새 칸 `group_cap`** | 코드 상수 (VitaminC 4) | `{"vitaminc": 2}` 를 규약에 적어 둔다 — 설계 효과를 줄인 근거 |
| `bootstrap` | 1만 번 · rng 20261011 · 묶음 | 그대로 |
| 금지 목록 노트 | blind-g3.forbid.json | blind-g3 + blind-g4.forbid.json |

- `min_groups` 를 「잰 뒤」가 아니라 **셋을 얼리기 전**에 박는 것이 핵심이다. 이번처럼 셋 꼴이 정해진 뒤 구간이 넓어서 떨어지는 일을 미리 막는다.
- `gates.py` · `compare.py` 는 손대지 않아도 된다(자 꼴이 g3 와 같다). `min_groups` 는 조립 도구만 읽는다.

## 5. 못 한 것 · 남은 것

- 필요한 수는 K 와 v1.1.0 의 엇갈림으로 셌다. K2 가 다르게 움직이면 수가 바뀐다.
- 판정 남김률 · 판정 시간은 g3 값을 그대로 늘린 어림이다. 판정 토큰은 기록이 없어 못 셌다.
- BoolQ · KLUE 평서문의 평서문 검사(`*-rw.check.jsonl`)에서 떨어지는 줄은 따로 안 뺐다(g3 에서 BoolQ 평가 몫 2,084 중 2 [원문]이라 작다).
- 어느 안으로 갈지, 짝 비교 기준 판, dev 셋을 바꿀지는 메인 · 설계가 정한다.
