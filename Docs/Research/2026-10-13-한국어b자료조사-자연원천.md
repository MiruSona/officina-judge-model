# 한국어 b 자료 조사 — 자연 원천(「같은 자리가 고쳐진 글」) (2026-10-13)

- 작성일 2026-10-13 · 소단계 5b(한국어 b 조사 · 자연 원천 갈래). 같은 날 다른 갈래 둘(① 공개 데이터셋·논문 · ③ 합성·변환)이 따로 돌았다.
- 물음 : 영어는 VitaminC(위키백과 고치기 전후 문장 쌍)가 잘 먹혔다. **한국어에도 「같은 자리를 고친 글」이 쌓인 곳이 있나**, 있으면 라이선스가 되나, 거기서 v6 b 가 얼마나 나오나.
- 칸 뜻은 `../Guide/라벨기준support-v6.md` 1·3절. b = 두 문장이 **둘 다 참일 수 없음**. 고치기 전후 쌍은 v6 「덮은 결정」 · ③ 「낱말 하나 바꾼 문장」 꼴이라, **값 하나 자리가 바뀐 고침만 b** 다. 띄어쓰기 · 말투 · 한자 병기 고침은 a, 문장 덧붙이기는 a 나 d 다.
- 표시 : **[원문]** = 페이지 · API 응답을 직접 열어 봄 · **[요약]** = 검색 결과 요약만 봄 · **[어림]** = 이 문서가 짐작한 수 · **[기억]** = 사전 지식, 이번에 확인 못 함.
- 덤프 · 파일은 내려받지 않았다. 크기 · 수는 목록 · 통계 페이지에서 봤다.

## 2. 원천별

### 2-1. 한국어 위키백과 개정 이력 — 추천 1

- **얻는 법.** 두 길이 있다.
  - 덤프 : `dumps.wikimedia.org/kowiki/20261001/` 의 `pages-meta-history` 29조각. 조각 하나 .7z 27MB~459MB, 합쳐 **.7z 약 6GB · .bz2 약 23GB** [원문, 조각 크기를 더함]. 덤프는 완료 상태 [원문].
  - API : `ko.wikipedia.org/w/api.php` (`action=query&prop=revisions` · `action=compare`). 문서를 골라 이력만 받을 때 쓴다. 대량이면 덤프가 낫다.
- **주의 — XML 덤프는 「deprecated」 딱지가 붙었다** [원문]. 위키미디어는 「MediaWiki Content File Exports」(`other/mediawiki_content_history`)로 옮기는 중이고 [요약], 새 형식이 옛 덤프와 문서 수가 어긋난 버그 보고도 있다(Phabricator T417596) [요약]. 2026-10-01 판은 아직 옛 형식으로 나왔다. **내려받을 거면 다음 달에 사라질 수 있으니 이번 판을 쓰는 게 안전하다.** 받기는 IP 당 연결 3개 · User-Agent 규칙이 걸린다 [요약].
- **규모.** 본문 문서 768,240 · 전체 편집 42,575,401 · 활동 사용자 4,901 [원문 API 통계].
- **라이선스.** CC BY-SA 4.0 (일부 GFDL 겸용) [원문]. 공개 예정 모델(CC BY-SA 4.0)과 같다. 출처 표시는 「한국어 위키백과 개정 이력, 판 ID」로.
- **VitaminC 가 한 일(따라 할 틀).** 영어 위키 약 2억 개정에서 고친 문장 전후를 뽑고, BERT 분류기로 「사실이 바뀐 고침」 같아 보이는 상위 30.5만 문장을 골라 사람이 봤더니 **35%(107,056)가 사실 고침**이었다 [원문 ar5iv]. 표 · 목록 조각처럼 혼자 뜻이 안 서는 문장은 뺐다 [원문].
- **뽑을 수 있는 수 어림.** 편집 4,257만 중 본문 · 사람 편집을 반으로, 그중 한 문장만 고친 편집을 30%로 보면 문장 쌍 600만쯤. 「수가 바뀜 · 고유명사가 바뀜」 거르기에 5~10% 가 남으면 **30만~60만**. 거기서 v6 b(같은 자리 다른 값)를 20~35% 로 보면 **b 후보 6만~20만** [어림 — 비율은 전부 짐작이다. VitaminC 35% 는 분류기를 거친 뒤 「사실 고침」 비율이고, 사실 고침 중에도 덧붙이기(a)가 섞인다].
- **b 가 되는 꼴 · 안 되는 꼴.**
  - b : 「1987년 개교」 → 「1985년 개교」 · 「인구 4만 7천」 → 「5만 2천」(같은 때) · 「A 사가 개발」 → 「B 사가 개발」.
  - **함정 1 — 때가 다른 고침.** 「현재 인구 X」 를 해마다 고치는 편집은 엄밀히는 때가 다르다(v6 → d). 다만 문장에 때가 안 적혀 있으면 VitaminC 는 b 로 다뤘다. 우리 실사용(「옛 결정 ↔ 새 결정」 = 덮은 결정 → b)과도 같은 꼴이라 **b 로 쓰되 문장에 연도가 적혀 있고 그 연도까지 바뀐 쌍은 d 로 뺀다.**
  - **함정 2 — 훼손 · 되돌리기.** 장난 편집(값을 엉터리로 바꿈)과 그 되돌리기는 b 쌍으로 아주 깨끗하다(고친 뒤 문장이 참). 위키는 되돌린 편집에 표지(`mw-reverted` 꼬리표 · 「되돌림」 요약)를 단다 [기억]. 이 쌍은 따로 묶어 비율을 보면 좋다.
  - **함정 3 — 문체.** 백과사전체라 우리 짧은 기술 · 기획 문장과 다르다. 영어 VitaminC 도 같은 처지였는데 먹혔다.
- **도구 공수.** 덤프 스트리밍 읽기 + 위키 문법 벗기기 + 문장 나누기 + 한 문장 고침 짝 + 거르기 + 교사 라벨 ≈ 2~3일. 파이썬 패키지 `mwxml` · `mwparserfromhell` 를 쓰면 빠르다(**패키지 추가는 따로 승인받는다**).
- **이미 만든 셋은 없다.** 한국어 위키 문장 고침 쌍 데이터셋은 못 찾았다(HF 검색 · 논문 검색) [요약]. WikiAtomicEdits 는 8개 언어에 한국어가 없고, **덧넣기 · 지우기만** 담아 값 바꿈(b 꼴)이 없다 [원문].

### 2-2. 국가법령 신구조문 — 추천 2

- **얻는 법.** 법제처 Open API `http://www.law.go.kr/DRF/lawService.do?target=oldAndNew&MST=<법령일련번호>&type=XML` [원문]. 인증값 `OC` 신청이 필요하고(무료), 공공데이터포털에도 「법제처_신구법 본문 조회」로 올라 있다 [원문]. 응답에 `구조문목록` · `신조문목록` 이 조문 단위로 짝지어 온다. 시험 값 `OC=test` 로 실제 조문 글이 오는 것까지 확인했다 [원문].
- **라이선스.** 공공데이터포털 표기 「이용허락범위 제한 없음 · 무료」 [원문]. 법령 · 고시 · 공고 · 판결은 저작권법 7조로 보호받지 않는다 [요약 — 조문 원문은 국가법령정보센터에서 한 번 더 볼 것]. 상업 이용 · 공개 모델 둘 다 걸림이 없다고 본다 [추론].
- **b 비율이 낮다.** 표본 하나(환경분쟁 조정법 전부개정, 230 조문)를 열어 보니 **바뀐 자리의 약 70%가 띄어쓰기 · 한자 병기 · 「자 → 사람」 · 「인 → 명」 같은 자구 정비**였고, 값이 바뀐 자리는 없었다(새 조항 신설 · 범위 좁히기만) [원문, 표본 1건]. 전부개정이 아닌 일부개정은 고친 자리가 좁아 값 바꿈 비율이 더 높을 것이다 [어림]. 그래서 b 비율은 3~10% 로 넓게 잡았다.
- **b 가 되는 꼴.** 「~ 30일 이내」 → 「60일 이내」 · 「위원 15명」 → 「20명」 · 「○○부장관」 → 「△△부장관」(정부 조직 바뀜에 따른 타법개정 — 값 하나 자리라 v6 ③ 로 b 지만 너무 쉬운 b 라 비율을 묶어 둔다).
- **같은 꼴 원천.** 행정규칙(고시 · 훈령)도 2024년부터 신구법 비교가 붙었다 [요약]. 국회 의안의 신구조문대비표(의안정보시스템)도 같은 꼴이나 첨부가 HWP · PDF 다 [기억].
- **함정.** ① 법조문은 한 조문이 길고 항 · 호로 나뉘어 「문장 하나」로 자르는 일이 먼저다. ② 문체가 우리 실사용과 가장 멀다. ③ 개정 전후는 시행일이 다르니 엄밀히는 「때가 다른 같은 자리」 — 「덮은 결정」 규칙으로 b 로 읽는다.
- **공수.** API 받기 + 조문 짝 + 자구 정비 거르기(한자 · 띄어쓰기 · 「자 → 사람」 목록) ≈ 1.5~2일.

### 2-3. 정책브리핑 「사실은 이렇습니다」(언론 보도 ↔ 정부 해명) — 추천 3

- **얻는 법.** `www.korea.kr/briefing/actuallyList.do` 목록 → `actuallyView.do?newsId=…` 글. 목록 표기 **총 2,019건** [원문]. 부처별 「(설명)」 · 「(보도설명)」 · 해명 글이다 [원문].
- **라이선스.** 글 바닥에 「이 자료는 텍스트에 한하여 **공공누리 제1유형(출처표시)**」 [원문] — 상업 이용 · 고쳐 쓰기 가능. 출처 표시 「자료출처=정책브리핑 www.korea.kr」. 사진 · 그림은 빠진다. 다만 해명 글이 **인용한 언론 기사 문장**은 언론사 저작물이라, 주장 쪽 문장은 해명 글이 요약한 짧은 꼴만 쓰고 기사 원문은 가져오지 않는다 [추론].
- **b 비율이 높다.** 「~라는 보도는 사실과 다릅니다 · 실제는 ~」 꼴이 b 그대로다. 단 「(설명)」 글 상당수는 반박이 아니라 보충 설명(a · d)이라 25~45% 로 잡았다 [어림 — 본문을 열어 세지 못했다].
- **함정.** 열어 본 글 하나는 **본문이 PDF · HWPX 첨부에만** 있었다 [원문]. HWPX 는 압축 XML 이라 풀 수 있지만 PDF 만 있는 글은 글 뽑기가 일이다. 반박 문장과 보도 요약을 짝짓는 데 교사(LLM) 손이 든다. 쌍 수가 수백~천이라 평가 몫용으로 알맞은 크기다.
- **공수.** 목록 긁기 + 첨부 풀기 + 교사로 「보도 주장 · 해명」 짝 뽑기 ≈ 1.5~2일. 목록 긁기 전에 robots · 호출 속도를 한 번 본다(이번엔 안 봤다).

### 2-4. 한국어 기술 문서 깃 이력 — 문체 표본용

- **얻는 법.** 번역 문서 저장소를 clone 해서 `mine_archive.py revision` (한 줄 고침 -1 +1 · 닮음 ≥ .6 · 15자 이상)을 그대로 돌린다. 우리 저장소에서 447 후보 · 남김률 .16 을 낸 그 방식이다(`../../measure/sets-g2.md` 1절).
- **후보와 라이선스** [원문] : 쿠버네티스 문서(`kubernetes/website`, `content/ko`) CC BY 4.0 · react.dev 한국어(`reactjs/ko.react.dev`, 커밋 9,057) 문서 CC BY 4.0 · MDN 번역(`mdn/translated-content`, `files/ko`) 글 CC BY-SA 2.5(뒤 판으로 바꿔 쓰기 허용 조항이 있어 4.0 과 맞는다 [기억]). 그 밖에 파이썬 문서 한국어판 · 러스트 책 한국어판도 같은 꼴 [기억, 라이선스 확인 못 함].
- **b 비율이 낮다.** 고침 대부분이 번역 다듬기(a)다. b 는 원문 판이 바뀌어 따라 고친 자리 — 「Node 14 이상」 → 「Node 18 이상」 · 기본값 켬 → 끔 — 뿐이라 3~8% [어림].
- **그래도 넣는 까닭.** 짧은 한국어 기술 문장이라 실사용(팀 기억 저장소 글)과 문체가 가장 가깝다. 양보다 **평가 셋에 「우리 같은 문체」 표본을 수십 개 보태는 몫**이다.
- **함정.** 저장소마다 라이선스가 다르다 — 고를 때마다 LICENSE 를 연다. 코드 블록 · 링크 줄은 이미 `mine_archive` 가 거른다.

### 2-5. 제타위키 · 리브레 위키 — 위키백과 파이프라인의 덤

| 위키 | 라이선스 | 본문 문서 | 전체 편집 | 활동 사용자 | 이력 얻는 길 |
| --- | --- | --- | --- | --- | --- |
| 제타위키 | CC BY-SA 4.0 | 131,922 | 970,438 | 8 | MediaWiki API 열림. 덤프 못 찾음 |
| 리브레 위키 | CC BY-SA 3.0 Unported | 60,916 | 2,020,376 | 32 | MediaWiki API 열림. 덤프 못 찾음 |
| 페미위키 | CC BY-SA 4.0 | 22,290 | 339,128 | 8 | MediaWiki API 열림 |

수는 모두 각 위키 API `siteinfo` 통계 [원문, 2026-10-13]. 셋 다 MediaWiki 라 위키백과용 도구를 API 받기만 바꿔 쓴다. 덤프가 없으니 API 로 문서마다 이력을 받는다 — 호출 속도를 낮게 두고 User-Agent 를 단다. 제타위키는 IT 기술 메모가 많아 낱말이 우리 쪽과 가깝지만 활동 사용자가 적어 한 사람 글투에 쏠릴 수 있다. 페미위키는 주제가 좁고 사회 논쟁 글이 많아 우선순위를 낮춘다. 위키독스(wikidocs.net)는 책마다 라이선스가 따로이고 고친 이력이 공개되지 않아 뺐다 [요약].

## 3. 「같은 자리가 고쳐진 글」이 b 로 이어지는 흐름 (공통 파이프라인)

1. 이력에서 **이웃한 두 판**을 꺼낸다(위키 판 · 법령 신구 · 커밋).
2. 위키 문법 · 마크다운을 벗기고 문장으로 나눈다.
3. **한 문장만 바뀐 짝**을 남긴다(앞뒤 문장이 같고 가운데 한 문장만 다름 · 닮음 ≥ .6).
4. 거르기 : 띄어쓰기 · 문장부호 · 한자 병기만 다름 → 버림(a). 수 · 날짜 · 고유명사 · 켬/끔 · 서수가 바뀜 → 남김. 덧붙이기만 함 → a 후보로 따로.
5. **교사 라벨(v6 2단 지침)** 로 b · a · d 를 가르고, 갈린 쌍만 사람이 본다(2차 웹조사의 「입력은 실물, 라벨만 LLM」).
6. 근거 = 고친 뒤 문장, 주장 = 고치기 전 문장 (`mine_archive` 와 같은 방향).

## 4. 나무위키 — 쓸 수 있나

**결론 : 못 쓴다.** 라이선스(NC), 얻는 길(덤프 · 개정 이력 API 없음), 이 프로젝트 기준 셋이 다 막는다.

- **라이선스는 지금도 CC BY-NC-SA 2.0 KR 이다.** 나무위키 「나무위키」 문서 바닥글(최근 수정 2026-10-08) : 「이 저작물은 CC BY-NC-SA 2.0 KR에 따라 이용할 수 있습니다. (단, 라이선스가 명시된 일부 문서 및 삽화 제외)」 [원문]. 같은 문서는 CC BY-SA 위키(위키백과 · 리브레 위키)와 서로 글을 옮길 수 없다고 적는다 [원문]. 이용약관 · 라이선스 안내 문서는 주소를 셋 시도했으나 404 라 원문을 못 봤다 — 바닥글로 확인했다.
- **NC 자료로 학습한 모델을 CC BY-SA 로 공개하면 어긋나나.** 법으로 딱 정해진 답은 없다(회색지대). 「학습 = 저작물 이용인가」 · 「모델 가중치가 학습 자료의 2차 저작물인가」는 한국에서 판례가 없고, 텍스트 · 데이터 마이닝 면책 조항을 넣는 저작권법 개정안도 통과됐다는 소식을 못 봤다 [기억]. 그러나 ① NC 는 영리 목적 이용을 막고, 공개 모델은 남이 영리로 써도 되는 CC BY-SA 라 **우리가 NC 조건을 모델 사용자에게 넘길 길이 없다** ② SA 쪽에서 보면 2차 저작물로 볼 경우 CC BY-NC-SA 를 이어야 하는데 우리 공개 라이선스와 맞지 않는다. 회색이면 피한다 — **이 프로젝트는 지금까지 NC 자료를 다 뺐다**(SICK CC BY-NC-SA 3.0 · FNC-1 등, `2026-10-11-d자료웹조사2차.md` 2절). 나무위키도 같은 기준으로 뺀다.
- **덤프 · 개정 이력 API.** 공식 덤프를 지금 내주는지 원문을 못 찾았다. 허깅페이스에 남이 올린 사본은 「2022/03/01 덤프」 867,024 문서 · 라이선스 cc-by-nc-sa-2.0 · **현재 판만 있고 이력 칸이 없다** [원문 HF 카드]. 공개 개정 이력 API 는 못 찾았다 [요약]. `robots.txt` 는 전부 막고 `/history/` (판 목록)만 열었다 — **두 판 비교(diff) · 원문(raw) 주소는 막혀 있다** [원문]. 즉 고친 문장 쌍을 뽑으려면 막힌 주소를 긁어야 한다.
- **같은 꼴로 쓸 수 있는 대안** : 2-1 위키백과(CC BY-SA 4.0 · 편집 4,257만) · 2-5 리브레 위키(CC BY-SA 3.0, 나무위키와 문체가 가장 가까움 · 편집 202만) · 제타위키(CC BY-SA 4.0 · IT 메모) · 페미위키(CC BY-SA 4.0). 문서 수 · 고침 밀도는 위키백과가 압도적이고, 「나무위키 같은 구어 서술」이 꼭 필요하면 리브레 위키가 가장 가깝다.
