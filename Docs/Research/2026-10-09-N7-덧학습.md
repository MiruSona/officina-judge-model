## 5. 고른 까닭

1. **dev 에서 B 가 앞선다** : 정확도 0.897 > 0.868 · 반대 재현 0.844 > 0.822 · 지지 재현 0.849 > 0.779 · 거짓 지지 5 로 같다.
2. **K 48 은 같다** (43/48 · 거짓 지지 2). A 가 지지 하나 더, B 가 무관 하나 더 맞췄다.
3. 설계 6-3 의 자(정확도 0.85 · 반대 0.75)는 둘 다 넘는다. 비슷하면 B 로 하기로 했고(자료가 더 넓다), 실제로도 dev 에서 B 가 낫다.
4. 게임 쌍이 link · num · long 을 보탰는데, dev 의 link 지지 재현이 0.73 → 0.82 로 올랐다. 게임 저장소 쪽 쌍꼴에도 덜 낯설 것이라 game90 에 유리할 수 있다(이건 잴 때까지 모른다).

`runs/nli-studio-v1/` 는 판 B 의 `ckpt-best` · `train_info.json` · `eval-*` 를 **복사**한 것이다 (`model.safetensors` SHA `61ea91e1…` 둘이 같음).

## 7. 뜻 차이가 얼마나 메워졌나 (dev 지지 재현, kind 별)

| kind (dev 지지 쌍) | 기반 nli-base-v1 (N6) | 판 A | **판 B (nli-studio-v1)** |
| --- | --- | --- | --- |
| long (15) | 0.40 | 0.73 | **0.87** |
| same (40) | 0.30 | 0.83 | **0.93** |
| num (15) | 0.13 | 0.73 | **0.67** |
| link (11) | 0.09 | 0.73 | **0.82** |
| 지지 전체 (86) | 0.24 | 0.78 | **0.85** |

- 설계 4-3 의 갈림 「long · link 가 0.70 아래면 replay 를 2:1 로 다시」 는 **안 탔다** (0.87 · 0.82).
- **num 은 0.67 로 가장 약하다.** num 지지 15쌍 중 틀린 5쌍은 무관 3 · 반대 2 다 — 반대 2쌍은 반올림·요약된 숫자를 「숫자가 바뀐 반대」로 본 쪽이다. 게임 쌍에 num 이 64 쌍 있는데도 A(0.73)보다 한 쌍 낮다. 15쌍이라 한 쌍이 0.07 이다.
- 반대로 「NLI 함의가 엄하다」는 어긋남(지지 → 중립)은 무관으로 간 지지가 49 → 8 쌍으로 줄어 거의 사라졌다.
