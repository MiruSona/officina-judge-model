## 0. 결론

1. **K 가 놓친 한국어 c 는 「쉬운 c」다.** 근거와 주장이 낱말 하나 안 겹치는, 다른 문단끼리 붙인 쌍(near-x)이다 [셈]. 부정어 · 수치 근접 · 길이는 원인이 아니다(1-3).
   - blind-g3 : ko c 61 중 v1.1.0 만 맞힌 쌍 **8**, K 만 맞힌 쌍 **0**. 8쌍 모두 near-x 다. BoolQ 6 (→ d 5 · b 1) · 위키 2 (→ d 1 · b 1).
   - dev-cmp-g3 : 씨앗 다섯 다수결로 v1.1.0 쪽만 맞힌 쌍 11, K 쪽만 맞힌 쌍 9 — 합으로는 비긴다. 그런데 **klue-mrc 는 10 대 0** 이다. klue-mrc ko c 재현이 씨앗 평균 .819 → .667 이다.
2. **까닭은 「글 갈래 지름길」로 본다** [셈 근거 · 결론은 어림].
   - 학습 층 train-g3-ko 2,644쌍은 **전부 「같은 근거 · 고친 주장」 꼴**이다. c 는 1쌍뿐이다.
   - 그래서 BoolQ 문단 · 위키 「제목 : 문장」 · KLUE 뉴스 문단이 근거로 오면 답이 늘 a · b · d 였다.
   - 게다가 BoolQ · KLUE 쪽 a · b 중 **193쌍은 근거와 주장의 낱말 겹침이 .1 아래**다. 「안 겹치면 c」라는 단서를 학습이 직접 지웠다.
   - 영어 c(VitaminC)와 우리 글(archive · mem) c 는 내리지 않았다(오히려 올랐다).
3. **dev-cmp-g3 에는 BoolQ · 위키 한국어 c 가 0쌍이라 짝 비교가 못 봤다** [셈]. 한국어 c 347쌍이 archive · mem · klue-mrc 뿐이다. 한국어 c 60쌍은 blind-g3 에만 넣었다(`sets-g3.md` 10절).
4. **c 층 재료는 이미 디스크에 넉넉하다.** 안 쓴 묶음이 BoolQ 학습 쪽 2,923 · 위키 3,808 · KLUE 1,850 이다. 라이선스는 모두 CC BY-SA 4.0 이다. 평가 셋을 만든 도구(`make_sets.near_c`, BM25 10~60위)를 학습 쪽에 그대로 쓰면 된다. **추천은 2안**(아래 3절)이다.
   - 같은 원천 near-x c 약 900 + 「같은 주장 · 다른 근거」 c 짝 약 400, 합 c 약 1,300.
   - 공수 어림 6~8시간이다. 학습 · 측정 시간은 빼고, 판정은 Opus 두 판 기준이다.
5. **b 를 지키는 길** : K 의 b 층은 그대로 둔다. c 는 b 와 같은 근거 · 같은 주장에 묶어 「c 짝」으로 넣는다. 짝 비교에 `c_recall@ko` 와 원천별 c 지킴 자를 더한다(4절).

## 2. 왜 밀렸나 — 학습 층과 맞대 보기

### 2-1. 학습 층 꼴 [셈 · `sets/g3/train-g3-ko.jsonl`]

| 원천 (pick) | 쌍 | 꼴 | a · b · c · d | 근거 「제목 : 」 꼴 | 근거 · 주장 낱말 겹침 평균 |
| --- | --- | --- | --- | --- | --- |
| 위키 | 945 | wiki-edit (같은 문장 고친 판) | 114 · 500 · **1** · 330 | 942 | .86 |
| BoolQ | 733 | labeled (같은 문단의 참 · 거짓 평서문) | 350 · 350 · 0 · 33 | 1 | .43 |
| 씨앗 | 516 | contrast (같은 문장 한 자리 바꿈) | 162 · 320 · 0 · 34 | 57 | .89 |
| KLUE | 308 | qa-alt · qa-true (같은 문단 답 바꿈) | 121 · 187 · 0 · 0 | 0 | .22 |
| MIT | 142 | edit · num-change | 142 · 0 · 0 · 0 | 17 | .92 |

- **다섯 원천 모두 「근거와 주장이 같은 대상」인 꼴뿐이다.** 다른 대상을 붙인 쌍이 한 줄도 없다. c 1쌍도 위키 고친 판(40분 → 1시간)으로, 사람이 보면 b 에 가깝다.
- **낱말 겹침 .1 아래인 a · b · d 가 193쌍이다** — KLUE b 60 · BoolQ b 48 · BoolQ a 41 · KLUE a 36 · BoolQ d 8. BoolQ · KLUE 주장은 질문을 평서문으로 고친 글이라 근거와 낱말이 잘 안 겹친다. 이 쌍들이 「안 겹쳐도 c 가 아니다」를 가르쳤다.

### 2-2. 섞임 비율 [원문 · `train_info.json`]

| | B2 (v1.1.0) | K |
| --- | --- | --- |
| 한 바퀴 우리 층 (replay 뺌) | train-r2 2,965 + g1-arch 1,436 = 4,401 | + train-g3-ko 2,644 = 7,045 |
| 그중 c (cd 뺌) | 1,436 (32.6%) | 1,437 (20.4%) |
| 그중 한국어 공개 원천 글 (BoolQ · 위키 · KLUE) | 0 | 1,986 — c 0 |
| replay (KLUE-NLI · MNLI · SNLI, 중립은 cd) | 2,965 / 바퀴 | 2,965 / 바퀴 (몫 40% → 30%) |
| 칸 가중치 a · b · c · d | .63 · 1.29 · .58 · 1.50 | .65 · .82 · **1.01** · 1.52 |

- c 가중치는 오히려 .58 → 1.01 로 올랐다(드문 칸을 무겁게 하는 셈). **그래도 c 가 밀렸으니 「c 가 적어서」보다 「그 글 갈래에 c 가 없어서」로 본다** [어림].
- c 를 잡아 준 옛 층(g1-arch c 984)은 우리 문서 글이다. 그래서 archive · mem c 는 그대로였다. BoolQ · 위키 · KLUE 같은 백과 · 뉴스 문단 c 는 B2 에도 학습 쌍이 없었다. B2 는 「겹치는 것이 없으면 c」라는 일반 규칙으로 맞혔다. K 의 새 층이 바로 그 갈래에서 그 규칙을 깼다.

### 2-3. 왜 d 쪽으로 갔나

- 위키 d 330 은 「2013년 현재 … / 2012년 현재 …」 같은 판 차이다 [원문 표본 3]. 「제목 : 」 근거 + 다른 문장 = d 가 학습됐다. blind 위키 c 의 d 확률이 .069 → .120 으로 올랐다 [셈].
- BoolQ d 33 · 씨앗 d 34 는 적지만, BoolQ 문단에서 a · b 가 아니면 갈 곳이 d 뿐이었다(c 0).
- blind d 재현이 ko .200 → .533 으로 크게 오른 것과 같은 힘이다. **c 를 되찾으면 d 재현 몫이 일부 되돌아갈 수 있다** [어림].

### 2-4. 짝 비교가 왜 못 봤나

- dev-cmp-g3 ko c 347쌍의 원천은 archive 188 · mem 87 · klue-mrc 72 이고, BoolQ · 위키는 0 이다 [셈].
- 짝 비교 지킴 자는 `c_recall` 전체 하나였다. klue-mrc 의 내림(−.15)을 archive 의 오름(+.02 × 188쌍)이 덮었다. 결과는 +.0016 「지킴 O」였다(`g3-K-eval/compare.md`).

### 3-2. 판정을 해야 하나

- 평가 셋 near-x 60쌍은 v6 두 판 판정을 거쳐 거의 다 c 로 남았다. blind-g3 한국어 c 61 = 후보 60 + 위키 1 이다 [원문 sets-g3.md 10절 · 셈].
- 그래도 BM25 10위 근처는 같은 주제가 섞일 수 있다(d 위험). **학습 몫도 두 판 판정을 거치기를 권한다** — 판정 어긋남은 버린다. 10~20위만 판정하고 30위 밖은 표본만 보는 절약 길도 있다 [어림].

### 3-3. 후보 세 안

| | 1안 — near-x 만 | **2안 — near-x + c 짝 (추천)** | 3안 — 2안 + 어려운 c |
| --- | --- | --- | --- |
| c 수 | BoolQ 300 · 위키 300 · KLUE 200 = **800** | near-x 900 (BoolQ 350 · 위키 350 · KLUE 200) + c 짝 400 = **1,300** | 1,300 + 같은 문서 다른 대상 c 300~500 + KLUE other-doc 250 = **1,850~2,050** |
| c 짝 | 없음 | 층의 b 쌍 주장을 **다른 문단 근거**에 붙인 c (BoolQ 200 · KLUE 100 · 위키 100) | 같음 |
| 층 c 몫 (train-g3-ko + c) | 800 / 3,444 = 23% | 1,300 / 3,944 = 33% | 약 1,950 / 4,600 = 42% |
| 한 바퀴 우리 층 c 몫 | 2,237 / 7,845 = 29% | 2,737 / 8,345 = 33% (B2 의 32.6% 와 비슷) | 약 38% |
| 판정 | 800 × 2판 | 1,300 × 2판 | 2,000 × 2판 + 어려운 c 는 갈림이 많다 |
| 공수 어림 | 4~5시간 | **6~8시간** | 10~14시간 |
| 위험 | 「안 겹치면 c」만 배워 겹침 낮은 a · b 를 c 로 부를 수 있다 | 같은 주장이 a · b · c 에 다 나와 주장 문체만으론 못 고른다 | 어려운 c 가 d 와 갈려 d 재현을 깎을 수 있다 |

- 공수는 이렇게 어림했다 [어림].
  - 뽑기 스크립트 1~1.5시간 — `add_g3_ac.py` 와 같은 꼴로 `make_sets.near_c` 를 학습 쪽 묶음에 부른다.
  - 판정 묶음 · 두 판 판정 · 합본 3~4시간.
  - `layer_g3.py` 에 c 목표 칸 추가 · 재조립 · 검사 1~1.5시간 — 지금 targets 에 c 칸이 없다(`train-g3-ko.md` 6-5).
  - 학습 다섯 판 · 짝 비교는 따로다. K 한 판이 약 18.5분(2,504걸음 × .44초)이었고, 2안은 한 바퀴 쌍이 약 13% 늘어(10,010 → 11,310) 약 21분이다.
- **2안을 추천하는 까닭** : 우리 층 c 몫이 B2 와 같은 33% 로 돌아온다. 그리고 c 짝이 「BoolQ · KLUE 평서문 문체 = a · b」 지름길을 직접 끊는다.

## 4. c 를 올리면서 ko b 를 지키는 길

| 길 | 무엇 | 왜 |
| --- | --- | --- |
| ① b 층은 그대로 | train-g3-ko 2,644쌍을 바꾸지 않고 c 만 더한다 | K 의 ko b +.128 이 이 층에서 왔다. 섞임만 바꿔 원인을 가른다 |
| ② c 짝 (주장 쪽) | 층의 b 주장 X 를 「제 문단」에는 b, 「다른 문단」에는 c 로 둘 다 둔다 | 모델이 주장 문체가 아니라 근거와의 관계를 봐야 한다. 같은 묶음끼리라 묶음 누출 걱정이 없다 |
| ③ c 짝 (근거 쪽) | 같은 BoolQ · 위키 문단에 a · b 주장과 near-x c 주장을 함께 둔다 | 「BoolQ 문단 = a · b」 지름길을 끊는다 |
| ④ 겹침 낮은 a · b 193쌍을 남긴다 | 지우지 않는다 | 이것이 「안 겹치면 c」 쪽으로 너무 가지 않게 잡는 무게추다 |
| ⑤ 짝 비교 자 더하기 | `c_recall@ko` 지킴(≥ −.03) · 원천별 c 보고(boolq · kowiki · klue-mrc) · `b_recall@ko` 목표 유지 | K 의 내림은 원천 하나에 몰려 전체 자로는 안 보였다 |
| ⑥ 새 dev 에 한국어 공개 원천 c | 새 dev-cmp · dev-cal · blind 에 BoolQ · 위키 · KLUE near-x c 를 원천마다 30~50 | 지금 dev-cmp-g3 에는 0 이다. blind-g3 쌍은 다시 쓰지 않는다 |
| ⑦ 실패하면 비율만 내린다 | ko b 가 짝 비교에서 −.03 넘게 내리면 c 짝을 400 → 200 으로 줄인 K2-h | K-h 와 같은 「미리 정한 대체 판」 꼴 |

- ko b 를 잃을 위험은 낮다고 본다 [어림]. c 짝은 근거가 다른 문단이라, 같은 문단 b 의 결정 면을 직접 건드리지 않는다. 다만 **겹침 낮은 b(193쌍 중 b 108)** 가 c 쪽으로 밀릴 수 있어 ⑤ 의 원천별 b 를 같이 본다.
- a 재현(blind a .914 → .815, BoolQ)도 같은 지름길 탓이면 c 짝이 같이 고칠 수 있다 [어림 — 안 재 봄].

## 5. 확인 못 한 것

- 학습 쪽 near-x 후보를 실제로 뽑아 보지 않았다. c 어림(3-1)은 묶음 수에서 짐작한 값이다.
- 「글 갈래 지름길」은 수의 정황이다. 원천 판별 · 주의 가중치처럼 모델 안을 들여다본 증거는 아니다. 확실히 하려면 K 에 BoolQ 학습 쪽 near-x 100쌍을 넣어 c 가 얼마나 나오는지 보면 된다(학습 없이 평가만, 10분 안팎 [어림]).
- B2 씨앗 다섯의 blind 예측은 없다(v1.1.0 한 판뿐). blind 쪽 「v1.1.0 만 맞힘」 8쌍은 판 하나끼리의 견줌이다.
- 영어 b 아래끝(−.032) · a 아래끝(−.035)은 이 조사 범위 밖이다.
