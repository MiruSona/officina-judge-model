## 주의

- **blind 는 dev 와 결이 다르다.** blind 는 history·todo 기억에서 나왔고 supersede · link 가 없다. dev 는 decision·caution 기억(game90 기억의 다른 문장)이 많고 supersede 33쌍이 있다. dev 점수가 blind 점수를 그대로 예측하지 않는다.
- dev 의 supersede·same 쌍 일부는 game90 과 주장(claim)이 같고 근거만 다르다. game90 은 학습에 안 쓰니 새는 길은 없다.
- 라벨은 Opus 둘의 일치이고 사람은 안 봤다.

## v2 시도 — 스튜디오 store supersede 덧붙임 (멈춤, blind 그대로)

blind 에 supersede 가 0이라 스튜디오 store 의 덮음 짝을 더하려 했다. **blind 에 넣을 수 있는 짝이 3개뿐이라 멈췄다.** blind 는 바꾸지 않았다(SHA 그대로).

## v2 — 합성 블록 (blind 다시 얼림, 측정 전)

**blind 에 합성 supersede 블록 109쌍을 더해 332쌍으로 다시 얼렸다.** 새 SHA `94ed613a66fb7c1028967a7128792596e6e4d1e6db7d889ee9cc71e4a84956e1` · `freeze.py check` ok. 옛 SHA(`27b8de33…`)는 MANIFEST 와 `blind-v1.jsonl` · `FROZEN-v1.sha256` 에 남겼다. dev 는 안 바꿨다.

**까닭**

- v1 blind 는 supersede 가 0이라 지난 미달의 핵심(덮음 반대)을 못 잰다. 실물 덮음 짝은 게임·스튜디오 store 둘 다 바닥이다(위 v2 시도 절).
- retain 관문이 실제로 하는 일은 「저장소에 이미 있는 기억 ↔ 새로 들어온 주장」 판정이다. 근거가 학습에 쓴 기억이어도 주장이 새것이면 실제 쓰임과 같은 꼴이다.
- 그래서 근거는 덧학습 446 이 쓴 게임 기억 216개 중 decision·caution·howto(165) 에서 골랐다. 이 기억은 dev·v1 blind 어느 덩이에도 없어 dev 와 안 겹친다. **blind ∩ 446 기억 59 는 의도된 것이다.** 스튜디오 store 는 학습용 합성 갈래가 쓰고 있어 안 썼다.
