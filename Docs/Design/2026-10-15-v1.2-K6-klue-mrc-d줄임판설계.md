## 2. 멈춤 규칙 점검 (판 규칙 1-3)

- b@ko 는 **K3 · K4 · K5 세 판 연속** 같은 지킴에서 깨졌다. 멈춤 규칙에 걸렸다.
- 그래서 K5 뒤에 학습 판을 띄우지 않고 진단(혼동표 · 원천 × 칸 · 씨앗 바꿔치기 · 겹침 구간)을 먼저 했다(진단 문서, 학습 0).
- **이 판은 그 진단의 후보 (ㄱ)을 사용자가 열어 준 판이다**(2026-10-15).
- **멈춤 줄 (판을 열기 전에 정함)** : K6 도 b@ko 지킴이 깨지면(아래끝 < −.03) 진단 뒤 새 판을 더 열지 않는다. **(ㄴ) — v1.2 를 접고 8092 는 v1.1.0 을 그대로 둔다.** 「문턱 근처」(판 규칙 3-1)여도 같다.
- 통과하면 blind-g4 를 한 번 열고 출시 관문으로 간다.

## 3. 층 손질 — train-g4-bal2

### 3-1. 어느 123줄을 빼나

대상 = train-g4-bal 에서 `cell_key` 가 (klue-mrc, d) 이고 origin g4-train 인 줄 **243 [손셈]**(꼴은 모두 `klue-removed`, 원래 train-g4-d 에서 옮겨 온 홀로 줄). klb 의 klue-mrc d 37 · bal 의 다른 klue-mrc 칸(a 90 · b 32 · c 132)은 안 건드린다.

| 안 | 무엇 | [손셈] | 약점 |
| --- | --- | --- | --- |
| (a) 씨앗 고정 무작위 | 243 중 120 을 무작위로 남김 | — | c 짝이 달린 d 23줄 중 절반쯤이 빠진다. K2 가 겪은 「축 한쪽만 남음」(R2)이 작게나마 생긴다. 구간 몫은 운에 맡긴다 |
| (b) 짝 보존 먼저 | 같은 묶음에 klue-mrc b 가 있는 d 를 먼저 남기고, 나머지에서 무작위 | 그런 d 는 **1줄뿐** | 243줄이 거의 다 다른 묶음(묶음 269 · 한 묶음에 2줄은 1곳)이라 (b) 만으로는 (a) 와 거의 같다 |
| (c) 겹침 구간 몫 유지 | 구간 0 · 1 · 2 를 각각 같은 비율로 줄임 | 구간 0 86 · 1 73 · 2 84 · 3 0 | 짝을 안 본다 |
| **고름 : (b) 넓힘 + (c)** | ① 같은 묶음에 klue-mrc b 가 있는 d (bal + klb 기준) ② `pair` 칸이 달린 d(c 짝) — 둘을 먼저 다 남기고, ③ 나머지를 **구간별 같은 몫으로** 씨앗 고정 무작위로 채워 120 | ① 1 · ② 23 → 남길 몫 24 · ③ 96 | 셋을 다 지킨다. 손이 하나(구간별 몫 나누기) 더 든다 |

- **고른 까닭** : 짝은 K4 설계 1-1 규칙 5(축의 양쪽을 짝으로)로 일부러 만든 줄이다. 짝을 깨면 「한 판에 바꾸는 것」이 둘이 된다(빼기 + 축 깨기). 구간 몫은 T2 가 보는 자리라, 지켜 두면 T2 가 줄 수 말고는 안 움직인다. 비용은 같은 도구 안의 몇 줄이다.
- ③ 의 구간 몫은 「큰 나머지」로 나눈다(구간 0 : 1 : 2 = 86 : 73 : 84 의 비로 96 을 나눔). 대상 줄은 id 순으로 정렬한 뒤 씨앗으로 섞는다 — 입력 줄 차례가 바뀌어도 같은 결과.
- 120 의 까닭 : 진단 5절 「약 절반」. 243 → 120 이면 덧층 klue-mrc d 몫이 .35 로 dev(.49)보다 .14 낮아 T1 문턱 안에 여유 .06 을 남긴다. 더 줄이면(예 80) −.20 에 가까워져 역풍 위험이 커진다.

### 3-2. 파일 꼴 — 새 층으로 얼린다

| 길 | 무엇 | 고름 |
| --- | --- | --- |
| **① 새 층 train-g4-bal2** | bal 에서 줄만 뺀 파일을 새로 얼린다. bal 은 그대로 둬 K4 · K5 재현을 지킨다 | **고름** — 얼린 층 · 해시 규약(`train_sets` · `FROZEN-*.sha256`)과 맞다. 학습 스크립트는 `--train` 파일 이름 하나만 바뀐다 |
| ② exclude 파일 | 뺄 id 목록 파일을 두고 학습 스크립트가 거른다 | 학습 입력이 「파일 + 거름」 둘이 되어 해시 하나로 못 맞춘다. train_nli 를 고쳐야 한다 |

- **줄 내용은 바이트 그대로 옮긴다.** `set` 칸도 `train-g4-bal` 그대로 둔다 — 「bal2 ⊂ bal」을 줄 바이트로 맞춰 볼 수 있게. 다른 도구가 `set` 을 층 이름과 견주는지는 2단계 첫 일로 본다(`build --v6` 재료 차단은 klb 줄만 막는다 — `../../build/README.md` 36항). 걸리면 그 검사 쪽을 손대지 않고 메인에 알린다.
- 새 id 가 없다 — id 꼬리 규칙(36항 「다음 층부터 `-s`」)은 이 층에 해당 없다.

### 3-3. 도구 — `layer_g4bal.py thin-mrc-d`

| 칸 | 값 |
| --- | --- |
| 명령 | `layer_g4bal.py thin-mrc-d --layer <g4>/train-g4-bal.jsonl --frozen <g4>/FROZEN-train-g4-bal.sha256 --klb <g4>/train-g4-klb.jsonl --keep 120 [--seed THIN_SEED] --out <build g4>/train-g4-bal2/ [--force]` |
| 대상 | `cell_key == ("klue-mrc", "d")` · origin `g4-train` |
| 남김 차례 | ① 같은 묶음(`groups`, 없으면 `group`)에 klue-mrc b(bal + klb)가 있는 d ② `pair` 칸이 있는 d ③ 나머지를 겹침 구간(`layer_g4d.overlap` · `bin_of` · 가름 .1 · .2 · .35)별 큰 나머지 몫으로 씨앗 무작위 |
| 출력 | `cands.jsonl`(bal 줄 그대로 · 차례 그대로 · 뺀 줄만 없음) · `summary.json`(입력 sha · 규칙 이름 · 씨앗 · keep · 단계별 남긴 수 · 구간별 전 / 뒤 수 · **뺀 id 목록** · 줄 수 전 / 뒤) |
| 씨앗 | 새 상수 `THIN_SEED = 20261506`(KLB_SEED 다음) |
| exit | 0 = 됨 · 2 = 파일 없음 · 입력 sha 가 FROZEN 과 다름 · keep 이 ①+② 보다 작거나 대상 수 이상 · 출력이 있는데 `--force` 없음 |
| 얼림 | `cp cands.jsonl sets/g4/train-g4-bal2.jsonl` → `freeze.py write` → `FROZEN-train-g4-bal2.sha256` |

시험 (`test_layer_g4bal.py` 에 `ThinMrcDTest` 하나):

1. **남김 차례** — 짜 맞춘 작은 층에서 ① · ② 줄이 다 남고, 남긴 수가 keep 이고, 구간별 수가 큰 나머지 몫과 같다.
2. **부분집합 · 재현** — 같은 씨앗 두 번이 바이트 같고, 출력 줄이 모두 입력 줄과 바이트 같으며, 대상 밖 줄은 하나도 안 빠진다. 입력 차례를 섞어도 같은 id 가 남는다.
3. **exit 2** — FROZEN sha 다름 · keep 범위 밖 · 출력 덮어쓰기.

## 4. 점검표 예상 (판 규칙 2-1 ~ 2-5) [손셈]
