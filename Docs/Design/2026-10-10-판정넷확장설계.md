## 결론 먼저

**상태** : 설계 끝 · 사용자 결정 셋 **확정**(2026-10-10, 끝 절) · 15 소단계(학습·내보내기 넷 칸) 구현 끝, 나머지(14 · 16 · 17 · 18) 전.

**한 줄** : 모델 머리를 **넷**(지지 a · 반대 b · 무관 c · **비슷한 계열 d**)으로 늘리고, 기억 짝을 **두 방향으로 한 번씩** 물어 「접기」와 「합치기」를 가른다.

```
짝 (X, Y) 를 두 번 묻는다 :  X→Y (X 가 근거, Y 가 주장)  ·  Y→X

  어느 쪽이든 확신 b           → 모순 후보   (contradict 큐, 지금 그대로)
  양쪽 다 「담김」              → 같은 내용   → 접기 후보 (옛 쪽 접음)
  한쪽만 「담김」               → 작은 쪽이 큰 쪽에 담김 → 접기 후보 (작은 쪽 접음)
  a 지만 담김은 아님 · 또는 d   → 겹치거나 같은 계열 → 합치기 후보 (merge 큐)
  둘 다 c                      → 무관 — 아무 큐에도 안 올림
```

| 갈래 | 무엇 | 잃는 것 | 누가 처리 |
| --- | --- | --- | --- |
| **접기** | 한 기억의 말이 다른 기억에 **다 들어 있다** | 없음 | 큐에 올리기만 한다. 접는 것은 AI 세션·사람 (자동 접기는 다음 판 — 끝 절 1) |
| **합치기** | 같은 주제인데 **서로 다른 말**이 있다 | 다시 안 쓰면 한쪽 말이 사라진다 | 사람·AI 가 두 기억을 **다시 써야** 한다. merge 큐에만 올린다 |

- **「담김」은 모델 칸 하나가 아니다.** 우리 지지(a)는 「일부만 받쳐도 지지」라서(길 1 설계 4-3), a 하나로는 「다 들어 있다」를 말 못 한다. 그래서 작은 쪽 기억을 **문장으로 쪼개 문장마다 확신 a** 일 때만 「담김」으로 친다(4-2).
- 새 이름 : 모델 `nli-studio-v3` · 응답 꼴 판 `nli-v2` · 라벨 기준 `support-v4` · 설정 `nli_sure_related` · 판정 셋 dev `dev-r2` · blind **v3**(새로 얼림).
- 옛 서버(`nli-studio-v2`)·옛 판 이름은 그대로 남겨 언제든 되돌린다(8절).

## 1. 라벨 정의 (`support-v4`)

`support-v4` = 지금 기준 `support-v3`(일부만 받쳐도 지지 · 어느 부분도 안 다루면 무관) **+ 무관을 둘로 쪼갬**.

| 칸 | 글자 | 뜻 | 한 줄 시험 |
| --- | --- | --- | --- |
| 0 | a 지지 | 근거가 주장의 **어느 한 부분이라도** 맞다고 받친다 | 주장 안에서 근거가 「맞다」고 해 주는 말이 하나라도 있나 |
| 1 | b 반대 | 근거가 주장의 어느 부분과 **어긋난다** | 둘 다 참일 수 없는 말이 하나라도 있나 |
| 2 | c 무관 | 다른 주제 | 두 글을 한 문서의 **같은 절**에 넣을 사람이 없다 |
| 3 | d 비슷한 계열 (새) | **같은 주제**인데 근거가 주장의 어느 말도 받치거나 뒤집지 않는다 | 같은 절에 들어갈 글인데, 서로 다른 사실을 말한다 |

**칸 차례는 a·b·c 를 그대로 두고 d 를 넷째에 붙인다.** 옛 칸 번호가 안 바뀌어 옛 평가 스크립트·옛 쌍 라벨을 고칠 필요가 없고, 3칸 기반 모델의 머리를 그대로 이어받을 수 있다(3-2).

### 1-1. 가르는 기준 (라벨 붙이는 사람·Opus 에게 주는 글)

**우선순위 : b > a > d > c.** 위에서부터 먼저 걸리는 칸을 붙인다.

| 헷갈림 | 기준 | 보기 (일반 문장) |
| --- | --- | --- |
| b 와 a 가 같이 있음 | **b.** 일부를 받쳐도 어긋나는 말이 하나 있으면 반대다 | 근거 「기본 켬 · 상한 100」 ↔ 주장 「상한 100 · 기본 끔」 → b |
| a 와 d | 주장의 말 중 근거가 **맞다고 해 주는 것이 하나라도** 있으면 a. 같은 주제라도 받쳐 주는 말이 하나도 없으면 d | 근거 「문턱을 0.30 으로 올렸다」 ↔ 주장 「문턱 보완 뒤 놓침이 5% 남았다」 → d (같은 문턱 일이지만 받치는 말 없음) |
| d 와 c | **같은 대상**(같은 툴의 같은 기능 · 같은 규칙 · 같은 수치 자리 · 같은 결정 자리)을 말하면 d. 같은 툴이어도 기능이 다르면 c | 「merge 큐 문턱」 ↔ 「merge 큐 놓침」 → d · 「merge 큐 문턱」 ↔ 「검색 색인 크기」 → c |
| 같은 scope 라는 것 | **기준이 아니다.** 같은 scope 라도 대상이 다르면 c | — |
| 한쪽이 다른 쪽의 「다음 단계」 | 앞 단계 결과를 다시 말하면 a, 새 일만 말하면 d | — |

- 라벨러가 c 와 d 사이에서 정말 못 고르면 **`cd`(둘 중 하나)** 를 붙일 수 있다. `cd` 쌍은 dev·blind 에 안 넣고 학습에서만 「합친 칸 손실」로 쓴다(3-3).
- 이 표는 라벨 지시 글의 원문이다. 구현 때 `Docs/Research/` 의 셋 만들기 문서에 그대로 옮긴다.

### 1-2. 다섯 칸을 안 고른 까닭 (다른 길)

- **다섯째 칸 「필요 없음」은 기각했다** — 「필요 없음」은 사실상 「다른 기억이 이 기억을 다 받친다」라 지지와 겹치고, 그렇게 붙인 자료도 없다. 양방향 지지로 끌어내면 새 칸 없이 같은 답이 나온다.

## 2. 응답 꼴 · 판 이름

### 2-1. 서버 (`serve.py`)

| 끝점 | 지금 (`nli-v1`) | 새 판 (`nli-v2`) |
| --- | --- | --- |
| `POST /judge` | `{"a","b","c","model","ms"}` | `{"a","b","c","d","model","ms"}` — 넷 합이 1 |
| `GET /health` | `{"ok","model","backend","name"}` | 위 + **`"letters": ["a","b","c","d"]`** (칸 수는 이 목록 길이) |

- 서버는 `model.json` 의 `letters` 를 읽어 응답 칸을 정한다. **`LETTERS` 상수를 없앤다** — 3칸 모델을 띄우면 지금 꼴 그대로 나간다. 그래서 같은 `serve.py` 로 옛 모델도 띄운다(되돌리기).
- **`--compat3` 깃발** : 4칸 모델을 띄우되 응답은 `{"a","b","c": c+d}` 로 낸다. 옛 `mem` 실행 파일(판올림 전 다른 저장소의 것)이 이 서버를 불러도 깨지지 않게 하는 물러설 길이다. 기본은 꺼짐.
- 양방향은 **손님이 두 번 부른다.** 묶음 끝점(`/judge2`)은 안 만든다 — 서버 약속을 작게 두고, 0.4초 × 2 면 충분히 빠르다.

### 2-2. 모델 명세 `model.json`

| 칸 | 새 값 |
| --- | --- |
| `name` | `nli-studio-v3` |
| `protocol` (새 칸) | `nli-v2` — 응답 꼴 판. 손님은 이 값을 기록에만 쓴다 |
| `labels` | `["support","contradict","unrelated","related"]` |
| `letters` | `["a","b","c","d"]` |
| `source_labels` | `["entailment","contradiction","neutral", null]` — 공개 NLI 에 d 에 맞는 원본 라벨이 없다 |
| `label_guide` (새 칸) | `support-v4` |
| `scores` | 문턱 셋(`nli_sure_support` · `nli_sure` · `nli_sure_related`) + blind v3 수치 |

### 2-3. 옛 손님의 합 검사 (`nli.go:131`)

지금 `readNLI` 는 a·b·c 가 다 있어야 하고 **a+b+c 가 1±0.02** 여야 받는다. 4칸 서버의 a+b+c 는 1−d 라 거의 늘 거절된다(옛 손님 × 새 서버 = 모든 답이 `nli:bad-answer`). 그래서 :

- **새 손님은 칸 수를 응답에서 읽는다.** a·b·c 는 꼭 있어야 하고 d 는 있으면 쓴다. 합 검사는 **있는 칸 전부의 합**으로 한다. 최고 칸 고르기도 있는 칸 전부에서 한다.
- 옛 손님(다른 저장소의 판올림 전 `mem`)은 `--compat3` 서버를 붙이거나, 그 저장소의 `nli_url` 을 옛 서버로 둔다.
- 판정 기록의 캐시 열쇠에 들어가는 `NLIVersion` 을 `nli-v1` → **`nli-v2`** 로 올린다. 옛 3칸 기록과 섞이지 않는다.

## 3. 자료

### 3-1. 기존 「무관」 다시 나누기

지금 스튜디오 원본(git 밖)의 무관 쌍은 줄 수로 약 1,100 이지만, 셋끼리 겹친 줄을 빼면 **595쌍**이다(2026-10-10 셈 : dev-r1 · 덧학습 train·dev · 앞 합의 셋의 무관 줄을 (근거, 주장) 으로 합침). blind v2 는 얼린 셋이라 **안 쓴다**.

| kind | 쌍 | d 가 나올 가능성 |
| --- | --- | --- |
| sscope (같은 scope 다른 기억) | 339 | **높다** — 여기서부터 본다 |
| xscope (다른 scope) | 178 | 낮다 — 표본 40 만 보고, d 가 5% 아래면 나머지는 c 그대로 |
| supersede · link · flip · same · num | 78 | 섞여 있다 — 다 본다 |

**절차** (14 소단계)

1. **불투명 id** : 쌍마다 `q0001` 꼴 새 id 를 붙이고 섞는다. 대응표는 라벨러가 안 여는 자리에 둔다. **id·파일 이름에 라벨 흔적을 남기지 않는다**(지난 판 검수 id 에 `-a/-b/-c` 를 붙여 블라인드가 깨진 일이 있었다).
2. **함정 쌍 10%** : 이미 a·b 로 확정된 쌍을 섞어 넣는다. 라벨러가 함정 쌍을 80% 아래로 맞히면 그 판을 버린다.
3. **Opus 둘이 따로** 1-1 기준 글만 보고 a·b·c·d·`cd` 중 하나를 붙인다. 서로의 답을 못 본다. 다른 파일을 열지 말라고 지시에 적는다.
4. **일치율 재기** : 둘이 같으면 그 라벨. c/d 에 대한 **Cohen κ** 를 적는다.
5. **사람 검수** : 둘이 다른 쌍 전부 + 같은 쌍 중 d 표본 30. 사람이 고른 라벨이 최종이다. 사람도 못 고르면 `cd`.
   **→ 확정(2026-10-10)으로 바뀜** : 둘이 다른 쌍은 **셋째 Opus** 가 판정하고, 사람은 표본(d 30 + fold 10)만 본다 (끝 절 3).
6. **κ 문턱 (미리 못 박음)** : κ ≥ 0.60 이면 그대로 간다. 0.40 ~ 0.60 이면 기준 글을 **한 번만** 고치고 표본 60쌍만 다시 붙여 본다. 그래도 0.60 아래면 **d 머리를 접는다**(8절 「되돌리는 법」 ②).

### 3-2. 계열(d) 씨앗

다시 나눈 595쌍에서 d 가 몇이나 나올지 모른다. 그래서 씨앗을 따로 모은다. 모두 스튜디오 기억에서 뽑고 스튜디오 원본(git 밖)에만 둔다.

| 씨앗 | 어디서 | 어림 |
| --- | --- | --- |
| C20 손검사 짝 | 2026-10-10 merge 문턱 세 바퀴 손검사 — 「맞다」 9 · 「애매」 2 · 놓친 짝 · 「틀리다」 12 | 약 40 (「틀리다」는 c 후보) |
| Near 짝 | `mem review` 의 닮은 짝 중 merge 큐에 **못 오른** 짝 (지금 약 130) | 130 |
| 덮임 짝 | `mem set --by-new` 로 덮인 옛 기억 ↔ 새 기억. 대부분 a·b 지만 「다른 길로 바꿈」은 d 다 | 약 70 |

- 씨앗도 3-1 과 **같은 절차**(불투명 id · Opus 둘 · 사람 검수)로 라벨을 붙인다. 씨앗이라고 d 로 미리 정하지 않는다.
- 보내는 글은 C19 와 같이 **정렬된 두 문장**이다(기억 본문 통째가 아니다). 서빙 때 보낼 글과 같은 꼴로 배운다.

### 3-3. 학습 자료 섞기

| 정한 것 | 내용 | 까닭 |
| --- | --- | --- |
| 기반 모델 | `nli-base-v2` (3칸, 공개 NLI 만) **그대로**. 다시 학습 안 한다 | 공개 NLI 에는 d 가 없다. 기반은 3칸으로 두고 d 는 덧학습에서만 배운다 |
| 머리 늘리기 | `train_nli.py --grow-head 4` (새) : 기반의 a·b·c 줄 가중치를 **그대로 복사**하고, d 줄은 **c 줄 복사 + 작은 잡음**으로 시작한다 | `--new-head` 는 머리를 통째로 새로 만들어 기반이 배운 a·b·c 를 버린다. d 는 c 에서 갈라져 나온 칸이라 c 에서 시작하는 것이 가깝다. `--new-head` 는 물러설 길로 남긴다 |
| 덧학습 처방 | `r1-04` 처방 그대로(4 바퀴 · ckpt-last · replay 한 : 영 1 : 1 · 갈래 가중치) — **바꾸는 것은 라벨 나누기 하나** | 「바퀴마다 한 가지만 바꾼다」. 3칸 r1-04 와 바로 견줄 수 있다 |
| replay 의 중립 | KLUE·MNLI 중립(neutral)은 **c∪d 합친 칸 손실** — 손실 = −log(p_c + p_d) | 공개 NLI 중립은 「같은 장면, 참·거짓 모름」이라 d 에 가깝고, 우리 c 는 대부분 「다른 주제」다. 어느 한 칸에 몰면 둘 중 하나를 틀리게 가르친다 |
| `cd` 쌍 | 같은 합친 칸 손실 | 라벨이 애매한 쌍을 버리지 않고 「a·b 는 아니다」만 가르친다 |
| d 가 모자랄 때 | 다시 나눈 d + 씨앗 d 가 **300쌍 아래**면 train 에만 합성 d(`synth-related`)를 넣는다 — d 의 30% 상한 · dev·blind 에는 0 · 합성 supersede 와 같은 검수 꼴 | 합성 쏠림(합성에만 있는 말버릇을 배움)을 막는다 |
| 갈래 가중치 | 넷 칸 수의 역수, 평균 1 | d 가 제일 적을 것이라 |

## 4. 판정 셋 · 자

### 4-1. 새 셋

| 셋 | 몫 | 수 (목표) |
| --- | --- | --- |
| `dev-r2` | 바퀴 · 온도 · 문턱 고르기 | 약 360 : a 90 · b 90 · c 80 · d 100 |
| **blind v3** | 판정 **한 번만** | 약 360 : a 90 · b 90 · c 80 · d 100 |
| `fold40` | 양방향 접기 확인 (기억 짝 단위) | 40 짝 : 같은 내용 10 · 한쪽 담김 15 · 겹침(담김 아님) 15 |

- **나누기** : 기억 덩이 단위(`split_pairs.py`, 길 1 설계 4-1)로 train · dev-r2 · blind v3 를 가른다. 셋 사이 기억 id 겹침 0. 갈래별 몫이 목표 ±15% 안에 들 때까지 씨앗을 올려 다시 뽑는다.
- **dev-r1 손질 먼저** : 진행상황의 「다음 셋 전에 할 것 ①②」(뺌 6 · 무관 → 지지 2 · flip 지지 차단)를 dev-r2 를 만들기 전에 한다. dev-r1 의 c 87쌍은 3-1 에 들어가 다시 라벨이 붙는다.
- **blind v2 는 다시 안 쓴다.** blind v3 는 새 기억으로만 만들고 `FROZEN-v3.sha256` 으로 얼린다. 저장소에는 SHA · 갈래 수만 적는다.
- `fold40` 은 문장 쌍이 아니라 **기억 짝**이다. 사람이 「접어도 잃는 말이 없나」를 보고 라벨을 붙인다(사람 검수 시간에 포함).

### 4-2. 자 (prereg 에 박제)

| 자 | 셈 | 기준 | 까닭 |
| --- | --- | --- | --- |
| 정확도 (3칸으로 접어서) | c·d 를 한 칸으로 합친 정확도 (최고 확률 답) | ≥ 0.85 | 옛 일(지지·반대·무관)을 잃지 않았나. 옛 자 그대로 |
| 반대 재현 | 정답 b 중 b | ≥ 0.75 | 옛 자 그대로. 넷 칸에서 반대가 d 로 새는지 본다 |
| 확신 거짓 지지 | 정답 b·c·d 인데 확신 a | ≤ 지지 아닌 쌍 × **1.5%** | blind v2 의 3/약 190 을 비율로 옮김 |
| 보류 | Unsure 비율 | ≤ 30% | 옛 자 그대로 |
| **d 재현** (새) | 정답 d 중 d (최고 확률 답) | ≥ 0.60 | merge 놓침을 줄이는 것이 목적. c/d 경계가 흐려 0.85 는 못 바란다 |
| **d 확신 정밀** (새) | 확신 d 답 중 정답 d | ≥ 0.75 | merge 큐의 「맞다」 비율. 지금 규칙 큐가 약 0.8 이다 |
| **접기 오판** (새, `fold40`) | 「담김」이라 했는데 사람은 「잃는 말 있음」 | ≤ 1 짝 | 접기는 잃는 것이 없어야 한다 |
| p95 | 한 번 묻기, HTTP 포함 | ≤ 1.0초 | 양방향은 두 번이라 짝당 약 0.8초 |

- **다 통과해야 통과다.** 정확도·반대·d 재현은 문턱 없이 재서 보류를 늘려 꾸밀 수 없다.
- 잰 뒤 문턱 · 온도 · 바퀴를 blind 결과를 보고 다시 고르지 않는다(길 1 설계와 같음).
- 미달이면 : 옛 일 자(정확도·반대·거짓 지지·보류) 미달 → **넷 칸을 꽂지 않는다**(8절 ①). 옛 일은 통과인데 d 자만 미달 → 3칸 접기(`--compat3`)로 꽂아 옛 일만 쓰고, merge 2차는 양방향 지지만으로 간다(8절 ②).

### 4-3. 문턱 고르기 (`calibrate.py`, dev-r2)

1. `nli_sure_support` · `nli_sure` : 길 1 설계 7절과 같은 법. 거짓 지지 몫은 2% → **1%** 로 낮춘다(자가 1.5% 라 여유).
2. **`nli_sure_related`** (새) : 0.50~0.99 에서 **dev 확신 d 정밀 ≥ 0.80** 을 만족하는 가장 작은 값.
3. 「담김」 문장 판정은 따로 문턱을 두지 않고 `nli_sure_support` 를 쓴다 — 거짓 지지를 막는 선이 곧 「잘못 접기」를 막는 선이다.

### 6-2. 큐마다 쓰는 법

| 큐 | 지금 | 새 판 (`--nli` 를 줬을 때만) |
| --- | --- | --- |
| contradict (C19) | 규칙 → NLI 한 방향, 확신 b 면 올림 | **그대로** |
| merge (C20) | 낱말 문턱만 (손검사 11줄, 놓침 약 5%) | 2차 거름 둘 — **보탬** : 문턱에 못 오른 Near 짝을 양방향으로 물어 확신 d 또는 「a 지만 담김 아님」이면 올린다(까닭 「NLI 계열」) · **표시** : 문턱에 오른 짝이 양방향 확신 c 면 줄 끝에 「NLI 무관」을 붙인다(지우지는 않는다 — 첫 판은 표시만) |
| **fold (C21, 새)** | 없음 | 양방향으로 「담김」이 나온 짝. 까닭에 「X 가 Y 를 담음 · 옛 쪽 / 작은 쪽 접기」 |
| retired (C18) | 덮였는데 안 접힌 기억 | **덮은 기억이 이 기억을 담는가**를 한 방향으로 묻는다. 담으면 「접어도 잃는 말 없음」, 아니면 「덮은 기억에 없는 말 N문장 — 옮긴 뒤 접는다」 |
| value (B12) | 값이 없어 보이는 기억 | **이 기억을 담는 다른 기억이 있나** — 이 기억이 낀 Near 짝을 양방향으로 물어 담는 기억이 있으면 fold 후보로 올린다 |

**「담김」 판정 (4-1 의 핵심)**

```
담김(작은 Z, 큰 W) =
    Z 의 요약 + 본문 문장(최대 5)을 하나씩 주장으로,  W 의 정렬된 문장 묶음을 근거로 묻는다
    모든 문장이 확신 a (≥ nli_sure_support)  이고
    어느 문장도 확신 b 가 아님
```

- 먼저 요약 한 문장만 두 방향으로 묻고(2번), 확신 a 가 나온 방향만 문장마다 더 묻는다. 그래서 대부분의 짝은 2번에 끝난다.
- **같은 내용(양쪽 담김)이면 옛 쪽을 접는다.** pinned 는 접기 후보로 안 올린다(retired 와 같은 까닭).
- 우선순위 : C19(모순) > C21(접기) > C20(합치기). `dropShadowed` 에 C21 을 더해, 모순에 걸린 짝은 접기에도 안 올리고 접기에 오른 짝은 merge 줄을 지운다.
- 상한 : NLI 묻기는 C19·C20·C21·retired·value 가 **한 상한**(`--nli-pairs`, 기본 100짝)을 나눠 쓴다. 짝 하나가 최대 12번이라 최악 약 100 × 12 × 0.41초 ≈ 8분이지만, 요약 2번에서 끝나는 짝이 대부분이라 보통 2분 안쪽으로 본다(짐작 — 17 소단계에서 잰다).
- **lint · gc · 훅은 그대로 LLM 0 이다.** 큐에 올리기만 하고, 접거나 다시 쓰는 판단은 AI 세션·사람이 한다.

## 8. 위험과 되돌리는 법

| 위험 | 징후 | 막이 |
| --- | --- | --- |
| **c/d 경계가 흐려 라벨이 안 맞음** | κ < 0.60 | 기준 글 한 번 고침 → 그래도 낮으면 d 머리를 접음(②). `cd` 칸으로 애매한 쌍을 dev·blind 에서 뺌 |

| d 자료 모자람 | 다시 나눈 d + 씨앗 d < 300 | train 에만 합성 d (30% 상한) |
| 합성 쏠림 | dev 의 합성 d 만 맞고 실물 d 는 틀림 | dev·blind 에 합성 0 · dev 에서 실물 d 재현을 따로 셈 |
| replay 중립과 d 가 엉킴 | 공개 NLI dev(KLUE·MNLI) 정확도가 크게 떨어짐 | 합친 칸 손실(3-3) · KLUE dev 를 바퀴마다 함께 잼(1점 넘게 떨어지면 기록) |
| 「담김」 오판으로 말을 잃음 | fold40 오판 > 1 | 접기는 큐만(자동 아님) · 문장마다 확신 a · 모순 우선 · pinned 제외 |
| 옛 손님이 새 서버를 부름 | 다른 저장소 `mem` 이 모두 `nli:bad-answer` | `--compat3` · 그 저장소 `nli_url` 을 옛 서버로 |
| 양방향 묻기로 review 가 느려짐 | `review --nli` 가 몇 분 | 요약 먼저 2번 · 공유 상한 · 판정 기록 캐시 |
| 비공개 자료 샘 | 스튜디오 셋·모델이 공개 저장소로 | `.gitignore` 그대로 · 문서엔 수와 SHA 만 · `nli-studio-v3` 는 publishable false |

- **b 가중 1.2 를 한 번 썼다 (2026-10-11, 소단계 16).** `r2-01` 의 dev-r2 반대 재현이 0.688 이라 위 줄대로 `r2-02` 를 `--class-weight-scale b=1.2` 로 한 번 더 돌렸다. 더는 안 돌린다(r2-03 없음). 결과는 `../Research/2026-10-11-R2-넷칸덧학습.md`.

**되돌리는 법**

- **① 넷 칸을 안 쓴다** : 서버를 `nli-studio-v2`(3칸) 로 다시 띄운다. 새 손님은 3칸 응답도 받으므로 `mem` 은 그대로 둔다. merge 2차·fold 는 「a 만 있는 양방향 판정」으로 줄어든다(d 보탬만 빠짐).
- **② d 만 접는다** : `nli-studio-v3` 를 `--compat3` 로 띄운다. 옛 일(지지·반대·무관)은 새 모델로, d 는 c 에 합쳐진다. merge 보탬은 「a 지만 담김 아님」만 쓴다.
- 판 이름이 다 갈려 있어(`nli-v1`/`nli-v2` · `nli-studio-v2`/`v3` · blind v2/v3) 옛 기록·캐시·셋이 섞이지 않는다. 옛 모델 폴더는 이번 판이 끝날 때까지 지우지 않는다.
