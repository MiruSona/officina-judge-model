## 0. 전제

### 0-1. 왜 이 판인가

- **B 판은 b 를 올렸지만 한국어 b 는 안 올랐다.** B4h 짝 비교에서 b 전체 +.070 인데 언어별로는 en .772 → .872, **ko .643 → .624**, mix .600 → .580 이다(B 결과 5-1). 층 전부를 넣은 B4 도 ko b −.024 였다(B 결과 4-2).
- **뿌리는 자료가 없는 것이다.** B 판 학습 층은 VitaminC(영어) 하나뿐이었다. 한국어 고침 원천은 어림의 1/4 이라 평가 몫에 다 들어가고 학습 층 D 는 1줄이었다(B 설계 3-1 A-1 실측 · mem `20261012-d3d4846c`).
- 오늘 조사 다섯이 한국어 b 원천을 찾았고, 사용자가 원천 다섯을 골랐다(0-3).

B 판은 짝 비교를 통과했고(B4h 「먹힘」) 릴리스(blind-g2 한 번)가 남았다. 결과에 따라 두 갈래다.

### 1-1. 1단계 덤프 확보 — 바로 돌릴 명령

- 저장 위치 : git 밖 **`~/.judgemodel/build/g2/kowiki/`**. 보관용 `.7z` 는 `7z/`, 처리용 `.bz2` 는 `bz2/` 아래. 받은 파일은 믿지 않는 자료라, 처리 스크립트는 `build/` 에 두고 경로를 인자로 넘긴다(그 폴더 안에서 인터프리터를 띄우지 않는다).
- 메인 PC Git Bash 에서 돈다. 먼저 빈 디스크가 10GB 넘는지 본다(`.7z` 6.14GB + `.bz2` 처리 조각 약 2~3GB).
- 위키미디어 규칙상 연결은 3개까지, User-Agent 에 연락처를 단다. `<연락처>` 는 사람이 채운다(저장소 주소 같은 공개 연락처. 개인 메일은 사람이 정할 때만).
- `kowiki-20261001-sha1sums.txt` 는 2026-10-13 에 HEAD 200 이고, `pages-meta-history*.7z` 29줄이 들어 있다.

```
df -h ~
D=~/.judgemodel/build/g2/kowiki
B=https://dumps.wikimedia.org/kowiki/20261001
UA='OfficinaJudgeModel-research/0.1 (<연락처>)'
mkdir -p "$D/7z" "$D/bz2"

# ① 대조 목록
curl -sSf -A "$UA" -o "$D/kowiki-20261001-sha1sums.txt" "$B/kowiki-20261001-sha1sums.txt"
grep -E 'pages-meta-history[0-9]+\.xml-p[0-9]+p[0-9]+\.7z$' "$D/kowiki-20261001-sha1sums.txt" > "$D/7z/history-7z.sha1"
wc -l "$D/7z/history-7z.sha1"            # 29 여야 한다

# ② 보관용 .7z 29조각 (연결 3개 · 끊기면 -C - 로 이어 받음)
cd "$D/7z" && awk '{print $2}' history-7z.sha1 | xargs -P 3 -I{} curl -sSf -A "$UA" -C - -o {} "$B/{}"
cd "$D/7z" && sha1sum -c history-7z.sha1  # 29줄 모두 OK

# ③ 처리용 .bz2 — 첫 조각은 중간 조각 하나 (3-1)
P=kowiki-20261001-pages-meta-history3.xml-p314777p379792.bz2
grep " $P\$" "$D/kowiki-20261001-sha1sums.txt" > "$D/bz2/first.sha1"
cd "$D/bz2" && curl -sSf -A "$UA" -C - -o "$P" "$B/$P" && sha1sum -c first.sha1
```

- 끝 기준 : `7z/` 29조각 sha1 모두 OK · `bz2/` 첫 조각 OK. 결과 수(조각 수 · 바이트 합 · 걸린 시간)를 `../../measure/sets-g3.md`(새로) 0절에 적는다.
- 조각이 404 면(덤프가 내려감) 받은 조각만 대조하고 메인에 알린다. 다른 미러(`other/` 의 새 형식)는 문서 수가 어긋난 버그 보고가 있어 이번 판에는 안 쓴다(자연원천 조사 2-1).

### 3-1. 한국어 위키백과 개정 이력 (양)

**얻는 법**

- `.7z` 29조각(6.14GB)을 받아 git 밖 `~/.judgemodel/build/g2/kowiki/7z/` 에 보관한다. 덤프 쪽 `sha1sums` 와 대조한다(명령은 1-1). IP 당 연결 3개 · 연락처를 단 User-Agent(위키미디어 규칙, 리브레위키 조사 2-3 에서 연락처 없는 UA 가 429 를 맞았다).
- **처리는 조각 두세 개면 된다.** 조각 하나 ≈ 편집 4,257만 / 29 ≈ 147만, 한 문장 고침 8.9%(리브레위키 조사 6절 실측 표 : 위키백과 본문 편집 중 12.9% · 판 번호당 8.9%) ≈ 13만, 수 · 이름 거르기에 5~10% 가 남으면 **조각당 후보 6천~1만 3천**(어림). 위키 몫(학습 b 500 + 평가 b 190)에 넉넉하다.
- 처리 조각은 `.bz2` 판을 따로 받아 표준 `bz2` + `xml.etree.ElementTree.iterparse` 로 흘려 읽는다(패키지 추가 없음). 위키 문법은 정규식으로 벗긴다(틀 · 각주 · 링크 · 굵게 · 표). `mwparserfromhell` 같은 패키지는 **사용자 승인 몫**이라 표준만으로 먼저 해 본다.
- 첫 조각은 `history1.xml-p1p9627`(문서 번호가 낮은 오래된 문서 · 이력이 길다)이 아니라 **중간 조각 하나**로 잰다. 오래된 문서만 보면 편집 꼴이 치우친다.

**거르는 법** (VitaminC 꼴 · 조사 「자연원천」 3절 흐름)

1. 같은 문서의 이웃한 두 판. 봇 계정 · 되돌리기 꼬리표(`mw-reverted`)가 붙은 판 쌍은 따로 묶음에 표시해 비율만 본다.
2. 위키 문법 벗기기 → 문장 나누기 → **바뀐 문장이 딱 하나 · 덧붙인 · 지운 문장 없음**.
3. 두 문장 다 15자 이상 · 글자 닮음 ≥ .6(`mine_archive revision` 과 같은 값) · 표 · 목록 조각(`list_like`) 버림.
4. **바뀐 덩이가 하나**이고 그 덩이가 수 · 날짜 · 서수 · 고유명사 · 켬/끔류 · 비교 한정어(이상 · 이하 · 넘는 · 앞 · 뒤 · 처음 · 마지막)일 때만 남긴다. 띄어쓰기 · 문장부호 · 한자 병기만 다름 → 버림.
5. **문장에 연도가 적혀 있고 그 연도까지 같이 바뀐 쌍은 d 후보로 따로 둔다**(v6 3절 「같은 수치 자리 · 때가 다름 → d」). 이 쌍이 4-1 의 d 짝 몫이다.
6. 근거 = 고친 뒤 문장, 주장 = 고치기 전 문장(`mine_archive` 와 같은 방향). 근거 앞에 「문서 제목 : 」을 붙여 「그 학교」 같은 가리킴을 풀어 준다.

**a 짝** : b 로 판정된 쌍마다 같은 고친 뒤 문장을 근거로, **고친 뒤 값을 다른 꼴로 쓴 주장**(「1985년 개교」 → 「1980년대 중반에 개교」 · 「4만 7천」 → 「4만이 넘는다」)을 로컬 모델로 만든다(3-3 과 같은 생성기). 판정을 두 번 돌게 되지만(b 판정 → a 생성 → a 판정) 버려질 b 에 a 를 만드는 낭비를 막는다.

**겹침**

- 묶음 = **위키 문서 id**. 평가 몫 문서는 문서 id 해시로 미리 떼어 둔다(예 : 해시 끝자리 0 → 평가). 한 문서는 한 셋에만 간다.
- BoolQ · KLUE-MRC 지문도 한국어 위키 문단이다. **위키 학습 쌍 × BoolQ · KLUE 평가 몫 문단**은 문장 정규화 일치 + 글자 3묶음 닮음 ≥ .8 로 빼고, 거꾸로도 본다.
- g1 · g2 의 KLUE 평가 묶음 지문과도 같은 검사를 한다.

**기대 b 와 근거**

| 단계 | 값 | 근거 |
| --- | --- | --- |
| 위키 한 문장 고침 b 비율 (거르기 전) | 19% (62쌍 중 12, 95% 범위 11~31%) | 리브레위키 조사 6절 [실물] |
| 거른 뒤 b 비율 | 25~45% (어림) | VitaminC 는 분류기 거른 뒤 35% 가 사실 고침(자연원천 2-1) · 수 · 이름 거르기가 말투 고침(40%)과 표기(40%)를 거의 다 뺀다 |
| 필요한 후보 | 학습 b 500 + 평가 b 190 + d 200 → 판정 후보 약 1,900 (b 쪽) | 남김 .36 어림 |
| a 짝 | 약 600 생성 · 판정 | b 남은 것 + 평가 몫 |

- **첫 조각 표본 200 판정이 멈춤 자리다**(흐름 차례 2). 거른 뒤 b < 15% 면 거르기 규칙을 한 번 고치고, 또 미달이면 위키 몫을 줄여 BoolQ · 씨앗으로 넘긴다.

**판정 공수** : b 쪽 1,900 + a 짝 600 = 2,500쌍 × 2.3 ≈ **Opus 5,750건**(표본 200 포함).

**함정**

- 백과사전체가 71%(리브레위키 조사 6절)라 문체가 우리 실사용과 멀다. 영어 VitaminC 도 그랬는데 en b 는 올랐다. 그래서 **위키 몫에 상한**을 둔다(4-1).
- 때가 다른 고침(「현재 인구」 해마다 고침)은 문장에 때가 안 적혀 있으면 b 로 쓴다(VitaminC 와 같음 · 덮은 결정과 같은 꼴). 적혀 있으면 5번대로 d.
- 장난 편집 · 되돌리기 쌍은 아주 깨끗한 b 라 많아지면 「대놓고 엉터리 값」만 배운다. 학습 b 의 위키 몫 중 20% 상한.
- XML 덤프는 Deprecated 라 다음 판이 안 나올 수 있다. 이번 판을 통째로 보관하는 까닭이다.

### 3-2. KoBEST BoolQ 거짓 문장 (사람 글)

**얻는 법** : HF `skt/kobest_v1` 의 `boolq` (train 3,665 · dev 700 · test 1,404, test 라벨 공개). 받기는 `mine_public.py` 에 `kobest-boolq` 모드를 더한다. **train → 학습 몫, dev · test → 평가 몫**(2-3 표).

**거르는 법**

- 근거 = 문단(1~5문장, 너무 길면 질문과 낱말이 가장 많이 겹치는 문장 두셋으로 줄임), 주장 = 질문 문장. 라벨 0 → b 후보, 라벨 1 → a 짝.
- 질문이 물음꼴(「~나요?」 · 「~인가?」)이면 **로컬 모델로 평서문만** 만든다(뜻 · 낱말은 그대로). 처음부터 평서문인 줄이 많다(공개셋 조사 2-1 [행]).
- **「한 자리만 바뀐」 규칙과의 관계** : BoolQ 거짓은 사람이 쓴 문장이라 한 자리 바꿈이 아닌 것도 섞인다. v6 판정이 b 로 본 것만 쓰고, 원인 · 결과 뒤집기처럼 갈리는 줄은 판정에 맡긴다. a 짝은 **같은 문단의 참(1) 질문**이 있으면 그것을, 없으면 거짓 줄의 바뀐 자리를 문단 값으로 되돌린 문장(로컬 생성)을 쓴다.
- 묶음 = 문단(같은 문단의 질문 여럿은 한 셋에만).

**겹침** : BoolQ 문단 × KLUE-MRC · g1 · g2 평가 지문 · 위키 평가 몫 문서(3-1)를 문장 일치 · 3묶음 닮음으로 본다. BoolQ train 과 dev · test 의 문단이 겹치는지도 본다(확인 못 함).

**기대 b** : 거짓 약 2,900 중 v6 b 50~70% → 1,500~2,000(공개셋 조사 2-1 어림). 학습 몫(train 거짓 약 1,830)에서 **b 350 을 층에 쓴다**(4-1 상한). 평가 몫(dev · test 거짓 약 1,050)에서 b 175.

**판정 공수** : 학습 후보 600(거짓) + 450(참) + 평가 후보 300 = 1,350쌍 × 2.3 ≈ **Opus 3,100건**.

**함정** : ① 「아니오」가 추론으로만 나오는 줄 → d 로 샘. ② 위키 문단이라 문체가 위키와 같다 — 위키와 합친 몫에 상한(4-1). ③ 공개 벤치마크라 바탕 모델이 봤을 수 있다(xlm-r 사전학습 말뭉치 — 확인 못 함). 짝 비교는 같은 바탕이라 상쇄된다.

### 3-3. 실물 문장 씨앗 → 한 자리 바꾼 b + a 짝 (실사용 문체)

**씨앗 고르기**

- 우리 한국어 문서 · 기억 문장 중 **값 하나 자리**(수 · 날짜 · 서수 · 켬/끔 · 이상/이하 · 처음/마지막 · 누가 냈나)가 정규식으로 잡히는 문장.
- **금지 목록 밖에서만.** g1 · g2 평가 묶음 · `blind-g2.forbid.json` 의 문서 경로 · 커밋 · 기억 id · use1 · 잣대 기억을 문서째 뺀다. 한국어 문서 대부분이 평가 묶음이라 **남는 씨앗 수는 세어 봐야 안다**(합성변환 조사 6절, 확인 못 함). 첫 일이 세기다.
- 게임 저장소 문장은 `scrub.py apply` 를 거쳐 이름을 지운 뒤에만 씨앗으로 쓴다.

**만드는 법** (합성변환 조사 1-1 · 2절)

1. 규칙이 바꿀 자리 하나를 고르고 새 값을 정한다(같은 종류 · 근거에 없는 값).
2. 로컬 모델은 **문장 다듬기만** 한다(조사 · 단위 맞추기, 「3이 → 3 이」류). 씨앗 하나에 세 줄 :
   - b : 그 자리만 바꾼 문장 (근거 = 씨앗)
   - a : 같은 값을 다른 꼴로 쓴 문장 (「90초」 → 「1분 30초」, 「4만 7천」 → 「4만이 넘는다」)
   - d : 같은 자리 · **다른 때 · 다른 조건**의 값 (「3월 120만」 → 「4월 90만」) — 숫자만 다르면 b 라는 지름길을 막는다
3. 기계 검사 : 근거 · 주장 차이가 한 덩이 · 새 값이 근거에 이미 없음 · 길이 · 물음꼴 아님 · `scrub.py`.
4. **표본 50 을 먼저 사람 대신 메인이 읽는다** — 한 자리만 바뀜 · 자연스러움 · 칸 뜻 맞음 셋 다 맞은 비율 ≥ 80% 면 전량. 미달이면 다른 모델(Qwen3.6 ↔ Gemma 4)로 50 을 다시, 둘 다 미달이면 씨앗 길을 접는다.

**모델** : 로컬 Qwen3.6(`agent` 프로필, 이미 실측된 판)을 먼저 쓴다. Gemma 4 는 미니PC 에서 안 띄워 본 판이면 게임 서버 규칙(`Docs/Guide/미니PC.local.md`)상 처음 띄우기 전에 메모리를 본다. 8-2 ④ (Qwen3.6 먼저로 확정).

**기대 b** : 씨앗 450 × b 남김 .70~.85 ≈ b 315~380 · a · d 짝 각 약 300(어림, 합성변환 조사 결론 표). **층에는 합성 b 상한(학습 b 의 25%) 안에서만** 넣는다(4-2). 0-3 표의 「1,000 안팎」을 450 씨앗으로 줄인 까닭이 이 상한이다.

**판정 공수** : 1,350쌍 × 2.3 ≈ **Opus 3,100건**.

**함정**

- **「대놓고 어긋남」** : 부정어만 넣기(「~하지 않는다」)는 쓰지 않는다(ㄴ 의 실패, 합성변환 조사 5절). 자리 목록을 값 하나 자리로 묶고 d 짝을 같이 넣는다.
- 생성기 라벨을 믿지 않는다. 판정은 v6 두 판, hint 와 다른 칸이면 **짝째(세 줄) 버린다**.
- 출처 판별기(`rulers.py source --diagnostic`, 씨앗 b vs dev-cmp-g3 ko 실물 b)가 **.65 를 넘으면 씨앗 몫을 층에서 뺀다**(진단 3-2).

### 3-4. MIT 한국어 CS · 기술면접 저장소 고침 커밋 (실사용 문체)

**얻는 법** : 개발자커뮤니티 조사 2-4 표의 MIT 저장소 5곳(커밋 합 약 3,000)을 clone 해 `mine_archive.py revision --repo 이름=<경로>` 를 그대로 돌린다. 라이선스 없는 저장소 넷은 뺀다. 저장소마다 LICENSE 를 열어 고지문을 `~/.judgemodel/build/g3/mit/NOTICES.txt` 에 모으고, 데이터 카드에 싣는다.

**거르는 법** : `revision` 의 거르기(한 줄 고침 · 닮음 ≥ .6 · 15자 이상 · 이름 바꾸기 · 코드 덩이) 그대로. 더해서 바뀐 덩이가 하나인 줄을 먼저 판정에 보낸다. 근거 = 고친 뒤 · 주장 = 고치기 전. a 짝은 b 로 남은 것만 로컬 생성.

**겹침** : 묶음 = 저장소 + 파일. 같은 문서가 저장소 여럿에 복사돼 있을 수 있어(스터디 저장소끼리 베낌) 글 겹침 검사를 저장소 사이에도 돈다.

**기대 b** : 표본 줄 쌍 약 45 중 b 4(9%) → 5곳 b 100~250, 최대 400(개발자커뮤니티 조사 2-4 어림). **평가 몫 70(2-3 표)을 먼저 떼고** 남는 30~180 을 학습에.

**판정 공수** : 줄 쌍 800 + a 짝 100 = 900쌍 × 2.3 ≈ **Opus 2,100건**.

**함정** : ① MIT 고지문 — 빠뜨리면 라이선스 위반. ② 오타 · 말투 고침이 대부분이라 b 수확이 적다. ③ 면접 정리 글은 「~는 ~이다」 정의문이 많아 실사용(결정 · 상태 글)과도 조금 다르다.

### 3-5. KLUE-MRC 「답 있는 질문」 답 바꾸기 (보조)

**얻는 법** : g1 `klue-mrc` 후보(22,406)에서 **지문이 답을 글자로 적는 질문**만. 답이 날짜 · 수 · 사람 · 곳 · 서수인 질문으로 좁힌다(「무엇을 했나」류는 d 로 샌다, 합성변환 조사 1-2).

**만드는 법** : 근거 = 참 답이 든 문장 1~2. b 주장 = 질문 + **같은 지문 속 같은 종류의 다른 값**을 평서문으로(QACG 꼴). a 짝 = 질문 + 참 답 평서문. 평서문 만들기는 로컬 모델(지금 `attach-rewrite` 는 Opus 로 돌았다 — 이번엔 생성은 로컬 규칙을 따른다).

**겹침** : g1 · g2 에 쓴 KLUE 지문 묶음을 문서째 뺀다(blind-g2 의 a 42 · c 40 포함). 「g1 KLUE 다시쓰기에 쓴 줄」 금지 그대로.

**기대 b** : 남김률 .70~.85(합성변환 조사 1-2 어림 · QACG 바꾼 답이 사실 맞았던 것 2%). 학습 b 150 · 평가 b 65.

**판정 공수** : 후보 b 300 + a 250 + 평가 100 = 650쌍 × 2.3 ≈ **Opus 1,500건**.

**함정** : 뉴스 · 위키 글꼴이라 실사용과 멀다. 같은 지문의 다른 값이 실제로 「둘 다 참일 수 있는 자리」(참여한 사람 중 하나)면 d — 판정에 맡긴다.

## 4. 층 구성 — `train-g3-ko`

### 4-1. 원천별 몫과 상한

| 원천 | b | a | d | 쌍 | b 몫 상한 | 까닭 |
| --- | --- | --- | --- | --- | --- | --- |
| 위키 | 500 | 500 | 200 | 1,200 | **ko b 의 40%** | 양으로 다 덮지 않게. 백과사전체 · 위키 꼴 지름길을 막는다 |
| BoolQ | 350 | 350 | 0 | 700 | 위키와 합쳐 **65%** | 같은 위키 문단 문체라 위키와 묶어 센다 |
| 실물 씨앗 | 280 | 280 | 250 | 810 | **학습 b 전체의 25%** (합성 상한) | 진단 3-2 |
| MIT | 30~180 | 같은 수 | 0 | 60~360 | 남는 만큼 | 평가 먼저 |
| KLUE 답 있는 질문 | 150 | 150 | 0 | 300 | 합성 상한에 같이 셈 | 바꾼 답은 만든 주장이라 합성으로 센다 |
| **합 (어림)** | **약 1,300** | **약 1,300** | **약 450** | **약 3,050** | | |

- **d 짝을 넣는 까닭** : B4(층 800 · d 0)가 d 를 깼다(아래끝 −.041). 층을 키우면 d 비율이 더 묽어진다. B2 학습 d 를 약 550(12.5%, B 설계 7절 어림)으로 보면, d 없이 3,050 을 더할 때 550 / 7,850 = 7.0% 로 떨어지고, d 450 을 넣으면 (550 + 450) / 7,850 ≈ 12.7% 로 B2 비율을 지킨다(어림). d 몫은 위키 「연도까지 바뀐 고침」과 씨앗 d 짝이 진다.
- 합성 몫 셈 : 학습 b = 기준 처방 b(갈래 ① 767 + 199 = 966 · 갈래 ② 767) + 층 1,300 ≈ 2,270(①). 씨앗 280 + KLUE 150 = 430 → **19%** ≤ 25%. 갈래 ② 면 2,070 중 21%.
- 짝 규칙은 train-g2-b 와 같다 : 같은 씨앗의 b · a(· d)가 **판정이 hint 와 모두 같을 때만** 짝째 넣는다(`pick_contrast.py keep-pairs` 를 세 줄 짝으로 넓힘 — 공수 ⑨).

## 5. 짝 비교와 릴리스

### 5-1. 조건 · 씨앗 · 비교

- K = 기준 처방 그대로 + `--train` 에 `train-g3-ko` 하나 더. 씨앗 [1..5] · 결정 모드 · 시작점 `runs/base-2/ckpt-best`.
- 비교 : `compare.py --protocol measure/protocol-g3.json --set dev-cmp-g3 --base <B4h|B2>=… --new K=… --by domain,lang` → 2-2 관문.
- `protocol-g3.json` 을 새로 만든다(protocol-g2 는 안 고친다, `hash_rule`). 바뀌는 칸 : `sets`(g3 해시 셋) · `pair_gate`(base 이름 · 목표 `lang_b_recall ko` · 지킴 · 경보) · `release_gate`(`set: blind-g3`, `ref_model`, ko b 자). 첫 짝 비교 전에 커밋한다.

### 5-2. 판정

| 결과 | 다음 |
| --- | --- |
| 먹힘 (목표 · 지킴 다 통과) | 릴리스(5-4) |
| 같다 (목표 못 미침) | 접음. 결과만 적고 길 C 로 |
| 지킴 깨짐 | **K-h 한 번**(5-3) |
| 판별 불가 (기준선 ko b 반폭 > .04) | 메인 판단 — 평가 셋을 더 넓힐지 |

### 5-3. 미리 정한 대체 판 — K-h

- **K-h = 층을 원천별 · 짝째 절반 무작위**(고정 씨앗). B4h 와 같은 꼴이다. 지금 정해 두어 결과를 보고 고르는 꼴을 피한다.
- 다른 대체(원천 하나 빼기 · d 짝 늘리기)는 안 둔다. K-h 도 깨지면 접는다.

### 5-4. 릴리스

- 릴리스 판 = K(또는 K-h) 다섯 중 dev-cmp-g3 **ko b** 재현이 평균에 가장 가까운 판(`release_pick` 의 metric 을 바꿈). 온도 · 문턱은 dev-cal-g3 로.
- `measure/prereg.py --protocol measure/protocol-g3.json` 로 박제 → blind-g3 에 **한 번**. 같은 쌍에 ref(v1.2.0 또는 v1.1.0)도 잰다.
- 잣대 3쌍 b 확률 · use1 ② 놓친 b 7쌍을 결과표에 같이 싣는다. 관문이 아니다.
- 통과해도 8092 교체는 사용자가 정한다. 데이터 카드에 원천별 라이선스 · MIT 고지문 · 위키 판 · BoolQ 출처를 싣는다.
