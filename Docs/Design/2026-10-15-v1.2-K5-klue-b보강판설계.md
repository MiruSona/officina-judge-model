## 결론

**K4 처방에 작은 층 하나(train-g4-klb, 약 360줄)를 더한 K5 를 K 와 짝 비교한다.** 층은 진단 4절 선택지 **(가)와 (나)를 합친 꼴**이다 — KLUE 글에서 「같은 자리 다른 값 = b」와 「그 자리를 말 안 함 = d」를 **같은 근거 위의 짝**으로 가르치고, KLUE 의 d 몫은 늘리지 않는다. 몸통은 이미 평서문으로 바꿔 둔 klue-answered 풀(qa-alt b · qa-true a)이라 **새 글 생성이 없다.** klue-mrc b · d 짝(약 80줄)은 새 평서문 바꾸기가 있어야 해서, 그 길을 사용자가 고른다(9절 ①).

학습 전에 **점검표 도구 T1~T3** 을 `build/assemble_g4.py check` 에 붙이고, K2 · K3 · K4 처방에 되돌려 돌려 **울려야 할 자리에서 울리는지**(수용 시험)를 본 뒤에만 층을 조립한다. 자(protocol-g6 의 목표 · 지킴 · 경보 · 출시 관문)는 그대로다.

| 통과 기준 | 무엇 |
| --- | --- |
| ① | T1~T3 수용 시험 — 3-5 표의 자리가 다 울리고, K4 에서 T2 는 조용 |
| ② | K5 처방 점검표 — 빈칸 0 · T1 미허용 경고 0 · T2 새 경고 0 |

## 0. 왜 · 목표 · 기준 (판 규칙 1-1 · 0-1 · 0-2)

- **왜** : K3 · K4 가 같은 자리(klue-mrc b 19쌍 · klue-answered b 20쌍)에서 b_recall@ko 지킴을 깼다. 진단은 잃은 b 표의 **90% 가 d 로 갔다**고 셌다(진단 1절 : K4 29표 중 26 · K3 32표 중 30). 그 밖 245쌍의 b 는 .802 → .803 으로 안 움직였다.
- **목표가 어디서 왔나** : v1.2 목표는 공개 범용 모델이고, 맞는 자는 공개 원천 자다(판 규칙 0-1). 이번 목표 칸은 그 자 안의 지킴 하나(b@ko)를 지키는 것이다. 실사용(mem) 고치기로 목표를 바꾸지 않았다.
- **기준 모델** : K(K-s1~5, 출시 안 함). 판 규칙 0-2.

| 자 | 기준 | 앞 판과 |
| --- | --- | --- |
| **관문 목표 `c_recall@ko`** | 평균 차 ≥ +.03 · 아래끝 > 0 (protocol-g6 그대로) | K4 와 같음 |
| **설계 목표 c@ko 유지** | K 대비 평균 차 **+.10 이상**(K4 는 +.121) — 판정은 안 바꾸고 결과표에 적는다 | 새 줄 (9절 ②) |
| **지킴 `b_recall@ko`** | 아래끝 ≥ −.03 — **이번 판이 겨누는 자** | 같음 |
| 지킴 나머지 여덟 · 경보 여덟 | protocol-g6 그대로 | 같음 |
| 보고만 (판 규칙 1-1) | use1 잣대 3쌍 b 확률 · 놓친 b 7쌍 · ② c → b (K · K4 · K5 열) | 새로 다시 실음 |
| 보고만 (새) | klue-mrc · klue-answered 원천 × 칸 재현 · klue d 재현(R2 역풍 감시) · T3 약한 칸 표시 | 더함 |

- 관문 목표를 +.10 으로 올리지 않은 까닭 : 그건 자를 바꾸는 일이다(판 규칙 4-1). +.10 은 「K4 이득을 잃지 않았나」를 보는 설계 기대로만 둔다.

## 2. 멈춤 규칙 점검 (판 규칙 1-3)

- klue b@ko 는 **K3 · K4 두 판 연속** 같은 원천 × 칸에서 깨졌다 → 멈춤 규칙에 걸렸다.
- 그래서 K4 뒤에 학습 판을 띄우지 않고 진단(혼동표 · 원천 × 칸 · 새로 틀린 쌍 · 쌍 읽기)을 먼저 했다(진단 문서, 학습 0).
- **이 판은 그 진단 결과로 설계된 판이다.** 진단의 자료 셋(d 로 감 · 겉꼴 같음 · 작은 표본)이 4절 층 고르기의 근거다.
- K5 가 또 같은 자리에서 깨지면 세 판 연속이다. 그때는 7절대로 진단 → 사용자이고, 같은 꼴 판을 다시 열지 않는다.

## 3. 점검표 도구 T1~T3 (판 규칙 2-2 ~ 2-4)

**셋 다 `build/assemble_g4.py` 에 붙는다.** 지금 `check --recipe` 가 빈칸 검사(2-1)를 하는 자리다. 새 파일은 만들지 않는다. T3 은 `measure/compare.py` 표에도 한 칸 더한다. 학습 전에 셋이 다 돌아 있어야 한다.

### 3-1. 공통 — 입력 · 출력 · exit

| 칸 | 값 |
| --- | --- |
| 입력 | `--recipe <학습 파일 …>`(새 판 처방, 얼린 층 파일) · `--base-recipe <파일 …>`(**기준 K 처방** = train-r2 · train-g1-arch · train-g3-ko, T1 기준) · `--prev-recipe <파일 …>`(앞 판 K4 처방, 보고만) · dev-cmp-g4(지금 `check` 가 읽는 셋) · `--ack <json>`(허용 목록) |
| 출력 | 기본은 사람이 읽는 표, `--json` 이면 결과 JSON. JSON 에는 `drift`(T1) · `bands`(T2) · `weak`(T3) 칸. 각 칸은 `rows`(표) · `flags`(경고) · `acked`(허용됨) · `unacked`(허용 안 됨). 쌍 본문은 안 찍는다. 경고 줄 수는 stderr 에 한 줄씩 |
| exit | 0 = 다 통과 · **1 = 빈칸(zero) · T1 미허용 · T2 새 경고 중 하나라도** (얼리기 막음) · 2 = 파일 없음 · 허용 목록이 금지 칸을 허용하려 함. `--draft` 면 적기만 하고 exit 0 (수용 시험용) |
| `cells` 하위 명령 | 같은 인자를 받아 홀로 돈다(지금 꼴과 같음) |
| `--recipe` 없이 돌린 `check` | 옛 출력 바이트 그대로 |

- **허용 목록(`--ack`)** 은 「그대로 갈 까닭을 설계 문서에 적는다」(판 규칙 2절)를 파일로 만든 것이다. 꼴 : `[{"tool": "T1", "domain": "klue-answered", "cell": "c", "dir": "up", "why": "c@ko 목표 — K2 이래 의도한 오름", "design": "<설계 문서> 절"}]`. 자리 `measure/cell-ack-g7.json`(git 안 · 쌍 본문 없음). sha 를 protocol-g7 `cell_check` 에 적는다.
- **허용 못 하는 칸** : T1 의 **b 칸 내림**. b 는 언어로 나눈 지킴(b@ko · b@en)이 걸린 유일한 칸이고 두 판 연속 깨졌다. 허용 목록에 넣으면 exit 2.

### 3-2. T1 — 원천 안 칸 몫 이동 (판 규칙 2-2)

| 칸 | 값 |
| --- | --- |
| 셈 | 원천(`domain`, 없으면 mem)마다 칸 몫 = 그 칸 줄 ÷ 그 원천 줄. 칸 글자는 지금 `cell_key` 그대로 |
| 기준 | **기준 처방(K)** 에 그 원천이 있으면 K 몫과, **없으면 dev-cmp-g4 몫과** 견준다. 기준에 원천이 있는데 칸이 없으면 몫 0 |
| 문턱 | **|차| > .20** (조사 후보 값 그대로) |
| 보고만 | 앞 판(K4) 몫과의 차 — 판 사이에 갑자기 바뀐 것을 본다 |
| 함수 | `cell_drift(recipe_rows, base_rows, dev_rows, max_shift=.20)` |

- **기준을 앞 판이 아니라 K 로 둔 까닭** : 짝 비교의 지킴이 K 와 견준다. 손셈으로 보면 K4 klue-answered b 몫은 앞 판(K3 .335) 대비 −.03 이라 안 울리고, K 대비로만 −.305 로 울린다(10절). 앞 판 기준이었으면 K4 를 못 잡았다.
- **dev 몫을 쓰는 까닭** : K 에 없던 원천(VitaminC · klue-mrc · proposals)은 견줄 몫이 없다. K3 의 「VitaminC = d 하나」(d 몫 1.0, dev .227)를 이것이 잡는다.

### 3-3. T2 — 겹침 구간별 칸 몫 (판 규칙 2-3, 꼴을 바꿈)

| 칸 | 값 |
| --- | --- |
| 셈 | 언어(ko · en)마다, 근거 · 주장 겹침(`layer_g4d.overlap`)을 네 구간(`layer_g4d.bin_of`, 가름 .1 · .2 · .35)으로 나누고, **구간 안 칸 몫**을 학습과 dev 에서 따로 센다 |
| 문턱 | 학습 몫 − dev 몫 **|차| > .20** · 학습 쪽 그 구간 **100줄 이상**만 |
| 새 경고 | **기준 처방(K)에서도 이미 울리는 칸은 「기준선부터」로 보고만** 하고 막지 않는다. K 에 없던 경고만 exit 1 |
| 함수 | `band_drift(recipe_rows, dev_rows, base_rows, edges=(.1, .2, .35), max_shift=.20, min_n=100)` |

- **판 규칙 2-3 의 「같은 원천 × 칸끼리 겹침 분포 차」에서 꼴을 바꾼 까닭** : 원천 안 칸끼리의 겹침 차는 dev 에도 똑같이 있다. 손셈으로 kowiki 는 학습 c .00 · d .86, dev 도 c .00 · d .89 다(10절). 그래서 「원천 안 차」로 울리면 K4 처럼 괜찮은 처방에서도 울린다. K2 의 문제는 「겹침 낮음 = c」가 **dev 보다 학습에서 훨씬 셌던 것**이라, 학습 몫을 dev 몫과 구간별로 견주는 꼴로 바꿨다.
- **100줄 바닥 · 「기준선부터」 까닭** : K 는 영어 학습이 작아(구간당 58 · 83줄) 영어 구간 넷이 울린다. 바닥 100 을 두면 K 에서는 en 구간 3 a(+.24, 114줄) 하나만 남고, 그것은 기준선부터라 막지 않는다.

- T3 수용 : dev-cmp-g4 에서 **klue-mrc b 19 · klue-answered b 20** 이 약함으로 뜨고, b@ko 지킴 쌍 284 중 39(13.7%)가 약한 칸이라 적혀야 한다. 다른 약함 칸 : klue-answered a 14 · d 4 · kobest-boolq d 8 · kowiki a 5 · c 24 · d 25 · mit-cs a 21 · proposals a 28 · b 1.
- 이 표대로면 점검표는 K2 · K3 · K4 셋 다 학습 **전에** 막았다. K2 의 d 무너짐은 T2 가 겨우 잡는다 — 「잡힌다」고 믿을 만큼은 아니다(8-2 위험 표).

## 4. 층 설계 — train-g4-klb

### 4-1. (가) · (나) 견주기

| 안 | 무엇 | 근거 (진단) | 약점 |
| --- | --- | --- | --- |
| (가) b · d 짝 | 같은 근거로 「같은 자리 다른 값」(b)과 「그 자리를 말 안 함」(d)을 짝으로 | 잃은 b 의 90% 가 d · klue-mrc b · d 겉꼴 같음(hint d 18/19 · 123/133) · 겹침으로 못 가름(1절) | d 줄도 더하니 d 몫이 늘 수 있다 |
| (나) d 몫 맞추기 | KLUE d 몫을 줄이거나 b 몫을 되돌린다 | klue-answered b 몫 .61 → .30 | d 를 줄이면 klue-mrc d 재현(.395 → .686)이 다시 떨어진다(R2 역풍) |
| **합침 (고름)** | **b 를 더해 몫을 되돌리고(나), 그 b 를 같은 근거의 a · d 와 짝으로 넣는다(가). d 는 짝으로만 더하고 KLUE d 몫은 K4 수준 그대로** | 둘의 근거를 다 쓴다 | 층이 작아(약 360줄) 효과가 작을 수 있다(P1) |

- **d 를 줄이지 않는 까닭** : klue-mrc d 몫은 K4 에서 .489 로 dev(.487)와 같다. 이미 맞는 칸을 깎으면 K4 가 얻은 d +.165 를 내준다.
- **c 를 줄이지 않는 까닭** : 처방에서 무엇을 빼면 「한 판에 바꾸는 것」이 둘이 된다(원인 조사 대책 8). K4 처방은 얼린 채 두고 **더하기만** 한다.

### 4-3. 쌍은 어디서 뽑나

| 몫 | 꼴 (짝) | 풀 | 새 판정 | 생성 |
| --- | --- | --- | --- | --- |
| klue-answered b 200 · a 80 | **세 줄 짝** — 같은 질문의 qa-alt(b) · qa-true(a), 그리고 그 질문의 removed d 가 K4 층 d 60 에 이미 있으면 그 질문부터 고른다(b · d 짝을 새 d 없이 만듦). 나머지 b 는 a 짝 80 · 홀로 b 순서 | 메인 PC `~/.judgemodel/build/g3/klue/answered-rw.jsonl` 학습 쪽(qa-alt 2,167 · qa-true 2,167, 이미 평서문 `claim_rewrite`). K 처방 · train-g4-c 문단 · 금지(K3 설계 4-4 · blind-g4 forbid · dev-cmp-g4) 뺌 | 후보 약 310(b 225 · a 85) → 약 700건 | **없음** |
| klue-mrc b 40 · d 40 | **같은 문단의 b · d 짝** — KLUE 「답 없는 질문」(unanswerable) 평서문을 판정해, b 로 정한 줄마다 같은 문단에서 d 로 정한 줄 하나를 짝으로 넣는다. 짝 없는 b 도 넣고, 짝 없는 d 는 버린다 | 메인 PC `~/.judgemodel/build/g1/klue-mrc/candidates.jsonl` 학습 쪽 unanswerable 5,423(평서문 없음) 중 문단에 질문이 둘 이상인 것 · g1 이 이미 바꾼 500 · 예약 688 은 뺌 | 후보 약 300 → 약 700건 | **평서문 바꾸기 300** (가짜 답 넣기, g1 45-다2 와 같은 꼴) — 길은 9절 ① |

- 판정 : v6 기준(`../Guide/라벨기준support-v6.md`) · Opus 서브에이전트 판정자 둘 + 갈림 셋째 · `label_batches.py make --mode train` · 함정 10% · 일치 .90 아래면 멈춤. 판정자에게 hint · 짝 표시는 안 보인다(`map/` 에만). K4 의 정함 규칙 그대로 — 다른 칸으로 정해진 줄은 그 칸 목표가 비었을 때만 넣는다.
- 남김률 어림 : klue-answered b .90 · a .975(sets-g4 2절 KLUE 평가 몫 실측). klue-mrc unanswerable 의 b 몫 .13(P4 어림 — 실제 .28).
- **Opus 판정 합 약 1,400건**(K4 3,206 의 절반 아래). 어림의 1.5배를 넘으면 메인에 알린다(K 설계 6절 규칙).
- klue-mrc 몫이 모자라면 : 300 판정에서 b 가 20 아래면 그 몫은 「있는 만큼」 넣고 멈추지 않는다. klue-answered 몫만으로도 T1 은 통과한다.
- **다음 판 손질 (10-15 리뷰)** : klue-mrc 짝 고르기가 욕심 순서라 b 가 앞에서 자리를 다 써 d 짝이 37 에 그쳤다(`mrc_b_over` 43). 다음 판은 묶음당 b 하나 + 짝 있는 b 먼저, 둘째 판에 나머지 b. 얼린 층은 그대로 둔다.
