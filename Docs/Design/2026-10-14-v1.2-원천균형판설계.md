## 0. 결론

**K 처방에 「원천마다 a · b · c · d 가 다 든」 층 하나(train-g4-bal, 약 3,200줄)를 더한 K4 를 K 와 짝 비교한다.** 층의 재료는 대부분 이미 판정이 끝난 줄이다(v6 줄 약 2,150 · v5 줄 약 790). 새로 판정하는 몫은 BoolQ d · klue-answered d · MIT b · c · d 약 280줄과, 우리 글 archive 의 「한 자리 바꾼 b」 씨앗 300줄뿐이다. v5 줄은 표본 200줄만 v6 로 다시 판정해 칸이 바뀐 비율이 10% 아래면 그대로 쓴다. 층 조립 검사(`assemble_g4.py check`)에 **원천 × 칸 빈칸 검사**를 넣어 「학습 전체에서 0 인데 dev-cmp-g4 에 있는 칸」이 하나라도 있으면 얼리기를 막는다. 지금 K 처방에 걸면 16칸이 울려야 하고(검사의 시험), K4 처방에서는 0칸이어야 한다. 셋은 g4 그대로, 기준은 K, 짝 비교 자(목표 c@ko +.03 · 지킴 아홉)와 출시 관문은 앞 판과 같다. 짝 비교가 「먹힘」이면 blind-g4 를 이번 판 마지막에 한 번 연다. 게임 저장소 기억은 이번 판에서 뺀다.

**통과 기준** : ① 빈칸 검사 K → 16칸 · K4 → 0칸 ② v5 표본 변화율 판정이 규칙대로 끝남 ③ 짝 비교 K → K4 「먹힘」(protocol-g5 와 같은 목표 · 지킴) ④ blind-g4 출시 관문(K2 설계 2-2 그대로).

## 1. 층 구성 — train-g4-bal

### 1-1. 짜는 규칙

1. **원천 하나의 학습 전체 줄 수(K 처방 + 새 층)를 먼저 정한다.** 공개 원천은 앞 판 층 크기(B 800 · c 1,300 · d 750)를 넘지 않게 원천당 300~800 으로 잡는다.
2. **칸 몫 = 원천 줄 수 × dev-cmp-g4 의 그 원천 칸 비율.** 단 dev 에 있는 칸은 **원천 줄 수의 10% 를 바닥**으로 둔다 — 원천 사전확률이 너무 기울어 「이 원천이면 이 칸」 지름길이 서지 않게(원인 비교 4절 (가) 위험 칸).
3. **재료가 모자라면 있는 만큼만** 넣고 「모자람」을 요약에 적는다. 재료는 v6 → v5(실물만) → 새 판정 차례로 쓴다.
4. **합성 v5 줄(가5, 908줄)은 안 쓴다** — R8. jira · minicheck 은 dev 에 없어 안 넣는다.
5. **축의 양쪽을 짝으로 넣는다(R2).** b 는 같은 「한 자리 다름」의 a 짝과(VitaminC 는 B 층 a · b 짝째, archive 는 씨앗 세 줄째), c 는 같은 근거 묶음 · 같은 겹침 구간의 d 와 같이 뽑는다. 겹침 셈은 `layer_g4d.overlap` 을 그대로 쓴다.
6. 근거 묶음당 칸마다 2줄 · 같은 원천 안에서만 · 금지 목록은 K3 설계 4-4 그대로(+ train-g4-bal 자신의 쌍 열쇠 중복 막기).

## 2. v5 표본 재판정

### 2-1. 무엇을 뽑나

- **모집단** = 새 층이 쓸 v5 실물 칸 여덟(가4 · 나4, 합성 가5 와 jira · minicheck 은 뺌) : VitaminC c 81 · klue-mrc a 233 · b 27 · c 257 · proposals a 127 · b 13 · c 712 · d 450 = **1,900줄**.
- **층별 뽑기 200줄** — 칸마다 15줄 바닥(그보다 적으면 전부), 나머지는 칸 크기에 비례. 고정 씨앗 무작위.

| 칸 | VitaminC c | klue-mrc a | b | c | proposals a | b | c | d | 합 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 모집단 | 81 | 233 | 27 | 257 | 127 | 13 | 712 | 450 | 1,900 |
| 표본 | 20 | 25 | 15 | 30 | 20 | 13 | 45 | 32 | **200** |

### 2-2. 판정과 셈

- **판정 주체** : Opus 서브에이전트 판정자 둘(j1 · j2) · 갈림은 셋째. v6 기준(`../Guide/라벨기준support-v6.md`) · `label_batches.py make --mode train` · 함정 10%. **판정자에게 v5 라벨을 보여 주지 않는다**(`map/` 에만 둔다).
- **「바뀜」** = v6 정함 칸 ≠ v5 칸. 정함이 cd · drop · need-third 로 끝난 줄도 바뀜으로 센다(쓸 수 없게 된 줄이므로).
- **변화율** : 칸별 비율 r_h = 바뀜 / 표본. 전체는 칸 크기로 무게를 단 값 R = Σ (N_h / 1,900) × r_h. 두 값과 칸별 Wilson 95% 위쪽 끝을 결과에 적는다(표본이 15~45줄이라 칸별 값은 거칠다).

### 2-3. 판정 규칙

| 결과 | 그때 |
| --- | --- |
| **R < 10% 이고 r_h 가 모두 < 10%** | v5 줄을 그대로 쓴다. 표본 200줄은 v6 칸으로 갈아 끼운다 |
| R < 10% 인데 어떤 칸 r_h ≥ 10% | **그 칸 종류만** 모집단 전부 재판정 (아래) |
| R ≥ 10% | r_h ≥ 10% 인 칸 종류를 모두 재판정. 셋 이상이면 메인에 알린다 — v5 를 쓰는 길 자체를 다시 볼 자리 |

- 「칸 종류 전부 재판정」 = 그 칸의 모집단 줄 전부(예 proposals c 이면 712줄)를 v6 두 판으로 다시 본다. 다시 판정한 줄은 v6 칸을 따른다 — 칸이 바뀐 줄은 바뀐 칸의 재료로 옮겨 1-2 목표 안에서 쓴다.
- 최악(여덟 칸 다)은 1,900줄 · Opus 약 4,400건(쌍당 2.3)이다. 통째(5,723줄)의 3분의 1이다.
- 표본 칸별 바닥 15 는 「10% 넘었나」를 겨우 가르는 크기다(15줄 중 2줄 바뀌면 13%). 칸별 판정은 보수적으로 둔다 — 넘으면 다시 판정한다. 비용이 작아서다.

### 3-2. archive b 씨앗 (K 설계 3-3 의 「한 자리 바꾼 b」)

- **씨앗 고르기** : 우리 한국어 문서 중 train-g1-arch 와 같은 문서 갈래(아카이브 글) · 금지 목록(g1~g4 평가 묶음 · `blind-g3/g4.forbid.json` · use1 · 잣대) 밖 · **K 의 seed 씨앗 문장과 다른 문장**. 값 하나 자리(수 · 날짜 · 서수 · 켬/끔 · 이상/이하 · 처음/마지막 · 누가)가 잡히는 문장. **게임 저장소 글 · 기억은 안 쓴다**(0-1).
- **근거 꼴이 K 의 seed 와 다르다.** K 의 seed 는 근거 = 씨앗 문장 하나였다. 이번엔 **근거 = 씨앗 문장이 든 아카이브 문단**(train-g1-arch 와 같은 꼴), 주장 = 바꾼 문장, 도메인 `archive` · `form` `seed-b` · `seed-a` · `seed-d`. 그래야 dev 의 archive b 와 겉모양이 같다.
- **만드는 법** : 씨앗 하나에 b(그 자리만 바꿈) · a(같은 값 다른 꼴) · d(같은 자리 · 다른 때 · 다른 조건) 세 줄. **llama 가 내려가 있으니 로컬 다듬기 없이 `seed_contrast.py make` 의 규칙 초안을 그대로 쓴다.** 조사 맞추기(「3이 → 3 이」)는 규칙 표로 한다. 기계 검사(`seed_contrast.py check`) · `scrub.py`.
- **표본 50 을 메인이 읽는다** — 한 자리만 바뀜 · 자연스러움 · 칸 뜻 셋 다 맞은 비율 ≥ 80% 면 전량. 미달이면 씨앗 길을 멈추고 메인 판단(llama 가 올라올 때까지 미루거나 archive b 를 30 안팎으로 줄임).
- **판정** : v6 두 판 · 셋째. 짝 규칙은 K 설계 4-3 과 같다 — 세 줄이 다 hint 와 같을 때만 짝째 넣는다.
- **수** : 목표 b · a · d 각 100. 짝째 남김률 어림 .6(K 의 씨앗 d 가 셋째에서 많이 빠졌다) → **씨앗 약 170 · 후보 510줄.** 씨앗 풀이 170 보다 적으면 있는 만큼, 100 아래면 메인에 알림.
- **출처 판별기**(`rulers.py source --diagnostic`, 씨앗 b vs dev-cmp-g4 archive b)는 보고만 한다. K 때 .937 이었는데 그대로 둔 판단(K 설계 「결정」 표)을 잇는다.

### 3-3. scrub · 금지 · 겹침

- 모든 새 줄 : `scrub.py` 0건 · K3 설계 4-4 의 금지 그대로(blind-g3 · blind-g4 forbid · dev-cmp-g4 · g4 평가 후보 · 옛 평가 문단 색인).
- v5 · v6 기존 줄도 조립 때 `recheck` 를 다시 돈다. 채움 조사가 겹침을 금지 열쇠로만 봤기 때문이다(채움 조사 7절 첫 줄).

## 4. 빈칸 검사

### 4-1. 코드 자리

| 자리 | 무엇 |
| --- | --- |
| `build/assemble_g4.py` 새 함수 **`cell_gaps(train_rows, dev_rows, thin=10)`** | 학습 줄과 dev 줄을 (원천, 칸)으로 세어 빈칸 · 적음 · dev 없음을 돌려준다 |
| 같은 파일 새 하위 명령 **`cells`** | `cells --recipe <학습 파일 …> --dev <dev-cmp-g4.jsonl> [--thin 10] [--draft]` — 홀로 돌림 |
| 같은 파일 `cmd_check` 에 **`--recipe <학습 파일 …>`** 인자 | 주면 `cell_gaps` 를 돌려 결과 JSON 에 `"cells"` 를 붙이고, 빈칸이 있으면 `bad` 에 더한다(exit 1). 주지 않으면 옛 동작 그대로 |

- **`--recipe` 를 따로 두는 까닭** : 지금 `check --train` 기본값은 새 층(train-g4-c · -d · g3-ko)만 받는다 — 겹침을 잴 몫이다. 빈칸은 **학습 전체**(train-r2 · train-g1-arch · train-g3-ko · 새 층)로 세야 한다. 같은 인자에 섞으면 겹침 검사가 train-r2 까지 다시 보게 돼 옛 동작이 바뀐다.
- 원천 = `domain`, 없으면 `mem`(채움 조사 6절과 같은 규칙). 칸 = `want` — `support · contradict · unrelated · related` 와 `a · b · c · d` 를 같은 글자로 맞춘다. `cd` 와 그 밖은 세지 않는다.

### 4-2. 울리는 조건과 출력

| 이름 | 조건 | 결과 |
| --- | --- | --- |
| `zero` | 학습 0 · dev ≥ 1 | **exit 1** (얼리기 막음). `--draft` 면 적기만 |
| `thin` | 1 ≤ 학습 < `--thin`(기본 10) · dev ≥ 1 | 경고만 (exit 0) |
| `dev_missing` | 학습 ≥ 1 · dev 0 | 보고만 — dev 가 못 덮는 칸(R5) |

```json
{"cells": {"recipe": ["train-r2.jsonl", "…"], "dev": "dev-cmp-g4.jsonl", "thin": 10,
  "zero": [{"domain": "vitaminc", "cell": "c", "train": 0, "dev": 56}],
  "thin_cells": [{"domain": "kowiki", "cell": "c", "train": 1, "dev": 24}],
  "dev_missing": [{"domain": "mit-cs", "cell": "c", "train": 40}],
  "table": {"vitaminc": {"a": [200, 155], "…": "…"}}}}
```

- `table` 은 원천마다 칸별 [학습, dev] — 결과 문서에 그대로 옮길 표다. 쌍 본문은 안 찍는다.

| 시험 | 기대 |
| --- | --- |
