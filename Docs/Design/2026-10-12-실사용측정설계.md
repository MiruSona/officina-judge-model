## 결론 먼저

1. **자는 「짝 비교 숫자 보고」다.** 자리마다 라벨 붙은 쌍 50 안팎에서 v1.0.0 과 v1.1.0 의 손해를 같은 쌍으로 잰다. 숫자마다 95% 구간을 붙이고 짝 차이에는 McNemar 를 붙인다. 합격선은 없다. 8절 「읽는 법」(T7) 표로 길 B · C 를 고른다.
2. **50쌍이 가르는 크기는 약 ±9~10%p 다.** 한쪽이 0건이면 위 끝은 6%(셋의 규칙)다. 그보다 작은 차이는 「못 가림」으로 적는다.
3. **mem 이 보내는 글을 그대로 잡는다.** 도구가 띄운 기록 대리 서버를 `MEM_LLM_CONFIG`(임시 llm.toml)로 mem 에 물린다. 그러면 꼬리표 떼기 · 비밀 꼴 거절 · 정렬된 두 문장이 실사용과 같다. 대리 서버는 한 물음을 두 모델에 다 보내고 기록한다.
4. **문턱은 두 벌로 잰다.** (가) 그 저장소의 llm.toml 값 = 지금 실사용 그대로 (나) 모델마다 자기 calibration 값. 8092 는 지금 v1.1.0 인데 문턱은 v1.0.0 값이라, (가)가 「지금 mem 이 겪는 것」이다.
5. **merge 는 지금 NLI 를 안 부른다.** 그래서 ③ 은 둘로 나눠 잰다. ③-1 숨김 놓침은 C19 거짓 반대가 merge 줄을 지우는 것(실제)이다. ③-2 2차 거름 모의는 NLI 를 merge 에 쓴다면 어떨지(가정)다. ③-2 가 「d 를 모델 안에 둘 값이 있나」에 답한다.
6. **④ · ⑤ 는 새로 모아야 한다.** ④ 는 mod 가 서브에이전트 보고를 받아 로그에 쌓는다(5일 안팎). ⑤ 는 localharness 판 기록을 거둔다(지난 228줄 + 2주). 둘 다 **측정만 한다.** 메인 화면 · 하네스 판정은 바꾸지 않는다.
   - 덧붙임(코드 · 파일로 확인, 2026-10-12) : ④ 는 지난 서브에이전트 대화 기록에서 바로 거둘 수 있다(지난 7일 보고 769 · 「정한 것」이 든 보고 91). ⑤ 는 정답 칸이 이미 채워진 G5 얼린 셋 246쌍이 있다. 그래서 둘 다 **기다리지 않고 첫 판을 뽑을 수 있다**(4-1 · 4-2 덧붙임).
7. **이 셋은 「실사용 셋 use1」로 별명마다 한 번 얼리고 다시 안 얼린다**(지킬 규칙 ①). 학습 · 보정 · 문턱 고르기에 쓰지 않는다.

## 3. 표본 뽑기 (①~③ — 지금 저장소에서)

### 3-1. 기록 대리 서버 (`use_eval.py` 안 · 127.0.0.1 빈 포트)

- 모든 `/judge` 를 받는다 → 같은 몸통을 `--models` 서버마다 차례로 보낸다 → `proxy-log.jsonl` 에 {evidence, claim, 모델마다 probs · model id · ms} 를 쓴다 → `--reply` 모델의 답을 바이트 그대로 mem 에 돌려준다. `/health` 는 reply 모델로 넘긴다.
- `v110d` 가 있으면 4칸 서버에 `"label_set":"nli4"` 로 묻고 4칸 확률을 기록한다. mem 에 돌려줄 일은 없다.
- 임시 llm.toml : 그 저장소의 설정(`mem judge config --json` 값)을 베끼되 `nli_url` = 대리 서버, `nli_timeout_ms` = 5000(최대값 — 두 모델에 차례로 묻느라 느려진다)으로 하고, 문턱은 벌마다 바꾼다. `url`(SemIf)은 **비운다**. 키는 옮기지 않는다. 파일은 `~/.judgemodel/measure/use1/<별명>/llm-<벌>.toml`.

### 3-2. 자리마다 뽑는 법

| 자리 | 원천 (mem 명령) | 층 |
| --- | --- | --- |
| ② C19 | `MEM_LLM_CONFIG=<임시> mem review --kind contradict,merge --nli --nli-pairs 100000 --nli-per-scope 100000 --json --all --repo <뿌리>` 를 reply(v100 · v110) × 문턱(repo · model) **네 판** | flagged : 어느 판에서든 큐에 오른 쌍 전부(60 넘으면 무작위 60) · rest : 물었지만 안 오른 쌍 중 무작위 30 · plus-superseded : `mem review --kind retired --ids --all` 의 (옛 id, by 새 id) 짝을 `mem show --json` 의 summary 쌍으로 만든 b 후보 20 (재현 보탬, 따로 보고) |
| ③ merge | `mem review --kind merge --ids --all` (`--nli` 없음) = M0 · 위 네 판의 merge 줄 | m0 : M0 전부 · hidden : 판마다 M0 에서 사라진 짝 전부(그 짝의 C19 글은 ② 라벨을 함께 쓴다) · near : ② rest 에서 무작위 20 (③-2 의 「합칠 만하지 않은」 쪽) |

- 뽑기 씨앗은 `sample_seed`, 층 크기는 규약대로다. `cands.jsonl` 의 줄 = {id, place, stratum, evidence, claim, group, src}.
- 대조 : reply=v110 · repo 문턱 판에서 mem 이 낸 contradict 줄 수와, 대리 서버 로그로 다시 셈한 수가 다르면 멈춘다(exit 2).
- **본 쌍 대조** : `--seen ~/.judgemodel/sets,~/.judgemodel/build` 의 jsonl 과 (StripTags 뒤 evidence, claim) 해시를 견준다. 학습에서 본 쌍은 `seen` 표시를 달고 수치를 「전부 / 본 쌍 뺌」 두 줄로 낸다(R3 의 「52% 외운 쌍」 사고를 막으려고).
- 어느 저장소든 : 저장소 뿌리는 `--repo`(기본 지금 폴더)로만 받고 mem 에 `--repo` 로 넘긴다. 경로를 박지 않는다. 별명은 `--alias` 로 받고, 없으면 `repo-<뿌리 경로 sha256 앞 8자>` 로 정한다(이름이 새지 않게).

**4-1 덧붙임 — 보고 받는 길을 코드로 확인한 것 (2026-10-12)**

위 표의 「`tool.call` Agent 에서 `await next(e)`」 길은 이 프로젝트에서 거의 못 쓴다. 서브에이전트는 기본이 뒤로 돌기(background)라 Agent 도구 결과가 이름뿐이다. 그래서 받는 길을 아래 차례로 바꾼다.

| 차례 | 길 | 보고를 받나 | 판단 |
| --- | --- | --- | --- |
| 1 | **mod `on('turn.complete')` · `e.agentId` 가 있는 턴** | 엔진 형 선언에서 `e.answer` = 「서브에이전트가 돌려준 보고 전문」. 뒤로 돈 에이전트도 잡힌다. agent-board 가 같은 자리에서 끝난 에이전트를 잡는다 | **권고.** `report-check` 는 여기서 `$.process.run([python, <useEvalPath>, 'log-report', …], { stdin: e.answer })` 를 부르고 `next(e)` 를 기다림 없이 돌려준다 |
| 2 | 지난 대화 기록 거두기 (`use_eval.py harvest-reports`) | `~/.claude/projects/<저장소 경로를 접은 이름>/<세션>/subagents/agent-<id>.jsonl` 의 마지막 `SubagentHandback` 도구 호출 `message`(없으면 마지막 assistant 글). 2026-10-12 셈 : 지난 7일 기록 777 · 보고 769 · 「정한 것」 절이나 `정함 :` 줄이 든 보고 91 · 그 절의 표 줄 약 740(머리줄 포함) | **첫 판은 이것으로 뽑는다.** 5일을 기다릴 필요가 없다. mod 는 그 뒤 새 보고를 같은 로그에 이어 쓴다(`src:"live"` · 거둔 것은 `src:"transcript"`). 폴더를 못 찾으면 `--transcripts <폴더>` |
| 3 | Claude Code `SubagentStop` command 훅 | 입력 칸은 **이미 실측됐다**(AIMemoryTool `Docs/Design/2026-08-30-서브에이전트훅설계.md` 2-3) : `agent_id` · `last_assistant_message` · `agent_transcript_path` · `stop_hook_active` | 기록만 하고 **아무것도 출력하지 않을 때만** 쓴다. 같은 실측에서 `additionalContext` 는 서브에이전트를 9번 다시 돌려 답을 망가뜨렸고, `systemMessage` 는 헤드리스에서 안 보였고, exit 2 는 답 꼴을 흩뜨렸다 |
| — | 메인이 보고를 명령에 손으로 넘김 | — | 잊기 쉬워 쓰지 않는다 |

- 문장 뽑기 덧붙임 : 표 줄은 머리줄에서 「결정」·「정한」 이 든 칸을 쓰고, 없으면 위 규칙대로 첫 칸 + 둘째 칸이다. 「까닭」 칸은 claim 에 안 넣는다. 보고에 적힌 mem id 자신과 **보고 시각보다 뒤에 생긴 기억은 짝에서 뺀다**(그 보고가 남긴 기억이 자기 짝으로 잡히는 것을 막는다).
- 묻는 명령 덧붙임 : 쌍 꼴 `{"id","evidence","claim"}` 은 `mem judge support --file` 의 줄 꼴(`cmd_judge.go` 의 `judgePair`) 그대로다. `--stage rules,nli --json` 으로 돌리면 줄마다 letter · probs · unsure · stage 가 나온다. `mem judge` 는 규칙 B · C 를 최종으로 쳐 C19 와 같은 사다리다. **지금 명령으로 된다**(새 mem 명령 없이).
- 로그에는 결정 문장 · 옛 summary · 짧은 해시만 둔다. 대화 기록 경로 · 세션 id · 보고 전문은 옮기지 않는다.
- 제품 꼴(측정 뒤) 덧붙임 : 뒤로 돈 에이전트는 「Agent 결과 끝」 이 없다. 알림은 mod 가 `$.session.append({ message: { type: 'user', … } })` 로 메인 대화에 **서술형 한 줄**(「보고의 결정 한 줄이 mem 결정 `<id>` 와 반대로 읽힌다 (b .91)」)을 붙이는 꼴이 맞다. 「~하라」 꼴은 08-30 실측에서 메인이 프롬프트 인젝션으로 의심했다. 이 길이 메인 모델에게 실제로 읽히는지는 **확인 못 했다** — 제품 설계 첫 소단계에서 잰다.

| `report` | 수치 · 구간 · McNemar · md | `--protocol measure/protocol-use1.json --alias A[,B]` | `result.json` `result.md` |

다른 저장소에서 한 줄씩:

```
python -I <JudgeModel>/measure/use_eval.py doctor --repo .
python -I <JudgeModel>/measure/use_eval.py serve --model ~/.judgemodel/models/nli-studio-v2 --port 8093
python -I <JudgeModel>/measure/use_eval.py sample --repo . --alias <별명> --models v100=http://127.0.0.1:8093,v110=http://127.0.0.1:8092
python -I <JudgeModel>/measure/use_eval.py labels make --alias <별명>      # → Opus 둘 → labels merge/decide
python -I <JudgeModel>/measure/use_eval.py freeze --alias <별명>
python -I <JudgeModel>/measure/use_eval.py report --protocol <JudgeModel>/measure/protocol-use1.json --alias <별명>
python -I <JudgeModel>/measure/use_eval.py stop --port 8093
```

- `<JudgeModel>` 은 그 저장소의 `Tools/JudgeModel` 이다. 도구는 AIMemoryTool 을 경로로 가리키지 않고 `mem` 명령만 부른다. 서버 주소는 `--models` 인자로 받는다(기본 v110=127.0.0.1:8092).
- 코드 재사용 : `compare.py`(mcnemar_exact · percentile) · `train/data_prep.py`(strip_tags) · `build/label_batches.py` · `build/bm25.py`. 쓰기 경로는 모두 git 밖인지 확인한다(`label_batches.inside_git` 와 같은 검사).
- 보안(security-invariants) : 임시 llm.toml 에 키를 옮기지 않는다 · 쓰는 경로는 `use1/<별명>` 감옥 안 · mem 출력 글은 믿지 않는 글로 다룬다(md 에 넣을 때 자름 · 백틱 이스케이프).
