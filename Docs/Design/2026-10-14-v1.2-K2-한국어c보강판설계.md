## 0. 전제

### 0-1. 왜 이 판인가

- **K 판은 한국어 b 를 올렸지만 한국어 c 를 깎아 출시 관문에서 떨어졌다.** blind-g3 에서 ko b .780 → .908 인데 ko c .902 → .770 이다. ref(v1.1.0) 대비 아래끝 셋(c −.090 · a −.035 · en b −.032)이 −.03 에 못 미쳤다(K 결과 0절).
- **c 가 밀린 까닭은 「글 갈래 지름길」이다**(c 진단 0 · 2절). K 의 학습 층 2,644쌍은 전부 「같은 대상 · 고친 주장」 꼴이라, BoolQ · 위키 · KLUE 문단이 근거로 오면 답이 늘 a · b · d 였다. 놓친 c 는 낱말 하나 안 겹치는 쉬운 near-x c 다.
- **짝 비교가 이것을 못 봤다.** dev-cmp-g3 의 한국어 c 347쌍에 BoolQ · 위키 c 가 0 이고, 지킴 자가 c 전체 하나라 klue-mrc 의 내림(−.15)을 archive 의 오름이 덮었다(c 진단 2-4).
- **en b · a 는 「셋이 작아서」 떨어졌다.** en b 는 묶음 79개 · 쪽당 4쌍이라 구간이 넓었다. 평균은 올랐다(blind 조사 0절).

## 1. 결론 — 한 줄과 흐름

**한 줄** : 같은 원천의 학습 쪽 문단으로 한국어 c 약 1,300쌍(near-x 900 + c 짝 400)을 만들어 K 처방에 더한 K2 를 K 와 짝 비교하고, 묶음 수를 미리 박은 새 blind-g4(약 1,800쌍)로 한 번 잰다.

## 2. 목표와 합격선

### 2-1. 짝 비교 관문 (K2 vs K · dev-cmp-g4 · `protocol-g4.json` `pair_gate`)

| 자 | 기준 | 까닭 |
| --- | --- | --- |
| **목표 `c_recall@ko`** | 평균 차 ≥ **+3%p** · 묶음 붓스트랩 아래끝 > 0 | dev-cmp-g4 ko c 약 470쌍 중 새 공개 원천 c 약 130 · klue-mrc 72 에서 K 가 .15~.20 밀렸다(c 진단 1-1). 다 되찾으면 +.05~.07(어림). 기대의 절반쯤에 둔다 |
| 지킴 **`b_recall@ko`** | 아래끝 ≥ −3%p | K 가 얻은 몫이다. **이 자가 깨지면 K2-h**(6-3) |
| 지킴 `b_recall@en` | 아래끝 ≥ −3%p | g3 와 같다 |
| 지킴 `b_recall` | 아래끝 ≥ −2%p | 같다 |
| 지킴 `acc3` | 아래끝 ≥ −2%p | 같다 |
| 지킴 `a_recall` · `c_recall` · `d_recall` | 아래끝 ≥ −3%p | 같다. c 전체도 지킨다(영어 c 를 잃지 않게) |
| 지킴 거짓 지지 | K 의 1.2배 이하 | 같다 |
| 지킴 곁 자 MNLI · KLUE | 평균 차 ≥ −1.0%p | 같다 |
| 경보 | K48 맞힘 40 이상 · `a_recall@ko` 평균 차 ≥ −3%p · `b_recall@mem·ko` ≥ −3%p · **`d_recall@ko` 평균 차 ≥ −5%p** | c 를 되찾으면 K 가 얻은 ko d(.200 → .533) 몫이 일부 c 로 돌아갈 수 있다(c 진단 2-3). 막지는 않고 본다 |

- **보고만** : 원천(domain) × 언어별 a · b · c · d 재현 — 특히 c 는 kobest-boolq · kowiki · klue-answered · klue-mrc · archive · mem 을 따로 적는다. c→d · c→b · b→c 수. 잣대 3쌍 · use1 ② 놓친 b 7쌍.
- **판별 불가** : 기준선 K 의 `c_recall@ko` 씨앗 평균 짝 반폭 > .04 면 compare 를 판정에 쓰지 않는다(8단계).
- 기준 판이 B2 가 아니라 **K** 다. K 처방이 채택돼 있고(0-2), 「ko b 를 지키며 c 를 되찾았나」를 바로 재려면 K 와 견줘야 한다.

### 2-2. 릴리스 관문 (blind-g4 · `release_gate`) — g3 와 같은 자

| 자 | 기준 |
| --- | --- |
| b 재현 (쌍 전체) | ≥ .80 |
| ko b 재현 | ≥ .70 |
| ref 대비 ko b | 같은 쌍 차 아래끝 > 0 |
| ref 대비 b · en b | 아래끝 ≥ −2%p · ≥ −3%p |
| ref 대비 acc3 | 아래끝 ≥ −2%p |
| ref 대비 a · c · d | 아래끝 ≥ −3%p |
| 확신 거짓 지지 | ≤ 지지 아닌 쌍 × 1.5% |
| 보류 | ≤ ref 보류 + 3%p |
| p95 | ≤ 1.0초 |

- ref = **v1.1.0** (`runs/g1-B2-s3/ckpt-best`, 가중치 sha256 14d0d520…). K 는 내지 않았으니 그대로다.
- 자는 하나도 안 바꾼다(사용자 「잰 뒤 기준 재검토 안 함」). 바뀌는 것은 셋 크기(묶음 수)뿐이다.
- **K 와 같은 엇갈림이면 넘는 선**(blind 조사 3-2) : en b 관측 차 ≥ +.010 · a ≥ +.012 · c ≥ .000. K 의 실제 차(en b +.035 · a +.017)면 둘 다 넘는다. c 는 K2 가 c 를 v1.1.0 수준까지 되찾아야 넘는다 — 이 판의 성패가 여기 걸려 있다.

### 3-3. 금지 목록 짜는 법

`G4Forbid` = `G3Forbid` 전부 + 아래.

| 더할 것 | 파일 |
| --- | --- |
| g3 세 셋 글 · 묶음 · 출처 id · 쌍 열쇠 | `~/.judgemodel/sets/g3/{dev-cmp,dev-cal,blind}-g3.jsonl` |
| **blind-g3 금지 목록** (묶음 458 · 출처 id 1,055 · 쌍 1,079) | `~/.judgemodel/sets/g3/blind-g3.forbid.json` |
| train-g3-ko 2,644쌍 (평가 쪽에만 금지) | `~/.judgemodel/sets/g3/train-g3-ko.jsonl` |
| reserve-g3 예약 묶음 · 학습 층 후보 1,409 | `~/.judgemodel/build/g3/reserve/reserve-g3.json` · `train-layer-cands.jsonl` |
| g3 셋 문장 색인 (`ParaIndex`, 글자 3묶음 닮음 ≥ .8) | 위 셋에서 만든다 |

- **두 방향으로 쓴다.** 평가 쪽(blind-g4 · dev-cmp-g4 새 줄)은 위를 다 피한다. 학습 쪽(train-g4-c)은 위 + **`blind-g4.forbid.json` + dev-cmp-g4 새 줄 묶음**을 피한다.
- **평가 쪽은 평가 몫 묶음에서만, 학습 쪽은 학습 몫 묶음에서만 뽑는다.** BoolQ 는 dev · test → 평가, train → 학습. KLUE 는 heldout → 평가, train split → 학습. 위키는 `wiki-all-eval` → 평가, `wiki-all-train` → 학습. split 으로 먼저 가르고 금지 목록은 겹침을 한 번 더 막는 그물이다.
- `blind-g4.forbid.json` 꼴은 `blind-g3.forbid.json` 과 같다(`make_sets.forbid_doc`). 만든 뒤 앞으로 모든 학습 · 합성 · 덧학습 금지 목록에 더한다.

| 옛 줄 | — | dev-cmp-g3 줄을 그대로 잇는다(칸 · 라벨 그대로, `g3_set` 에 옛 이름) |

- 새 c 는 **평가 몫 묶음 중 blind-g4 가 안 쓴 묶음**끼리 near-x 로 만든다(`reserve-g4` 가 blind-g4 를 먼저 채우고 남은 묶음으로). blind-g4 와 묶음 · 글 · 출처 id 가 안 겹친다.
- **dev-cal 은 바꾸지 않는다.** `calibrate_on` 은 dev-cal-g3 그대로다. 문턱 · 온도를 고르는 셋이라 c 를 더해도 관문 판정이 크게 안 바뀐다(어림). 셋을 하나 덜 얼린다.
- 옛 쌍 라벨은 v6 그대로라, K 다섯 판을 dev-cmp-g4 로 다시 재는 데는 평가만 든다(8단계).

### 3-5. 얼림 절차

g3 14절 꼴 그대로다. 차례만 적는다.

1. `assemble_g4.py assemble --set dev-cmp-g4` · `--set blind-g4` → `check` (겹침 · scrub · `min_groups`) — exit 0.
2. **정답 확인 gold-g4** : blind-g4 에서 무작위 ko b 30 + ko c 30 (씨앗 고정, why=random) → 신중 판(careful) · 판정자 둘 → `gold-score --dev-from`. 관문 .85. 이번 판은 c 라벨이 성패를 가르니 c 를 반 넣는다.
3. `assemble_g4.py freeze` 둘 · `train/freeze.py write` 둘(train-g4-c · train-g4-c-h). 해시 넷.
4. `blind-g4.forbid.json` 을 `sets/g4/` 로 복사.
5. `assemble_g4.py protocol --draft measure/protocol-g4.draft.json --out measure/protocol-g4.json` → 첫 짝 비교 전에 커밋(사용자 승인).

## 4. c 층 — train-g4-c

### 4-1. 뽑기 규칙

| 꼴 | 근거 | 주장 | 원천 × 수 (판정 뒤) | 후보 |
| --- | --- | --- | --- | --- |
| **near-x c** | 학습 쪽 묶음 A 의 문단 | 같은 원천 다른 묶음 B 의 주장 · BM25 **10~60위** (`make_sets.near_c` 그대로) | BoolQ 350 · 위키 350 · KLUE 200 = **900** | 약 1,000 |
| **c 짝 (같은 주장 · 다른 근거)** | 같은 원천 다른 묶음의 문단 · BM25 10~60위 | **train-g3-ko 의 b 주장** 그대로 | BoolQ 200 · KLUE 100 · 위키 100 = **400** | 약 440 |

- **near-x 의 근거는 train-g3-ko 에 이미 든 문단을 먼저 쓴다**(c 진단 4절 ③). 같은 BoolQ · 위키 문단이 a · b 쌍과 c 쌍에 같이 나오게 해 「이 문단이면 a · b」 지름길을 끊는다. 모자라면 안 쓴 학습 쪽 묶음(BoolQ 2,923 · 위키 3,808 · KLUE 1,850)으로 채운다.
- **c 짝의 주장은 train-g3-ko b 줄에서 고른다**(c 진단 4절 ②). 같은 주장이 제 문단에선 b, 남의 문단에선 c 로 나와, 모델이 주장 문체가 아니라 근거와의 관계를 보게 한다. b 주장 하나에 c 짝 하나까지.
- 근거 하나는 c 쌍 2개까지(묶음당 2) · 주장 하나는 한 번(`near_c` 의 `used`).
- 같은 묶음끼리 · 같은 원천 안에서만 짓는다(BoolQ 문단 × 위키 주장은 안 만든다). 원천을 섞으면 「원천이 다르면 c」라는 새 지름길이 생길 수 있다.
- 위키 근거는 「제목 : 문장」 꼴을 지킨다(학습 층 위키 942쌍이 이 꼴 · c 진단 1-4).
- **뺀다** : KLUE 「답 없는 질문」(c/d 경계 꼴 · c 진단 1-2) · KLUE other-doc c 250(teacher 점수만, 3안 몫) · MIT · 씨앗(우리 글 c 는 안 밀렸다).
- 줄 칸은 train-g3-ko 와 같다(5-2 의 `near_c` 손질로 `split: train` · `origin: g4-train` · `set: train-g4-c` · `pick` 에 원천 · `form` 에 `near-x` 또는 `c-pair` · c 짝은 `pair` 에 b 줄 id).

### 4-2. 판정 묶음

- `label_batches.py make --mode train --guide ../Docs/Guide/라벨기준support-v6.md --traps <g1>/traps.jsonl` · 100쌍 묶음 · 함정 10% · 판정자 둘(j1 · j2) · 갈림은 셋째(`third`). g3 학습 몫과 같은 꼴이다.
- 후보 약 1,440쌍 → 묶음 약 15개 × 판정자 2. 쌍 1개 ≈ Opus 2.3건이면 약 3,300건(어림).
- **정함 규칙** : 두 판이 다 c 일 때만 넣는다(셋째가 갈림을 c 로 정한 것 포함). c 아닌 줄은 버린다. c 짝이 버려져도 짝이 된 b 줄(train-g3-ko)은 그대로다 — 그 층은 얼려 있다.
- 판정자는 근거 · 주장만 본다. 뽑은 꼴(near-x · c-pair) · BM25 순위는 `map/` 에만 둔다.

### 4-3. 라벨 기준

`../Guide/라벨기준support-v6.md` 그대로. c 판정에서 볼 자리는 둘이다.

- 근거와 주장이 **다른 대상**이면 c. 같은 주제 갈래(둘 다 새 · 둘 다 축구 규정)여도 대상이 다르면 c.
- **같은 대상인데 다른 때 · 다른 조건**이면 d. BM25 10위 근처는 같은 대상이 섞일 수 있다 — 판정이 걸러 낸다(c 진단 3-2).

### 4-5. 진단 확인 (학습 전 · 10분 안팎)

- c 판정이 끝난 near-x c 에서 원천별 무작위 50(합 150, 고정 씨앗)을 떼어 **K-s1~5 로 평가만** 한다(c 진단 5절의 제안). 이 150쌍도 층에 그대로 넣는다 — 학습 전에 K 만 재는 것이라 새는 것이 없다.

### 6-5. 릴리스

- 릴리스 판 = K2(또는 K2-h) 다섯 중 dev-cmp-g4 `c_recall@ko` 가 평균에 가장 가까운 판 · 동률이면 acc3 · 그다음 씨앗 작은 판.
- `prereg.py --protocol measure/protocol-g4.json` 로 박제 → **`prereg.json` 의 `next` 칸이 K2 문구인지 눈으로 본다**(9번 손질 확인) → blind-g4 에 **한 번**. 같은 쌍에 ref v1.1.0 도 잰다.
- `gates.py release` 는 저장소 판(동기화된 미니PC 판과 같은 sha)으로 돈다.
- ONNX 내보내기 · p95 는 K 판과 같은 길. 메인 PC 에는 새 모델 폴더(약 2.2GB) 하나만 둔다.
- 통과해도 8092 교체는 사용자가 정한다. 미달이면 내지 않고 결과만 적는다.

## 7. 소단계와 공수

`effort estimate` 는 이 판 묶음에 1시간 14분을 낸다. 실측 표본이 작은 일 위주라 L 급 새 코드와 긴 학습을 2.5배 넘게 작게 잡는다(mem 10-01 · AssetTool 기록). 그래서 **K 판 실측을 눈금으로** 다시 잡았다 — 학습 · 짝 비교 1시간 46분 · 사전 등록 · blind 12분 · g3 판정 661쌍 벽시계 약 8분(Opus 8개 동시) · 위키 · BoolQ · KLUE 평가 몫 뽑기 + 판정 13 · 16 · 9분.
