쌍 본문은 git 밖(`~/.judgemodel/build/g1/`)에만 쓴다. 원자료 폴더 안에서 인터프리터를 띄우지 않고, 경로는 인자로 넘긴다.

1. 원천마다 후보 뽑기 : `python -I mine_public.py <proposals|vitaminc|klue-mrc|minicheck|ood|jira> --raw <원천 폴더> --out ~/.judgemodel/build/g1` (ood 의 `--raw` 는 raw 뿌리) → `<원천>/candidates.jsonl` · `groups.json`
   - Jira 는 원자료가 mongodump 아카이브(zip 5.8GB · 풀면 약 60GB)라 먼저 줄인다 : `python -I jira_dump.py slim --src <jira.zip> --out <빈 폴더>/issues.jsonl` (풀지 않고 zip → gzip → BSON 을 흘려 읽음, 링크 · won't fix 이슈만, 2.7M 중 1.09M · 미니PC 2분 36초) → 그 폴더를 `jira --raw` 로 준다. 링크 이름은 원자료 `jira_issue_linktype_mapping.json` 의 Relate 꼴(Reference · Related · Relates · 「1 - Relate」 …) → d link, Duplicate → a, 같은 프로젝트 다른 컴포넌트 → c. 설명 80~1,200자 · `{code}` 류 표기 없는 이슈만, 한 이슈 쌍에 하나. 익명판 덤프에는 댓글이 없어 b(wontfix)는 0 이다.

KLUE 는 `klue-mrc/rewrite-reserved.jsonl` 의 claim 을 붙이고 skip 은 뺀다. 근거가 목록 · 제목 · 메뉴뿐(`list_like`)이면 버린다. ood-g1 은 세 원천 고르게 320, 자 ④ 쌍을 빼고 원래 라벨(hint · source_label)은 지운다. 앞 셋이 쓴 (근거, 주장)은 뒤 셋이 못 쓴다.
   - 평가 겹침 검사 : 위 `check` 에 `--eval-dir ~/.judgemodel/build/g1/eval-public` 을 더하면 셋 사이 · 평가 × 학습 후보 · 평가 × 옛 셋 겹침도 0 인지 본다.
   - 평가 묶음 : 셋마다 `label_batches.py make --cands eval-public/<셋>-cands.jsonl --out eval-public/<셋> --mode eval --traps g1/traps.jsonl --seed <셋마다 다르게>`. 판정자에게는 `eval-public/JUDGE-README.txt` 와 묶음 하나(`<셋>/batches/bNN-jK.*`)만 준다. 답은 `<셋>/answers/bNN-jK.out.jsonl`.

7. `bm25.py` 는 묶음 안 근접 순위(토큰 = 낱말 + 글자 2묶음), `parquet_lite.py` 는 패키지 없이 parquet 를 읽는 작은 읽개다.

   - `traps --dev-r2 … --ruler4 ~/.judgemodel/sets/g1/ruler4 --pool <trap-pool.jsonl>` : 함정 풀 — a = dev-r2 same·long 지지 · b = flip 아닌 반대 · c = xscope 무관 · d = 자 ④ 사람 감사 d (flip 반대는 함정 못 씀, mem 20261010-425aa4ed). 풀이 없으면 make 는 함정 없이 돈다.
   - `make --cands … --out … --mode train|eval [--style careful]` : 100쌍 묶음(신중 판정자는 20쌍) · 함정 10% 를 칸 넷에 고르게 · 불투명 `q` 다섯 자리 · 판정자 j1 · j2 마다 쌍 차례와 기준 3절 예시 차례가 다르다 → `batches/bNN-jK.jsonl`(`q`·글만) + `bNN-jK.txt`(안내).
   - 빈 쌍 막기 : `make` 는 근거나 주장이 빈 후보가 한 줄이라도 있으면 exit 2 로 멈춘다(넘기는 옵션 없음). `assemble` 은 빈 줄을 빼고 `dropped_empty` 로 summary(전체 · 폴더별)에 센다 — train-II 의 KLUE 빈 주장 1,000쌍(46 결함)을 조립 때 거르려고.
   - 판정자 답은 `<out>/answers/bNN-jK.jsonl` (다시 돌린 판은 `bNN-jK.r2.jsonl`). `merge` → `votes.jsonl` · `merge-report.json` : 함정 정답률 80% 아래 · 「답 없음」(앞뒤 안 맞는 줄 · 빠진 줄) 5% 넘는 판은 통째로 버린다. 함정 답은 셈에서 뺀다. 함정 자체가 의심스러우면 `merge --exempt-trap <함정 id> …`(map.jsonl 의 id) 로 관문에서만 뺀다 — 정답률 분모·분자에서 빠지고(남은 함정 0 이면 관문 「없음」 통과), `merge-report.json` 의 판에 `trap_exempt` · `trap_n` 이 남는다. 라벨에는 여전히 안 들어간다. 신중 판정 20쌍 묶음은 함정이 1~2개라 하나가 애매하면 판이 통째로 버려져서 둔다(g1 gold b06 의 t0046).
   - `decide --mode train|eval` → `decided.jsonl` · `third` → 갈린 쌍만 셋째(j3) 묶음 `tNN-j3` (실제 쌍 q 는 그대로, 함정은 새 q). 셋째 답을 넣고 `merge` → `decide` 를 다시 돈다.
